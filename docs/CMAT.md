# `-fopt-cmat`：清理重复的常量材料化

[English](CMAT.en.md) | 中文

> 一句话：值栈后端会把同一个常量材料化两次——先搬进暂存寄存器，再由使用者折回寻址方式；
> 暂存寄存器也常常连写两次；常量还会去穿一条移位/扩展指令；`do {} while (0U)` 那种
> 条件恒假的比较也照样发成 `CMP` + 条件跳转；值栈还会把基址压栈、中间只留下死写、
> 再原样弹回。`-fopt-cmat` 在一个函数的已发射文本上清掉这七类形态，HAL 全语料上少
> **993 条指令（−6.23%）**，`LSL` 509→163、`UXTB` 218→61、条件跳转 116 条消失、
> 值栈推拉对少 67 对。

---

## 1. 为什么做这个

0.9.1 的文本层 pass 已经吃掉了很多「搬来搬去」，但值栈机的产物里还有一族没人管：

```asm
    MOV   r7, #0
    MOV   r1, r7          ; 把已知常量搬进索引寄存器
    LDR   r7, [r5, r1, LSL #2]   ; 硬件本来就能直接编码 [r5, #0]
```

```asm
    MOV   r7, #0          ; 写了一次
    MOV   r1, r7          ; 又一次覆写 r7 之前没有任何读
    ...
```

这类形态不需要活跃性分析就能证明安全——它们要么「地址一样、结果一样」，
要么「在块内可证明被后写覆盖」。这就是本 pass 的全部定义域。

## 2. 九条规则

### 2.1 M1：把已知常量搬成立即数

> `MOV rD, rS`，且本块内已知 `rS` 的值是 0..255 的常量 `k` ⇒ `MOV rD, #k`。

单独看它**不减少任何指令**（仍是一条），它是给 M2/M3 创造条件：折成立即数之后，
被搬的那个寄存器才算「不再被读」，M3 才能把它删掉。

上限 255 是因为发射器本身就用这个形态表达小常量，超过 255 要走 `MOVW`，反而更长。

### 2.2 M2：把已知索引折进寻址方式

> `LDR/STR/LDRB/LDRH/STRB/STRH rT, [rB, rI(, LSL #s)]`，本块内已知 `rI` 是常量 `k`、
> 位移 `k << s` 落在 0..4095、且 `rI != rB` ⇒ `[rB, #k << s]`。

地址完全一样，标志完全一样，只是少了一个操作数（也少读一个寄存器）。

4095 是 Thumb-2 立即数偏移的上限；`rI == rB` 排除掉（那是「把寄存器当索引」的另一种
语义边界）。写回与后索引（`[rB, rI]!`）不在接受形态内。

### 2.3 M3：删掉被后写覆盖的标志中性写

> 标志中性的写（`MOV` / 同一寄存器的 `MOVW`+`MOVT` 对 / 三操作数 `LSL LSR ASR ROR` /
> `MVN` / `UXT*` / `SXT*` / `CLZ` / `REV*`），若在**同一块内**、在任何读它之前被
> **再次写**，则删除。

「必须是块内后写」这条要求，就是 M3 不需要活跃性的原因：块只有一个入口，
后写就发生在每一条路径上，删除不可能让任何读到旧值。

**`MOVW`+`MOVT` 必须当成一个单元**：单独删掉一半，寄存器里留下的是另一个值。
实现里二者融成一个 `nlines == 2` 的单元，重建时整对复制或整对丢弃，绝不半删。

### 2.4 M4：常量穿三操作数移位

> `LSL/LSR/ASR rD, rS, #n`，本块内已知 `rS` 是常量 ⇒ 结果算出来，若落在 0..255
> 就改写成 `MOV rD, #k`（否则**只记下常量状态、不改写**）。

安全性来自编码形式：**三操作数的移位不置标志**（置标志的是两操作数
`LSL rD, rS` 那种老形式），所以改写成 `MOV rD, #k` 之后值与标志都没变。

只改写 0..255 是因为发射器用这个形态表达小常量，超了要走 `MOVW`、反而更长；
但**不改写也要记状态**——`LSL` 之后 `rD` 的值是算得出来的，后面的 M2/M3/M6
照样能用它。`rS == rD`（`LSL r0, r0, #3`）同样接受，先取值再算，没有先后问题。

### 2.5 M5：常量穿扩展

> `UXTB/UXTH/SXTB/SXTH rD, rS`，本块内已知 `rS` 是常量 ⇒ 同上。

`UXTB` 的截断与 `SXTB` 的符号扩展在常量上都是纯算术，标志不动。
结果落在 0..255 才改写；`SXTB`/`SXTH` 的负结果不改写（也不留负常量状态，
因为下游的 M2/M6 只认非负小常量）。

### 2.6 M6：已知的 `CMP` 之后条件分支当场判定

> `CMP rX, #k` 之后紧邻一条条件跳转（中间不得插入其它会写标志的单元），
> 且本块内已知 `rX` 是常量 ⇒ 分支的去向当场算出来：
> 恒跳就把该行改成 `B` 目标，恒不跳就整行删除，**`CMP` 自身保留**。

保留 `CMP` 是关键：任何后续指令读到的 N/Z/C/V 与不优化时逐位相同，
所以 M6 不需要任何活跃性论证，也不会改变任何后续条件码求值。
条件求值是教科书的 64 位减法（N/Z/C 由 32 位无符号差给，V 由 64 位减给），
覆盖 `BEQ/BNE/BCS/BCC/BMI/BPL/BVS/BVC/BHI/BLS/BGE/BLT/BGT/BLE`。

恒跳分支改成 `B` 在指令数上**不赚**，赚的是 Thumb-2 里 `B` 的编码比条件跳转小；
恒不跳分支是纯赚（整行删掉）。语料里后者远多于前者（70 : 46），因为
`do { ... } while (0U)` 这类 HAL 宏展开成 `MOV r0, #0 / CMP r0, #0 / BNE`。

### 2.7 M7：删掉值栈的 `PUSH {rX}` / `POP {rX}` 对

> `PUSH {rX}` 之后，若直到某条 `POP {rX}` 之间**只剩已经被删掉的单元**，
> 这两行一起删。

值栈把一个值存进栈、紧接着又原样取回同一个寄存器，中间没有留下任何生效代码时，
这一存一取就是纯开销：`sp` 去了又回，净变化为 0，中间没有任何观察者。

安全论证三条：

- **中间没有活代码**。两条之间的单元必须全部是 M3 已经判定为死的写入，
  而 M3 的判据本身要求「本块内稍后被写且期间无人读」，所以删掉它们不改变任何值；
- **不跨标签与调用**。标签、`BL`/`BLX`、任何分支都结束搜索——分支可能带着不同的值栈
  到达那条 `POP`，而调用必须看见它自己那一层栈；
- **不碰多寄存器列表**。只认 `PUSH {rN}` / `POP {rN}` 恰一个 `r0`–`r12` 的形式；
  `PUSH {r5,r6,r7,lr}`（序言）与 `POP {..., pc}`（收尾）一律不动。

配套的两处判据扩展（它们和 M7 是一对，缺一条就删不掉中间的写）：

- **`POP`/`LDM` 是写**：M3 的 `cm_dies_later` 原先一见 `POP` 就当块尾，
  于是「被 `POP {rX}` 覆盖的写」看不见；现在 `POP`/`LDM` 在其列表里写了该寄存器
  就算覆盖，列表里没写它则**继续往后扫**（`LDM rB!, {...}` 这类带基址回写或认不出的
  形式仍当块尾）；
- **`POP`/`LDM` 只清它自己列表里的常量状态**：原先任何 `POP` 都把 13 个
  「已知常量」全部清掉，导致 `POP {r0}` 之后连 `r1` 的已知值也没了，
  `LDR r0, [r0, r1, LSL #2]` 折不成 `[r0, #0]`。现在只清列表里那几位。

这解释了为什么 M7 的收益要分两段看：先删掉中间的 `MOV`（−93），
再删掉 `PUSH`/`POP` 对本身（−203）。

### 2.8 M8：删掉全函数范围内死掉的常量与拷贝

> `MOV rD, #imm` 或拷贝 `MOV rD, rS`，若 `rD` 在本函数里**任何地方**都不再被读，
> 这条写就是死的。

M1–M7 全都只看一个块，因为一个块只有一个入口，块内稍后被覆盖的写在所有路径上都死。
M8 是第一条必须知道「这个寄存器在别处还活着吗」的规则，所以它把单元表按控制流切成块、
用不动点算 live-in / live-out，再把目标不活的 `MOV` 删掉。两种形态都是标志中性的
（发射器要改标志时会打印 `MOVS`），删掉它们既不改值也不改标志。

它补的是前面几条规则自己留下的尾巴：被消费者折掉的常量（`CMP rX, #0` 折出来之后，
原来那条 `MOV rX, #0` 就没人读了）和后继规则搬运之后多余下来的拷贝。

这个图**只往保守方向近似**，一个方向都不许反过来：

- 条件分支与 `CBZ`/`CBNZ` 同时到达「目标」和「下一块」；`B`/`BAL` 只到达目标
  （标签不在本函数里时退化为下一块，即尾调用）；
- 调用读 `r0`–`r3` 与 `r12`；
- 返回点（`POP {..., pc}`、`BX lr`）读 `r0` 与 `r1`（64 位返回值的低位可能在 `r1`）；
- 任何本 pass 不认识的指令一律**当它读全部寄存器、写零个**，于是它前面的一切都活着。

漏一条后继是不健全，多一条后继只是少赚一次，所以每个未知都收敛到更宽的那一侧。

安全性另有两条：

- **IT 覆盖内一律不删**。`IT` 块覆盖几条指令是它契约的一部分，删掉一条会静默改变
  条件执行的范围；
- **已经被前序规则删掉的单元不参与这张图**。它们不在输出里，既不算读也不算写。

`MOVW`/`MOVT` 不在本规则范围内：它们不是标志中性的单行，且语料上的死对实测为 0。

块边界沿用 §3 的那张表：`PUSH` 在白名单里，所以它不是边界（一整段「常量上栈、
取回」的代码可以落在同一个块里）；`POP`/`LDM`/`STM`/`IT` 与分支才是。

### 2.9 M9：join 处的 `PUSH {rX}` / `POP {rX}` 回环对消

> 一条路径上 `PUSH {rX}` 之后**只经过标签**就到达某个 `POP {rX}`，且这个 `POP` 的
> **每一个**前驱都满足同样条件（`PUSH {rX}` 是那条路径的最后一条动作），
> 那么这些 push 与这一个 pop 可以同时删掉。

值栈机在合流点（`if`/`&&`/`?:` 合流、`switch` 出口）会把算好的值先推上栈、
到合流处再取回同一寄存器。M7 只能处理「同一个块里、中间没有分支」的那一类，
因为它在块内线性扫描；跨分支的这一类必须知道控制流图，所以 M9 和 M8 一样是图上的规则。

安全性三条：

- **push 是它所在块的最后一条动作**，到 `POP` 之间只有标签，中间不可能有人读栈；
- **`PUSH {rX}` 不改寄存器**，`POP {rX}` 装回的也是同一个寄存器，所以在合流点
  `rX` 的值就是 push 时那个值——两半一起删，值不变；
- **`POP` 的所有前驱都必须删掉各自的 push**（`npred > 0` 且逐个通过），于是每条路径上
  `sp` 的加减同时消失，栈平衡不变。任何一个前驱不满足就整块放弃。

实现上有两个必要细节：

- **标签链折叠**。连续标签会切出「只含标签的空块」（`cm_be < cm_bs`），于是
  `B .L1` 的目标块并不是 `POP` 所在的那个块。所以先做一次 canon 折叠：从每个块出发，
  只要「块内全是标签且只有一个前驱」就继续跟随后继，记下最终块号；分支目标的判定
  走 canon（`cm_canon[succ] == j2`），不再比较标签文本。没有这一步时首版几乎全不命中，
  调试输出是 `npred=1` 但前驱终结符不是 `PUSH`——全是被标签空块挡住的假失败。
- **放行顺序**。M9 插在 M8 的活跃性建图**之前**，于是 M9 把回环拿掉之后，M8 还能顺势
  吃掉因此变死的常量写（语料上额外 16 条，见 §6）。

整函数弃权条件：出现 `TBB`/`TBH`，或 `BX` 的目标不是 `lr`——这两类跳转的目标
在文本上无从得知，后继表不可信，M9 在该函数内全部放弃。`r13`/`r14`/`r15` 不作候选，
`LDM`（多寄存器或带基址回写）不算 `POP`，IT 覆盖内的两条都不删。

## 3. 块边界与读集模型

块在这些位置结束（状态清零）：

- 标签（`.L...:` / 函数名）；
- 任何分支：`B` 族、`BL`、`BX`、`BLX`、`CBZ`/`CBNZ`、十种条件跳转；
- `IT` 系列——其中的指令是条件执行的；
- `POP` / `LDM*` / `STM*`——**例外**：`POP`/`LDM` 只写它列表里点名的寄存器，
  所以它只清那几位的常量状态，其余寄存器保持已知（§2.7）。带基址回写的
  `LDM rB!, {...}` 与含 `sp`/`lr`/`pc` 的列表仍按整块边界处理；
- **任何不在白名单里的助记符**（未知指令可能写寄存器或改标志，一律当边界）。

注释、`.loc`/`.file` 之类的伪指令与空行不是边界（它们没有寄存器或标志副作用）。

助记符比较**大小写不敏感**：发射器会打印小写 `bx` / `rev16` / `revsh` / `rrx`，
也会打印带条件后缀的 `MOVNE` / `MOVEQ` / `MOVHI` / `MOVLS` / `MOVLT` / `MOVGE`。
带条件后缀的形式不在白名单里，因此整体当边界。

### 3.1 读集：两个被抓出来的致命错误

「哪些操作数算读」是这一族 pass 唯一的真陷阱，第一版在这里错了两次，都是**真实误编译**：

1. **双操作数 ALU 读自己的目标。** `MUL r0, r7` 是 `r0 = r0 * r7`，`r0` 既是目标也是源。
   第一版把「所有寄存器减去目标」当读集，于是 `MOV r0, r5` + `MUL r0, r7` 里的
   `MOV` 被当成死拷贝删掉，程序读到了旧 `r0`。修法：源部分只取第一个逗号之后，
   并在 `cm_is_rmw()` 判定为双操作数自我更新时把目标也计入读集。
2. **`STR` 的第一个操作数是源。** 第一版假设 `operands[0]` 总是纯写目标，
   于是 `STR r0, [r6, #24]` 被当成「写 r0」，它前面的 `MOV r0, #0` 被删掉，
   中断标志位写成了垃圾。修法：对 `STR` / `STRB` / `STRH` / `CMP` / `CMN` / `TST` /
   `PUSH` / `NOP` 这些「首操作数不是目标」的助记符，读集**扫描整串操作数**。

门禁里的 `strfirst` 夹具就是第二个错误的回归守卫：
它让 `MOV r5, r0` 的唯一消费者是 `STR r5, [r1]`，若把 `STR` 当写就会删掉这条拷贝，
存进 `cm_vv` 的就不是 5，返回值和期望不符。

## 4. 明确拒绝的形态

- `ADD` / `SUB` / `AND` / `ORR` / `EOR`：可能写标志，而且语料里满是
  `ADD rX, rB, #0` 拿来做拷贝——按「拷贝」处理会改变值域；
- `MUL`：`MULS` 写 N/Z；
- 写回 / 后索引寻址；
- `LSL #s` 之外的寄存器索引（`LSR` / `ASR` / `ROR` 索引、`RRX`）；
- 位移超过 4095；
- **两操作数**的移位/扩展（`LSL rD, rS` 置 N/Z/C，改写会改标志）；
- M6 里跨越任何别的写标志指令（只认紧邻；`pcmp` 被非 `CMP` 单元清零）；
- 任何需要活跃性分析才能证死的删除（块尾、跨块）。

## 5. 一条没活下来的规则

除了下面这条 `MOVW`+`MOVT` 冗余对，还试过一条「把常量生产者登记下来交给 M3 检查」的机制
（`cm_cdef`/`cm_canddef`），也被删掉了：它的后置判据只在**折叠点**检查存活，
而折叠没实际发生（值 >255 或负）时折叠点自己还在读源寄存器、又不在扫描范围内，
于是会**误删仍被读的常量生产者**——这正是本 pass 最不能出的那种静默错答案。
删掉它不损失收益：能置常量状态的生产者都是标志中性写，M3 本来就覆盖。

第一版还有第四条规则：`MOVW`+`MOVT` 的值如果寄存器里**已经是**这个常量，整对删除。

语料上实测 **0 命中**：两个相同常量对之间必然夹着一次对寄存器的读（清掉状态），
没有读的时候前一对本来就因为别的理由死了。按「不留从不触发的代码」的原则，
本轮把这规则连同它的状态（`pknown/pval`）一起删掉，规则重编号为 M1/M2/M3
（后来的 M4/M5/M6 接在后面编号，不是重排）。
这件事记在这里，是因为它本身就是一条结论：**这族形态在语料上不存在。**

逐 TU 累加（实测，非推导）：−2,422（M1–M7）之后再 −1,164（M8）、再 −476（M9），
合计 −4,062（−10.11%）。

M8 的 −571 同样可以逐条对到语料上，而且这一次账是**单行项**：

| 项 | M1–M7 | M1–M8 | 差 |
| --- | ---: | ---: | ---: |
| `MOV rD, #imm` | 1,927 | 1,374 | **−553** |
| `MOV rD, rS` | 1,156 | 1,138 | −18 |

| 全部助记符 | 14,940 | 14,369 | **−571** |

其余高频助记符逐项一字不变：`LDR` 1,600、`ADD` 1,270、`MOVW` 937、`STR` 915、
`PUSH` 895、`CMP` 845、`B` 817、`MOVT` 803、`POP` 566。

更强的一条证据是**逐文件差分**：把两棵树（M1–M7 / M1–M8）的 95 个 `.s` 用
`difflib` 逐行比对，结果是 **删除 571 行、新增 0 行、其他改动 0 行**，
而且删掉的每一行都匹配 `MOV rD, #imm` 或 `MOV rD, rS`。
换句话说，这条规则在真语料上只能动这两行形态，别的一个字节都不碰。

M9 的 −238 是三笔账，而且 push 与 pop **不等量**：

| 项 | M1–M8 | M1–M9 | 差 |
| --- | ---: | ---: | ---: |
| `PUSH {r0}`（全语料） | 674 | 532 | **−142** |
| `POP {r0}`（全语料） | 202 | 122 | **−80** |
| `MOV r0, #0` / `MOV r0, #1`（M8 连带） | — | — | −16 |
| 全部助记符 | 14,369 | 14,131 | **−238** |

142 : 80 的不对称是这条规则的正常形态：一个合流点可以有多条前驱各自 push，
但只有一个 pop，所以被删的 push 一定不少于 pop。同一次差分（M1–M8 / M1–M9）
是 **11 个 `.s` 有改动、删除 238 行、新增 0 行**，删掉的每一行都是
`PUSH {r0}` / `POP {r0}` / `MOV r0, #0` / `MOV r0, #1` 四种形态之一。
最后那 16 条 `MOV` 不是 M9 自己删的，而是回环拿掉之后 M8 的活跃性终于能判死它们——
这也顺带证明了「M9 放在 M8 之前」这个顺序是对的。

M7 的 −296 可以逐条对到语料上（三棵树的同一双计数器逐助记符相减）：

| 项 | M1–M6 | 七条规则 | 差 | 归属 |
| --- | ---: | ---: | ---: | --- |
| `PUSH` | 962 | 895 | **−67** | M7 删的推拉对 |
| `POP` | 633 | 566 | **−67** | 同上 |
| `MOV` | 3,733 | 3,594 | −139 | M3 被新判据放出来的死写 |
| `LSL` | 186 | 163 | −23 | 同上 |
| 合计 | 15,236 | 14,940 | **−296** | |

即 **67 对推拉（134 行）+ 162 行中间的死写 = 296 行**，与实测差逐位相等。
M1–M6 版本的树里剩下 74 个「`PUSH {r0}` / `MOV r0, #0` / `MOV r1, #0` / `POP {r0}` /
`LDR r0, [r0, r1, LSL #2]`」形态的站点，最终删掉 67 个；剩下 7 个形似站点中间的那条写
仍被后面的指令读走，所以一对都没删——这正是「不做全局活跃性分析」的代价，也是它安全的原因。

助记符账（M1–M6 版本，同一批 `.s` 逐行统计，基线 vs M1–M6 全开；M7 的那一段就在上表）：

| `cm_split` | 拆成「助记符 + 其余」 |
| `cm_reg` / `cm_imm` | `rN`（0..12）/ `#十进制` |

| `cm_write_first` | 第一个操作数是否纯写目标 |
| `cm_neutral` | 该助记符是否是标志中性写 |
| `cm_boundary` | 是否结束块 |
| `cm_is_rmw` | 双操作数自我更新（`MUL rD, rS`、`LSL rD, rS` …） |
| `cm_uses` | 读集（§3.1） |
| `cm_mem_idx` | 识别 `[rB, rI(, LSL #s)]` 形态 |

### 3.2 读集：第三个致命错误——`CBZ`/`CBNZ` 读首操作数

`-fopt-cbz` 把 `CMP r0, #0` + `BEQ` 折成 `CBZ r0, label` 之后，M8 的块内 use 集里必须
出现 `r0`。第一版既没把 `CBZ`/`CBNZ` 列进 `cm_modelled`，又让 `cm_no_reg_effect`
走 `cm_cond_branch` 把它们当成「不读任何寄存器」，于是 `CBZ r0` 前那条唯一的写
`MOV r0, #0` 看起来是死写，被 M8 删掉——`&&` 表达式因此在 `-fopt-cbz -fopt-cmat`
下返回 1 而不是 0。

第二个错误在同一规则里：块后继用 `cm_label_block(nb, u->ops)` 在**整串**操作数里找
标签，而 `CBZ`/`CBNZ` 的目标标签在逗号之后，分支边完全缺失（`CMP`+`BEQ` 的目标是
唯一操作数，所以没暴露）。

修法：`cm_modelled` 收 `CBZ`/`CBNZ`；`cm_boundary` 显式保留它们为块边界；
`cm_no_reg_effect` 对它们返回「读首操作数」；后继计算新增 CBZ/CBNZ 分支，从逗号后
取目标标签，再补上顺序后继。门禁见 `tests/run_cmat_tests.py` 第 5f 节
（`join_shapes` + untorn 值）。
