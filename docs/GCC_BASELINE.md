# 对照组换人：gcc 基线（2026-11-25 实测）

[English](GCC_BASELINE.en.md) | 中文

> 一件事：**「打过 armcc」这个目标已经过期了——gcc 13.2.1 在这套 95 TU 语料上比 armcc
> 5.06u7 少 20% 指令。所以 0.9.1 之后的第一对手是 gcc，不是 armcc。**
>
> 本文只做三件事：把 gcc 的基线量死（§1）、把差距逐 TU 与逐函数摊开（§2）、
> 把 23.5% 语料份额的那个单点函数的根因写清楚（§3）。不写实现计划，实现见后续预注册。

## 1 三方基线

**口径必须完全一致**：同一份 95 个 TU（`examples/ark_test` 的 `Core/Src` +
`Drivers/STM32F4xx_HAL_Driver/Src`），同一套 `-I`，只换编译器。

| 臂 | 版本 / 开关 | 指令 | asm 文本字节 |
| --- | --- | ---: | ---: |
| arkc（本仓库 HEAD） | 26 开关（`sw24` + `-fopt-exit` + `-fopt-bitmask`）+ `-O2` | **11,666** | **396,986** |
| armcc | 5.06u7，`-O2` | 5,619 | 13,920（这是**镜像大小**，不可比） |
| **gcc** | **arm-none-eabi-gcc 13.2.1，`-mcpu=cortex-m4 -mthumb -O2 -S`** | **4,469** | **174,119** |
| gcc（尺寸档） | 同上，`-Os` | 4,303 | 169,681 |

三句话：

1. **arkc / gcc `-O2` = 2.61×**；arkc / armcc `-O2` = 2.08×。
2. **gcc 比 armcc 好 20%（4,469 对 5,619）**，所以拿 armcc 当标尺会低估自己的差距；
   `docs/BOUNDARY.md` §7 里「打到 5,619」那句的对手应当换成 4,469。
3. 字节列只能同类相比：arkc 与 gcc 都是 `.s` 文本字节（含指示符、标签、行号），
   armcc 的 13,920 是 ELF 镜像大小，**不得**把两者放在一张表里做倍数。

复现（只读，未入库）：



## 3 根因：`__HAL_DMA_CLEAR_FLAG` 的嵌套三目被逐次重算

先把量摆出来（`D:/tmp/bm/gate_exit/s9b_off/stm32f4xx_hal_dma_ex.c.s`，按 `.loc` 归并）：

| `.loc` 行 | 指令 | 是什么 |
| --- | ---: | --- |
| 27,897 | 419 | `__HAL_DMA_CLEAR_FLAG(hdma, ...)` |
| 27,898 | 419 | 同上 |
| 27,899 | 494 | 同上 |
| 27,900 | 537 | 同上 |
| 27,901 | 540 | 同上 |
| 其余 24 个 `.loc` | 223 | 函数真正的逻辑 |
| **合计** | **2,632** | |

五条语句 = **2,409 条 = 该函数的 91.5%**。它们不是五段不同的代码，是**同一个宏的展开**：

```c
/* stm32f4xx_hal_dma_ex.c，预处理后 27,897–27,901 行，一条语句一行 */
__HAL_DMA_CLEAR_FLAG(hdma, __HAL_DMA_GET_TC_FLAG_INDEX(hdma));
```

宏体（`stm32f4xx_hal_dma.h`）把「选哪个寄存器 + 选哪个掩码位」写成**一条**巨型条件表达式：
外层按 `hdma->Instance` 落在哪个 DMA 控制器选 `HIFCR/LIFCR`（4 个臂），每个臂里再挂一条
**13 路**的 `hdma->Instance == &DMAx_StreamY ? mask : ...` 链。于是**一条语句 = 4 × 13 = 52 次
指针比较**，每次比较的三条指令是：

```asm
    LDR r0, [r6, #0]        ; 重新把参数 hdma 从帧槽里载回来
    LDR r5, [r0, #0]        ; 重新读 hdma->Instance
    LDR r7, .Llit_2_2_5     ; 重新从字面量池载入 stream 地址
    CMP r5, r7
    MOV r0, r5              ; ← 死搬运
    MOV r1, r7              ; ← 死搬运
    BNE .L_..._325
```

对照 gcc 的同一段（`D:/tmp/bm/gccbase/O2/stm32f4xx_hal_dma_ex.c.s`）：`hdma->Instance`
**一次载入 r4 就不再重载**，13 路链用 `adds r3, r3, #24` 沿 0x18 的步长走，比较一律
`cmp r4, r3` / `beq`。整函数 292 条。

指令构成对照（同一函数）：

| | arkc | gcc |
| --- | ---: | ---: |
| LD/ST（`LDR/STR/LDRB/…`） | 840 | 111 |
| MOV | 587 | 89 |
| 分支（`B`/`Bcc`） | 529 | 33 |
| PUSH | 324 | 3 |
| CMP | 266 | 21 |
| POP | 70 | 3 |
| 合计 | 2,632 | 304（含 8 个 `.word`） |

四个可打点，按上界从大到小：

1. **重复载入没有 CSE**：`hdma` 是帧槽里的参数、`hdma->Instance` 是普通指针成员，两者在
   一条语句内被重复读 52 次，中间**没有任何写**（唯一的写是那条条件表达式的最终赋值）。
   这是「同一条语句内、无调用无写」的 CSE，语义上是安全的。
2. **同一常量地址在一条语句内被物化 4 次**：13 个 stream 地址在 4 个外层臂里各载一次。
   `-fopt-constcache` 只覆盖立即数与少量字面量，覆盖不到这种跨块重复。
3. **比较前的两条死搬运** `MOV r0, r5` / `MOV r1, r7`：比较的「操作数入位」沿用了值栈
   的三地址形状，而分支两侧都会先写 `r0`、`r1` 从不被读。
4. **地址链没有强度削减**：13 个相邻 stream 只差 0x18 字节，gcc 用 `adds` 走步长，
   我们每条都从头载入。

## 4 第一切片的验收口径（先写明，后实现）

对象就是上面那一个函数，理由：它单点占语料 23.5%、占「到 gcc 的总差」32.5%，
而且**一个函数的读数就能验证方向对不对**，不必等全语料跑完。

- **主判**：`HAL_DMAEx_MultiBufferStart_IT` 从 2,632 降到 **≤ 1,400 条**（−47% 以上）；
- **次判**：26 开关口径全语料 **≥ 5%**（11,666 → ≤ 11,083 条）**且字节不增**；
- **正确性**：26 开关 95 TU 全编译通过、`tests/arm_exec` 四臂 0 failure、
  `run_peep_tests.py` / `run_addr_tests.py` / `run_vreg_tests.py` / `run_cmat_tests.py` /
  `run_litpool_tests.py` / `run_bitmask_tests.py` 全绿；
- **OFF IS OFF**：新开关关掉时 95 TU 产物**逐字节**等于今天；
- **裁切**：新开关在 `ARKCC_PROFILE=STM32_MIN` 下为 0，`C*` 按名拒绝，默认档体积不变；
- 不足 5% ⇒ 按仓库纪律登记或撤回，不留在树里当「差不多有用」。

## 5 负数：一条文本层的「重复载入消除」救不了这个函数

很自然的下一个念头是「加一条 pass：同一个地址重复载入就复用」。先量上界，再决定写不写。

| 读数 | 数字 | 占 11,666 |
| --- | ---: | ---: |
| 该函数在 `-fopt-live` 打开前后的指令数 | 4,013 → 2,745（**−1,268 = −31.6%**） | — |
| 全语料「同块内、同地址、中间无 store/调用」的重复载入 | **47** | 0.40% |
| 全语料跑一遍「可用载入」数据流（汇合点取交集、写基址/写目标寄存器即失效）后的重复载入 | **5** | 0.04% |

**为什么跨块一条都捞不到**：判据不是「同一个地址」，而是「那个值此刻还在哪个寄存器里」。看
§3 那个循环节——`LDR r0, [r6, #0]` 把帧槽里的 `hdma` 读进 **r0**，紧接着比较前的
`MOV r0, r5` **又写了 r0**，于是「`[r6,#0]` 的可用副本」在每一次比较处都被自己的操作数入位
抹掉；到了 label 上（每条三目分支都是一个 label），可用集已经空了，下一次自然只能重新载入。
换成寄存器身份来记也一样：被复用者必须是**跨块活着**的寄存器，而 r0/r1 正是最不该跨块活着
的那两个。

结论写死两句：

1. **文本层的重复载入消除到这里为止**——不是没写，是上界 0.04%。这和
   `docs/EXPR_MODEL.md` §9（语句内三地址值 0.137%）、`docs/RA_MODEL.md` §2（九族残形 1.42%）
   是同一个结论的第三次独立复现：**表面上看是「多发了指令」，实际上是「值没地方常住」**。
2. 要让这个函数掉下来，只有一条路：**让值在块之间与分支之间常驻一个寄存器**（r4–r11），
   也就是 `docs/RA_MODEL.md` §3 的目标模型 / `docs/EXPR_MODEL.md` §10 的跨块值传递（S10）。
   本文 §4 的验收口径因此挂在那个模型上，而不是挂在任何一条新窥孔上。

复现（只读，未入库）：`python -X utf8 D:/tmp/bm/loadcse_ub.py`（括号内的口径：块 = label 切分，
transfer 在 store / PUSH / BL 处清空可用集，写基址寄存器或写持有者即删条目，汇合点取交集）。
