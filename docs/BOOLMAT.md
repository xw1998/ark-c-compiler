# 布尔物化消解（`-fopt-boolmat`）

[English](BOOLMAT.en.md) | 中文

> 0.9.1 的第七块优化。一句话：**比较的结果本来就是 0 或 1，再拿它跟 0 比一次是多余的
> ——`(a<b) != 0` 是恒等，`(a<b) == 0` 是取反，把这层多余的物化在 IR 里拆掉。**
>
> 实现位置：`src/opt.c`，`opt_boolmat_func()`（IR 阶段 `ir.boolmat`，排在 `ir.deadpush` 之后）
> 门禁：`tests/run_boolmat_tests.py`（`make test-boolmat`）
> 开关：`-fopt-boolmat` / `-fno-opt-boolmat`，INI `opt-boolmat=` / `boolmat=`
> 可裁切：`ARKCC_FEATURE_OPT_BOOLMAT`（`STM32_MIN` 剖面为 0，被裁掉后按名字拒绝）

---

## 1. 现象：同一个布尔值被算了两遍

C 里 `if (p && q)`、`if ((a < b) != 0)`、`return (x == y) != 0;` 都很常见。前端把
`!= 0` 如实发成「压 0，再比一次」，于是 IR 里出现

```
BINARY LT          ; a < b        —— 结果已经是 0/1
PUSH_INT 0
BINARY NE          ; (a<b) != 0  —— 恒等，白算
```

后端再把两条比较各自物化一次：

```asm
CMP   r5, r7
ITE   LT            ; a < b 变成 int
MOVLT r0, #1
MOVGE r0, #0
CMP   r0, #0
ITE   NE            ; 再跟 0 比一次
MOVNE r0, #1
MOVEQ r0, #0
```

后四条指令的输入只有 0 和 1 两种取值，输出恒等于输入——**五个字节、四条指令，零信息**。
如果这个值紧接着被 `if` 消费，`-fopt-cbranch` 本来能把「比较 + 条件跳转」折成两条，
但因为中间夹了这层物化，它认不出前面是一条比较，折叠也就没发生。

## 2. 三条规则

整个 pass 只在 IR 上做局部改写，共三条规则，全部跳过 `IR_NOP`（别的 pass 留下的空位）。

### R1 —— 帧往返（`STORE w ; PUSH_VAR w`）

`int x = (a<b); if (x)` 会先把值写进帧、再读回来。写 4 字节、紧接着读同一 4 字节，
净栈效应为 0，读回的就是刚写进去的那 4 个字节。判据：

| 条件 | 判据 |
| --- | --- |
| 宽度恰好 4 | `aux & 0xFF` 为 0 或 4；`VOLATILE`/`SLOT64`/`COMPLEX` 一律拒绝 |
| 同一槽 | 两条指令的 `val`（帧偏移）相等 |
| 无人旁观 | 全函数内除这两条外，没有任何 `STORE`/`PUSH_VAR`/`PUSH_ADDR`/`STORE_FLD`/`LOAD_FLD` 的 `val` 落在 `[off-3, off+3]` |
| 函数干净 | 含 `IR_ASM` 或 `IR_ALLOCA` 的函数整段跳过 |

宽度必须**恰好 4**：`char c = 300` 的 1 字节往返不是恒等（存 `0x2C`、读回 44）。
「±3 窗口」一次覆盖三种旁观者：同槽的第二次读、同字内的位域邻居、以及取地址。
含 `IR_ASM`/`IR_ALLOCA` 直接放弃，是沿用 `-fopt-prop` 对同一个问题的既有保守先例
（内联汇编可以按偏移点名一个帧槽，`ALLOCA` 会改变「帧」的含义）。

R1 在 HAL 语料上**只省了 3 条指令**——因为前端对「临时布尔」多数情况下已经用了值栈
寄存器而不是帧槽。真正的大头是下面两条。（这条实测留着，是因为 R1 是这条通道上唯一
必须有的正确性兜底：一旦别的 pass 把值挤回帧里，它就是免费的。）

### R2 —— 恒等（`<cmp> ; PUSH_INT 0 ; BINARY NE`）

比较结果 ∈ {0,1}，`x != 0` 就是 `x` 本身。所以把中间那条 `PUSH_INT 0` 和末条 `BINARY NE`
都删掉，比较结果留在值栈上。**删掉之后比较直接贴上它的消费者**，`-fopt-cbranch` 于是
认出 `<cmp> + JZ/JNZ`，折成 `CMP` + 一条条件分支。

### R3 —— 取反（`<cmp> ; PUSH_INT 0 ; BINARY EQ`）

`x == 0` 等于 `x ^ 1`（`x` 只有 0/1 两种取值）。把 `PUSH_INT 0` 改成 `PUSH_INT 1`、
`BINARY EQ` 改成 `BINARY BXOR`，`-fopt-imm` 再折成一条 `EOR r0, r0, #1`。
四条指令变一条。

**但有一个例外**：如果 `BINARY EQ` 的下一条（跳过 `NOP`）就是 `JZ`/`JNZ`，R3 主动放弃。
理由是对比两种走法：

| 走法 | 结果 |
| --- | --- |
| 交给 `-fopt-cbranch` | `CMP r0, r1` + `BNE/BEQ target`（**2 条**，条件取反就行） |
| R3 改成 `^ 1` 再由 cbranch 消费 | `CMP` + `ITE` + 三条 MOV + `EOR #1` + `CMP #0` + 分支（**更多**） |

R2 没有这个例外——删掉那对往返之后，剩下的正是 cbranch 最想要的样子。
R1 也与分支无关（它不改变栈上值的形状）。

### 匹配的确切形状

首条必须是 `IR_BINARY` 且 `aux & ~0x100` 属于 `{EQ, NE, LT, GT, LE, GE}`，
`aux` 除 `0x100`（无符号比较位）之外不允许有别的位；中间必须是 `val == 0` 的
`IR_PUSH_INT` 且不带 `VOLATILE`；末条必须是 `aux` 恰好等于 `TOK_NE` 或 `TOK_EQ`
的 `IR_BINARY`。首条不是比较的（`(a & 3) != 0`、`(a + b) != 0`、`char` 变量、
指针取值、函数返回值、`long long` 比较走的是 `IR_64CMP`）一律不碰——
那些值的取值域不是 {0,1}，删掉就是错答案。

## 3. 为什么是 IR 层，而不是新加一条指令

最初的方案是「新增一个 IR opcode 表示『标志位仍然有效』」，那要动 irgen、`irser`、
MIR 和四个后端。读完代码发现不必：`-fopt-cbranch` 已经在**发射器**里做了
「`BINARY <cmp>` 紧跟 `JZ/JNZ` → 单条条件分支」，所以只要在 IR 层把多余的物化拆掉，
比较结果自然落在值栈上、自然贴上分支，下游自己去兑现收益。这样只改一个文件，
零新增 opcode，四个后端行为不变。

## 4. 实测（95 个 HAL/Core TU，`-O2` + 23 个 `-fopt-*`）

| 指标 | 关 | 开 | 差 |
| --- | --- | --- | --- |
| 指令数 | 12,266 | 12,146 | **−120** |
| 汇编字节 | 405,833 | 403,994 | **−1,839** |
| 未定义标签 / 失败 TU | 0 / 0 | 0 / 0 | — |

逐 TU 只有 8 个 TU 变短、没有一个变长（`stm32f4xx_hal_rcc.c −27`、
`ll_utils.c −16`、`hal_dma.c −13`、`hal_dma_ex.c −10`、`hal_rcc_ex.c −9`、`hal_exti.c −7`、
`hal_gpio.c −4`、`hal_pwr_ex.c −4`）。

**收益比预期小，原因已经量清**：语料里剩下的 40 个 `ITE` 块中绝大多数是
**短路求值**（`if (A || B)`、`A ? 1 : B`）的形状——两个分支各自压一个值到栈上，
在汇合点必须让两边的栈形状一致，于是 `ITE` 物化不可避免，而消费它的 `CBZ` 在汇合点
之后。那不是这条 pass 能碰的（要 CFG 级重写分支目标），已登记为后续项。

## 5. 门禁

`tests/run_boolmat_tests.py`（`make test-boolmat`）逐条钉死：

| 检查 | 内容 |
| --- | --- |
| OFF IS OFF | `-O2` 与 `-O2 -fno-opt-boolmat` 的汇编与镜像**逐字节相同** |
| IT PAYS | `ITE` 块数与总指令数都下降，且都不是 0（否则「规则从不触发」也能过） |
| R2 会触发 | 只有 `(cmp) != 0` 形状的夹具：`ITE 16 → 8`，指令 `412 → 340` |
| R3 会触发 | 值被使用（不是被分支消费）的 `!` 形状：`ITE 10 → 7`，指令 `232 → 223` |
| R3 会退让 | 同一批 `!` 形状但被 `JZ` 消费时，带旗标与不带旗标**逐字节相同**（让位给 cbranch） |
| 必须不动 | `(a&3)!=0`、`(a+b)!=0`、`char` 变量、指针取值、函数返回值、`long long` 比较 → 逐字节相同 |
| 答案不变 | 六种关系、无符号、取反、嵌套、值当 `int` 用、值参与算术：五个臂（`base`/`off`/`on`/`va`/`all`）在 unicorn 上返回同一个值，且与 Python 独立算出的期望值一致 |
| 裁切拒绝 | `-DARKCC_FEATURE_OPT_BOOLMAT=0` 的构建对 `-fopt-boolmat` 报 `C3900U` 并点出旗标名；不带旗标照常编译 |

## 6. 归属

- 与 `-fopt-cbranch`、`-fopt-imm` **超可加**：R2 把比较送到分支旁边、R3 把 `== 0`
  变成一条 `EOR` 立即数，两个下游都因此拿到更多机会。R2/R3 各自单独开也变小，
  但一起开收益更大（上面的 `va → all` 两列）。
- 与 `-fopt-prop` 的次序是刻意的：`prop` 先把「存常量再读回」折成立即数，
  boolmat 只处理剩下的非常量情形，两者不重叠。
