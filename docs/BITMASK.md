# 取反掩码的直接编码（`-fopt-bitmask`）

[English](BITMASK.en.md) | 中文

> 0.9.1 的第九块优化。一句话：**`~常数` 被建成 `MOV rX,#imm` + `MVN rX,rX` 两步，
> 紧接着的 `AND` / `MOV` 只把它的结果拿来用——这两步可以一步写成 `BIC` / `MVN` 的
> 立即数形式，于是三条并成一条。**
>
> 实现位置：`src/backend/arm/backend_arm.c`，`ark_bitmask_function()`（ARM 后端文本行级
> pass，紧跟 `ark_cmat_function()` 之后、`ark_litpool_function()` 之前）
> 门禁：`tests/run_bitmask_tests.py`（`make test-bitmask`）
> 开关：`-fopt-bitmask` / `-fno-opt-bitmask`，INI `opt-bitmask=` / `bitmask=`
> 可裁切：`ARKCC_FEATURE_OPT_BITMASK`（`STM32_MIN` 剖面为 0，被裁掉后按名字拒绝）

---

## 1. 现象：每个 `& ~常数` 都先建掩码再取反

`x & ~4u` 在前端是「取 `4` 的反再按位与」，后端按顺序发出来是：

```asm
MOV   r0, #4
MVN   r0, r0
MOV   r7, r0          ; 掩码落到一个长寿命寄存器
...
AND   r0, r7          ; 消费
```

前两条是**把 `~4` 建成一个寄存器值**。Thumb-2 的 `BIC` 与 `MVN` 都带立即数形态，
而它们要的立即数正好就是这里的 `imm`（不是它的反）：

- 消费者是 `AND rD, rX`（且 `rX` 在消费者之后死亡）⇒ `BIC rD, rD, #imm`
- 消费者是 `MOV rD, rX`（纯复制）⇒ `MVN rD, #imm`

于是三条指令压成一条。这是**纯文本层**的重写：不碰标签、不碰分支目标、不碰帧大小，
所以 `ark_fix_far_offset`、字面量池偏移、控制流看到的仍是同一个函数。

## 2. 三条前提

### 2.1 三条相邻活行

必须是字面相邻的三行（允许中间有空白/注释类的空行）：

```
MOV  rX, #imm
MVN  rX, rX
<消费者>
```

只认这一个形状。中间插了别的指令（比如掩码被先 `STR` 出去）就不折——那说明掩码
本身有独立用途，折叠会把它的构建成本转嫁到别处。

### 2.2 `imm` 必须能编成 modified immediate

`BIC #imm` / `MVN #imm` 都是 `thumb_imm12_a()`（`imm12` + 4 位旋转）。判据是
**旋转后的 8 位模式**：允许奇数旋转，例如

`0xD0000 = 0xD0 ROR 20` —— 奇数旋转 20，合法，`MVN rD, #0xD0000` 编得出来；
`0x101` 不是任何 `imm8 ROR 2k` 的形状，`BIC/MVN` 立即数形式编不出来，**拒绝**。

（`imm == 0` 也拒绝：`~0` 是 `0xFFFFFFFF`，那是 `MVN rD, #0` 的语义，但
`MOV #0` + `MVN` 这种形状在语料里不出现，保守起见不进规则。）

### 2.3 消费者必须是严格两操作数形式，且 `rX` 在之后死亡

- `AND rY, rX`（两操作数，第二操作数是 `rX`）或 `MOV rY, rX`。
  `AND rY, rZ, rX` 这种三操作数/移位形态一律不认。
- `rX` 在消费者之后必须**可证明死亡**，否则掩码还有下家，折叠会删掉它。
  证明是前向线性扫描（`bmk_dead`）：

| 扫描中遇到 | 处理 |
| --- | --- |
| 任何提到 `rX` 的助记符（除下表） | 判活，放弃 |
| 写入 `rX` 的行（`MOV/MOVW/MOVT/LDR/…  rX,`） | 判死，折叠成立 |
| `POP {…, rX, …}` | 视为写（callee-saved 槽被恢复），判死 |
| label 定义 | 跳过，继续（扫描区已由「遇分支即放弃」保证为无分支线性区） |
| `B .Lx` 无条件跳转 | 跟踪到目标继续，最多 4 跳；超过或目标缺失则放弃 |
| 其他分支（`Bcc`/`CBZ`/`CBNZ`/`BX`/表跳转）、未知助记符提到 `rX` | 放弃 |
| 40 行内还得不到结论 | 放弃 |

`AND` 且 `rX == rY`（`AND rD, rD`）时不需要活跃性证明：`rD` 被就地覆盖，
折叠前后 `rD` 的最终值相同，没有第二个读者可失去。

## 3. 为什么排在 `-fopt-cmat` 之后、`-fopt-litpool` 之前

- **cmat 之前不行**：`-fopt-cmat` 决定掩码是否还需要被材料化（它能把一次性的
  常量掩码直接吃进消费者），顺序反了会先折一遍、再被 cmat 覆盖。
- **litpool 之后不行**：32 位掩码一旦进了字面量池就变成 `LDR rD, <label>`，
  `MOV #imm` 那条线已经不存在了。放在前面才能看见 `MOV`，也让 `BIC/MVN` 的
  立即数形态免于进池（4 字节 vs 池里 4 字节 + 一次 `LDR`）。
- **必须 `-fopt-vstack` 在上游**：值栈留在栈上时，掩码的构建与消费之间会夹一堆
  `PUSH`/`POP`，三条不相邻，pass 什么也看不见。

## 4. 实测（95 个 HAL/Core TU，`-O2` + 25 个 `-fopt-*` 含 `-fopt-exit`）

| 指标 | 关 | 开 | 差 |
| --- | --- | --- | --- |
| 指令数 | 11,877 | 11,766 | **−111** |
| 汇编字节 | 400,125 | 398,673 | **−1,452** |
| 未定义标签 / 失败 TU / 变大 TU | 0 / 0 / — | 0 / 0 / 0 | — |

关掉时与上一版 25 旗标基线**逐字节相同**（0 diff），所以 −111 完全是这一块。

逐 TU 下降（前 9）：`stm32f4xx_hal_dma −39`、`hal_pwr −17`、`hal_rcc −17`、
`ll_utils −9`、`hal_rcc_ex −8`、`hal_flash −6`、`hal_flash_ex −6`、`hal_cortex −5`、
`stm32f4xx_hal −4`。

折叠站点：`BIC rD, rD, #imm` **35 处**，`MVN rD, #imm` **26 处**，合计 **61**。
残留 5 处未被折叠：4 处 `AND r7, r0`（`imm` 不可编码，或消费者不在无分支的
线性区），1 处 `UXTB r0, r0`（不在规则内，输入也不是 `~常数`）。

## 5. 编码正确性：与 GNU as 逐字节对拍

`MVN`/`BIC` 的立即数形态不是本项目自己发明的编码，直接用交叉汇编器核对
（`arm-none-eabi-as`，默认 `DEFAULT_GNU_BIN`）：

| 源 | 编码 |
| --- | --- |
| `MVN r7, #0x1` | `6ff0 0107` |
| `MVN r7, #0xD0000`（奇数旋转） | `6ff4 5027` |
| `MVN r1, #0x80000000` | `6ff0 0041` |
| `BIC r7, r7, #0x1000000` | `27f0 8077` |
| `BIC r3, r3, #0x2` | `23f0 0203` |
| `BIC r10, r10, #0x40000` | `2af4 802a` |

`arkcc` 的产物与上表**逐字节相同**。这条对拍的作用是钉住「立即数编码器不自己
发明形状」——包括那条容易看错的奇数旋转。

## 6. 门禁

`tests/run_bitmask_tests.py`（`make test-bitmask`）逐条钉死 18 项：

| 检查 | 内容 |
| --- | --- |
| OFF IS OFF | `-O2 <passes>` 与再加 `-fno-opt-bitmask` 的汇编与镜像**逐字节相同** |
| 复制折会触发 | `MOV/MVN/MOV` 变成单条 `MVN rD, #0x4`，且函数**恰好少两条**（只查"没变长"抓不住一条从不触发的规则） |
| 与折会触发 | `MOV/MVN/AND` 变成 `BIC rD, rD, #0x2`；关掉那一臂里只有 `AND rD, rX`、没有 `BIC`；同样**恰好少两条** |
| 奇数旋转 | `~0x000D0000` 必须折成 `MVN rD, #0xD0000`（按名断言，只接受偶旋转的实现会在这里红） |
| 不可编码拒绝 | `~0x101u` 的函数**逐字节相同** |
| 无相邻消费者不动 | 掩码建好先 `STR` 出去的函数**逐字节相同** |
| 活掩码不被破坏 | 消费者之后还要读掩码时，只许改写副本：`MVN rD, #0x8` 出现，且**恰好少两条** |
| 整文件账 | 指令数下降、镜像不增、所有分支目标都有定义 |
| 答案不变 | 六种掩码形态（含旋转与不可编码）汇成一个校验和：四个臂（`base`/`off`/`on`/`all`）在 unicorn 上返回同值，与 Python 独立算出的期望值一致 |
| 裁切拒绝 | `-DARKCC_FEATURE_OPT_BITMASK=0` 的构建对 `-fopt-bitmask` 报 `C3900U` 并点出旗标名；不带旗标照常编译 |

## 7. 归属

- 与 `-fopt-cmat` **互补**：cmat 消掉「只用一次的掩码」，bitmask 消掉「掩码被建出来
  又立刻取反」的那两步；两者都在语料上留下对方处理不了的形状。
- 与 `-fopt-litpool` **互斥于同一个常量**：被 bitmask 折掉的 `imm` 不再进池；
  没折掉的（不可编码、或消费者形态不认）仍归 litpool 处理。
- 与 `-fopt-imm` / `-fopt-peep` **不重叠**：那两块处理的是 `MOV`/算术立即数本身，
  不认「`MVN` 是 `MOV` 的反」这条跨指令关系。
