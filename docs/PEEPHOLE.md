# 栈往返清理（`-fopt-peep`）

[English](PEEPHOLE.en.md) | 中文

> 0.9.1 的第八块优化。一句话：**值栈机把「把一个值搬到另一个寄存器」和「把刚存进
> 槽的值再读回来」都发成了经内存的往返；这两类往返在文本层面可以无风险地消掉。**
>
> 实现位置：`src/backend/arm/backend_arm.c`，`ark_peep_function()`（内部四条规则
> `pp_r1` / `pp_r3` / `pp_r5` / `pp_r6`）
> 门禁：`tests/run_peep_tests.py`（`make test-peep`），外加 `tests/arm_exec` 全语料
> 开关：`-fopt-peep` / `-fno-opt-peep`，INI `opt-peep=` / `peep=`

---

## 1. 为什么做，做在哪一层

`-fopt-vstack` 已经把「相邻的 `PUSH`/`POP` 直接在寄存器之间搬」吃掉了大部分，
但有两类形态残留在文本里：

**R1：栈上拷贝。** `int y = x;` 在值栈机上就是「把 x 压栈，再弹回另一个位置」：

```asm
    PUSH {r0}
    POP  {r0}          ; 同一个寄存器：两条都是废动作
```

```asm
    PUSH {r0}
    MOV  r0, #1
    PUSH {r0}
    POP  {r1}          ; 两个寄存器：这就是一条 MOV，栈是多余的
    POP  {r0}
```

**R3：存完立刻读回。**

```asm
    STR r0, [r6, #8]
    LDR r0, [r6, #8]   ; r0 本来就还是那个值
```

R3 的名字容易引起误会：**这里删的是 `LDR`，`STR` 一个字节都不动**，所以不存在
「删掉一次内存写」的风险。

## 2. 四条规则

扫描以函数为单位，逐行看「去缩进、去行尾 CR」之后的文本。

### R1 `PUSH {rX}` … `POP {rY}`

| 条件 | 判据 |
| --- | --- |
| **C1 形状严格** | 两边都必须是 `PUSH {rN}` / `POP {rN}` 单寄存器形（`r0`..`r12`，`r12` 也接受 `ip` 这个写法）。`PUSH {r5, r6, r7, lr}` 这种多寄存器形**不匹配**，帧操作因此天然安全 |
| **C2 中间只能是 pad** | 两条之间只允许空行、`;`/`@` 注释、`.` 开头的指示/元数据（`.loc`、`.cfi_*`）；**以 `:` 结尾的行是标签，不算 pad**，跨标签一律放弃 |
| **C3 作用域内** | 「函数内」：`ark_peep_function()` 拿到的是 `[fstart, buffer_end)` 这一段 |

三条全过 ⇒ 改写规则只有两条：

- `X == Y`：两条一起删；
- `X != Y`：替换成一条 `MOV rY, rX`（位置取原来 `POP` 之前）。

### R3 `STR rX, [r6, #o]` … `LDR rX, [r6, #o]`

| 条件 | 判据 |
| --- | --- |
| **C1 形状严格** | 必须是 `LDR|STR[BH] rN, [r6, #off]` 这一种形态：宽度 1/2/4 之一，基址严格是 `r6`（帧指针），偏移是无符号十进制。`LDRD`、`LDRSB`、`LDRSH`、前/后索引形（`[r6, #4]!`、`[r6], #4`）**一律拒绝** |
| **C2 三个字段全等** | 宽度相同、偏移相同、寄存器相同 |
| **C3 相邻** | 中间只允许 pad 行（规则与 R1 一致，`.loc` 可以穿过） |
| **C4 先存后读** | 顺序是 `STR` 在前、`LDR` 在后 |

三条全过 ⇒ **保留 `STR`、删除 `LDR`**。同一次扫描里，紧随其后的重复读
（中间仍然只有 pad）也一并删掉：`STR` 之后没人写过这个槽，多读几次都一样。

### R5 `ADD rD, rS, #0` 变 `MOV rD, rS`

| 条件 | 判据 |
| --- | --- |
| **C1 形状严格** | 必须是三操作数 `ADD rD, rS, #0`。`ADDS` 不匹配（前缀比较会先撞上 `ADD r`，但 `pp_add0()` 用 `strncmp(p, "ADD r", 5)` 直接拒绝 `ADDS`），`ADD.W`、寄存器操作数、非零立即数也一律拒绝 |
| **C2 无需活跃性** | 两侧都不写标志（`ADD` 无 `S` 后缀；`MOV rD, rS` 的 16 位形 `0x4600` 也不写），所以改写与"后面有没有人读标志"无关 |

三条全过 ⇒ `D == S` 时整行删（`ADD r5, r5, #0` 是恒等式）；`D != S` 时换成
`    MOV rD, rS`。**编码宽度是这条规则的全部理由**：`ADD rD, rS, #0` 在 Thumb-2 里
只有当 `D == S` 且 `rd <= r7` 时才走 `0x3000` 形态（那是 `ADDS`，会写标志），
`D != S` 只能编成 32 位 `ADDW`（4 B）；而 `MOV rD, rS` 是 2 B
（`add r5, r8, #0` = `08f1 0005`，`mov r5, r8` = `4600`，keystone 实测）。

改在文本层而不在发射期，是因为下游 `-fopt-live`（L1）与 `-fopt-coalesce` 只认
`MOV`：`ADD` 一条也匹配不上，`MOV` 才能被删或被前推。一次改写吃两级收益。

### R6 `PUSH {rX}` … `POP {rY}`，中间有代码

R1 只管「中间只有 pad」。可值栈的真实形态常常是「压一个值 → 材料化另一个值 → 再弹」：

```asm
    PUSH {r0}          ; 保住第一个实参，同时材料化第二个
    MOV  r0, r8
    POP  {r1}          ; 第二个实参，晚一条指令到位
```

这三行合起来就是一次**经过内存的 `MOV r1, r0`**。R6 把它改成：

```asm
    MOV  r1, r0
    MOV  r0, r8
```

| 条件 | 判据 |
| --- | --- |
| **C1 形状严格** | 两端各是单寄存器 `PUSH {rX}` / `POP {rY}`（`rN` 或 `ip`）。多寄存器形、`PUSH {r5-r7, lr}` 一律拒绝（与 R1 同一函数 `pp_pushpop()`） |
| **C2 中间不停止扫描** | 中间只允许 pad 行与「不观察栈、不转移控制」的行。**停止扫描**的是：以 `:` 结尾的标签、任何**整词**提及 `sp`（`PUSH`/`POP`/`SUB sp` 都会挪动那个槽）、任何 `B*` 前缀（`B`/`Bcc`/`BL`/`BLX`/`BX`，也顺带挡住 `BIC`/`BFI`）、`IT` 块、`CBZ`/`CBNZ`、任何 `P*`（嵌套 `PUSH`/`POP`） |
| **C3 窗口 12 行** | 从 `PUSH` 起最多看 `PP_R6_WINDOW = 12` 行；超出就放弃（漏折叠，不会错折叠） |
| **C4 `rY` 不被提及** | 中间每一行都不得以**整词**形式出现 `rY`；`X == Y` 时连 `rX` 也不得出现 |

四条全过 ⇒ `X != Y`：在 `PUSH` 的位置先发一条 `MOV rY, rX`，再照抄中间各行，删掉 `POP`；
`X == Y`：两行全删。

三条等价性论证（都写进了代码注释）：

- **拷贝必须发在 `PUSH` 的位置**。中间那段代码正是可能覆盖 `rX` 的那段——`PUSH` 保护
  的就是它。放在 `POP` 的位置就会读到被覆盖后的值。
- **`rY` 在窗口内不得被提及**。否则它要么提前拿到值（读到一个还没到位的实参），要么
  把这个值消费掉；两种情况都没法靠文本分析救。
- **`X == Y` 时 `rX` 也不得被提及**，因为那时这条规则要证明的是「这段时间里没有任何人
  观察过 `rX`」。

**这条规则不需要活跃性分析**，`C4` 已经把 `rX`/`rY` 的可观测性直接证完了；`C2` 保证
中间没有任何控制流入口、也没有任何栈操作。这也是 §3 里说的「纯文本等价变换」。
`pp_mentions()` 用的是整词边界匹配，所以 `r1` 不会在 `r10` 里命中、`ip` 不会在标签名里
命中。

`ip` 的由来：发射器把 `r12` 有时写成 `r12`、有时写成 `ip`。只认 `r12` 的老 `pp_pushpop()`
会**静默跳过**语料里的 9 条 `POP {ip}`（R1 的同类机会也一起漏了）；`pp_rname()` 负责在
写回时把它打印成 `ip`。

**实测（2026-11-24，95 TU / 十九开关）**：12,346 → **12,304**（−42 条 / −54 字节），
95/95 TU 无一变大。候选共 30 处：21 处 `X != Y`、8 处 `X == Y`、1 处 `lr → pc` 必须排除；
寄存器配对分布 `r0→r1` 12、`r0→r0` 8、`r0→ip` 7、`r5→ip` 1、`r7→ip` 1。

### 为什么 volatile 不会被误伤

volatile 访问前后发射器一定会插 `DMB SY`。`DMB SY` 既不是 pad 也不是这两条规则的
任何一端，所以「`STR` / `DMB SY` / `LDR`」这种序列在 C3 就被挡下——不需要为
volatile 单独维护一张污点表。`pp_mem()` 也只认 `[r6, #off]` 一种基址形，
经过 `r12` 的远偏移访问（`ark_fix_far_offset()` 生成的 `LDR r0, [ip]`）不匹配。

## 3. 为什么只做 R1、R3、R5 和 R6

原本列的候选里还有两条被主动放弃：

| 放弃的规则 | 为什么 |
| --- | --- |
| **R2**：`MOV rM, #k` 之后把 `rM` 的使用全部换成 `#k` | 需要向后活跃性分析（这个常量寄存器还能不能被杀掉），做错就是发出错指令；`-fopt-imm`（发射期）已经覆盖了同一个收益的大头 |
| **R4**：`MOV rD, r0` 与随后一条三操作数指令融合 | 需要跨指令的读/写分析，同样是活跃性问题 |

R1、R3、R5 与 R6 的共同点是**纯文本等价变换**：不改变任何一条指令的操作数含义，不需要
知道任何一个寄存器在别处是否还活着（R6 的 C4 已经把窗口内的可观测性证完）。这是它们能放进 0.9.1 的唯一理由。R5 比 R1/R3
更弱一档——它连「两条指令之间」都不要求，只看单行；`ADD #0` 之所以还有 `D != S` 的
形态，是因为值栈把拷贝和零位移地址材料化成了三操作数 `ADD`（见 `docs/VREG.md` §17）。
R2 与 R4 仍不做，理由不变。

## 4. 实测

语料与口径同 `docs/IMM_FOLD.md` §6：96 个 TU（93 个有效），`-O2 -mcpu Cortex-M4`，
基线为 `-fopt-vstack -fopt-addr -fopt-strength -fopt-cbz -fopt-branch`。

| 构建 | 指令数 | 相对基线 |
| --- | --- | --- |
| 基线（五个 pass） | 35,211 | 1.000× |
| 基线 + `-fopt-peep` | **33,730** | 0.958×（**−1,481，−4.21%**） |
| 基线 + `-fopt-imm` | 27,716 | 0.787× |
| 基线 + 两块 | **26,316** | 0.747×（**−8,895，−25.26%**） |

`-fopt-peep` 单独是 −4.21%，比最初估计的 −0.6% 大得多：第一版实现里 `POP` 的
助记符长度算错了（`POP` 是三个字母，代码按四个字母取偏移），于是 **R1 一处都没命中**，
只有 R3 在工作。修好之后 HAL 语料里的栈上拷贝才真正被吃掉。

两块一起开比两者相加少 81 条：`-fopt-imm` 吞掉常量 push 之后，原本会形成
`PUSH`/`POP` 相邻对的那些站点已经不存在了——这是两块优化重叠，不是互相干扰。

**后续阶梯（95 TU、十九开关全开，口径见 `docs/COMPARISON.md` §1）**：

| 阶段 | 指令 | 字节 |
| --- | ---: | ---: |
| 第一遍窥孔，R1/R3 | （见 `docs/VREG.md` 的逐阶梯表） | |
| + R5 + 第二遍窥孔（提交 `b2e915c`） | 12,795 | 33,464 |
| + 第二遍寻址折叠（见 `docs/ADDR_FOLD.md` §11） | 12,346 | 32,744 |
| **+ R6 与 `ip` 识别** | **12,304** | **32,690** |

R6 自己这一笔是 **−42 条 / −54 字节**（0.34% / 0.16%），基数是已含第二遍 addr 的
12,346；它不大，但它清掉的是「值栈把拷贝走到内存」这一类里最后一批纯文本可判的形态。

## 5. 门禁说了什么

`make test-peep`（`tests/run_peep_tests.py`）跑三份夹具 × 多臂，共 12 项全 ok：

- `COPY`（`copies`，返回 6）：连续的栈上拷贝；
- `READBACK`（`sread`，返回 13）：存完立刻读回；
- `BRANCH`（`branchy(5)`，返回 76）：分支、标签、循环——**用来证明跨标签的
  `PUSH`/`POP` 不会被误配**。

关键断言：

1. **OFF IS OFF**：`-O2` 与 `-O2 -fno-opt-peep` 的镜像逐字节相同（1298/1298）。
2. **R1 真的命中**：`PUSH`/`POP` 相邻对 `13 → 0`（`COPY` 夹具）。
3. **条数真的下降**：`124 → 83`。
4. **镜像只减不增**：`1298 → 1216` 字节。
5. **R3 真的命中**：`STR`/`LDR` 配对 `6 → 0`，镜像 `1290 → 1228` 字节。
6. **语义**：`off / on / vstack / imm` 四臂三份夹具答案全对（`6/6`、`13/13`、`76/76`）。
7. **夹具真的有分支目标**：`9` 个标签——否则「跨标签不匹配」这条断言是空的。
8. **裁切构建**按名字拒绝 `-fopt-peep`（`C3900U`，退出码 1），不带旗标仍能编译。

第 3 项与第 6 项必须同时存在：只断言「对消失了」会漏掉「配对错了、把别人的
`POP` 删了」——那种错在汇编期不报，在运行时会破坏栈。

## 6. 裁切

`include/arkcc_config.h` 的 `ARKCC_FEATURE_OPT_PEEP`：`ARKCC_PROFILE_STM32_MIN` 下为 0，
宿主 / 交叉为 1。为 0 时 `pp_*` 与 `ark_peep_function()` 整块被预处理掉，
`src/main.c` 以 `C3900U: -fopt-peep is not compiled into this build` 拒绝该旗标。

运行期默认**关**（`g_config.enable_opt_peep = 0`）。

## 7. pass 顺序

```
ark_vstack_function()      # 先删掉「相邻 PUSH/POP」里最便宜的那一层
ark_addr_function()        # 再把 ADD/MOV 折进寻址
ark_cbz_function()         # 然后 CMP #0 + 跳转 -> CBZ
ark_peep_function()        # 到这里残余的栈往返才现形（R5 -> R6 -> R1 -> R3）
ark_regalloc_function()    # 最后在更短的指令流上选寄存器
ark_fix_far_offset()       # 正确性兜底，永远最后
```

放在 `-fopt-cbz` 之后有实际理由：cbz 会删掉 `CMP`，而 `CMP` 常常正是夹在
`PUSH` 与 `POP` 之间的那条——**先 cbz 才能让两侧相邻**。

`pp_r5` 先跑、`pp_r6` 次之、`pp_r1` 第三、`pp_r3` 最后：

- **R5 只改单行**，不制造也不销毁任何配对机会，所以放最前。
- **R6 在 R1 之前**：R6 处理的是「中间有代码」的形态，R1 处理「中间只有 pad」。R1 先跑
  也吃不到 R6 的形状（它的 C2 要求中间全是 pad），两者不重叠；但 R6 会把
  `PUSH … POP` 换成一条 `MOV`，从而让后面 R1/R3 看到更短、更相邻的文本。
- **R1 的改写会插入一条 `MOV rY, rX`**，它既不是 `STR` 也不是 `LDR`，不会给 R3 制造假机会；
  反过来 R3 删掉 `LDR` 之后 R1 也不会多出机会。所以 R1 与 R3 的先后不影响结果，
  这里固定成 R1 在前只为可复现。

**第二遍窥孔**：`-fopt-live` 与 `-fopt-coalesce` 的改名会在**最终文本上**再造出一批
相邻的 `PUSH {rX}` / `POP {rX}` 死对（改造前语料 34 对里有 25 对同名、改造后只剩 9 对
且同名 0 对，就是这批被清掉了）。所以 `ark_emit_program()` 在第二遍活跃性之后、
`ark_fix_far_offset()` 之前再调一次 `ark_peep_function()`——同一门控、同一规则集，
收益是 −52 条 / −108 B。它必须在 `ark_fix_far_offset()` 之前：之后帧偏移变成经 `r12`
的间接访问，就没有 `[r6, #off]` 可配了。

第二遍窥孔之后、`ark_fix_far_offset()` 之前还**再跑一次 `ark_addr_function()`**：上面的
R5/R6 与改名的联合作用会再造出「`MOV rX, r0` 紧接着经 `rX` 的访问」这类可折形态，那
正是第二遍寻址折叠吃的东西（见 `docs/ADDR_FOLD.md` §11）。三者的相对次序是
`peep(2) → addr(2) → ark_fix_far_offset()`，而 `ark_fix_far_offset()` 永远最后。

## 8. 明确没做

| 没做 | 原因 |
| --- | --- |
| 跨标签的 `PUSH`/`POP` 配对 | 两条必须落在同一个基本块里才等价；跨标签意味着控制流可以从中间进入 |
| 多寄存器 `PUSH {r0, r1}` 的配对 | 需要逐寄存器分析栈上布局，且 `PUSH {r5-r7, lr}` 是帧操作，混在一起会出致命错 |
| `STR` / `LDR` 之间隔着一条无关指令时的 R3 | 只有「严格相邻（含 pad）」才能保证 `rX` 没被改过 |
| dead store 消除（`STR` 之后没人读） | 需要活跃性/别名分析，不在 0.9.1 的范围 |

## 9. 已知代价

- 每次 `ark_peep_function()` 调用都会静态分配两张 `PP_MAX_LINES = 8192` 的
  `int` 数组（`ls` / `ll`，共 64 KB，`static` 所以不在栈上）。超过 8192 行的
  函数整段跳过，不做优化——不会出错，只是不优化。
- 跑两遍：一次在 `-fopt-cbz` 之后、一次在第二遍活跃性之后（理由见 §7）。头一遍的
  结果是后一遍的输入，两遍之间没有状态复用，所以每多一遍就多一次整函数扫描。
- 只认发射器自己的文本形态。将来若发射器改了某一处的行长或助记符写法
  （例如把 `STR` 写成 `STR.W`），对应规则会静默失效——所以两条规则都用**严格匹配**
  而不是前缀匹配，失效时宁可漏。
