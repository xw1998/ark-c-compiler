四条主项 `MOVREG + PUSHPOP + FRAME + MOVIMM` 合计 **+4,844 条 = 全部差值的 78.8%**。
它们不是四个独立的机会，而是**同一条模型事实的四种外形**：

1. **每个中间值在 `r0` 里出生，再由一条 `MOV` 搬到它真正要待的地方**（MOVREG 1,101）；
2. **值栈池只有 `r5`/`r7` 两槽（三值同时存活时才借 `r4`）**，池满就退化成真实
   `PUSH`/`POP`（PUSHPOP 里 471 处 pool-full + 589 处边界 pin，见 `docs/VSTACK_CFG.md` §1）；
3. **每个局部变量每次访问都走 `[r6, #o]`**（FRAME 926 条差额）——`-fopt-slotreg` 的
   「只删不增」只拿走了死写与重复读，剩下的访问是「值必须先落内存才能再取」这条规则的产物；
4. **同一常量在不同站点各自材料化一次**（MOVIMM + MOVW/MOVT）——`-fopt-litpool` 已经把
   32 位常量赶进池，但 0..255 的短常量仍按「谁需要谁写一条 `MOV`」处理。

## 3 目标模型：分配单位从文本行换到 IR 虚拟寄存器

今天的样子（`docs/RA_VSTACK.md`）：IR 里每个表达式节点**真的压一次栈**，后端按行发射，
值栈 pass（`-fopt-vstack`）在**文本上**做影子栈改名，池只有 2–3 槽，边界一律清空。
S6 系列（`-fopt-vreg` / `-fopt-slotreg`，`docs/VREG.md`）已经把「文本层改名」做到头：它
能删冗余搬运，但**决定不了「值出生在哪个寄存器」**——那在发射时就已经写死了（`r0`）。

目标模型只有一句话：**发射期就给每个 IR 值一个虚拟寄存器，分配在 IR 层完成**。

```
值 v 的一生：  def 在一个 IR 指令上 → 活跃区间 [def, last_use]
分配：        线性扫描（Poletto & Sarkar），可用寄存器 r4–r11（8 个，callee-saved）
              r0–r3 留作参数/返回值与「区间不跨越调用也不跨越分支」的短命临时
帧槽：        只有两类对象留在 [r6, #o]：spill，以及地址被取走的变量
边界：        块内分配为主；跨块（join）沿用 `docs/VSTACK_CFG.md` §3 的保守判据
```

为什么这是「换模型」而不是「再加一条 pass」：

- 今天的 FRAME 926 条差额与 MOVREG 1,101 条差额是**同一个决定**：值出生在 `r0` 且必须
  先落内存。文本层再怎么改名，也改不动「它在 `r0` 里出生」这件事。
- 反过来，只要分配器能在发射期说「这个值就住在 `r7`」，`MOV`/`STR`/`LDR` 三族的相当一部分
  **根本不会产生**，而不是产生后被删掉。这正是 `docs/BOUNDARY.md` §4 三条结构性原因的根。

已经就位的零件（不必重做）：常量池（`-fopt-litpool`）、基址复用与寻址折叠
（`-fopt-addr`）、强度削减（`-fopt-strength`）、比较直连分支与 `CBZ`、尾调用与块尾合并、
`--size-weight`。

缺的只有一件：**分配器本身**。

## 5 判据（冻结，实现前不改）

**S8a 的判据**（决定要不要做 S8b）：

- `cov ≥ 60%`（全部指令里，落在「`pmax ≤ 8` 且无 spill」函数中的比例）⇒ 继续 S8b；
- `cov < 40%` ⇒ **收档**，模型改造记为不可行，本文改记为负结果；
- `40% ≤ cov < 60%` ⇒ 只登记，不实现，并把切片改小（只对 `pmax ≤ 4` 的函数做）。

**S8b 的判据**（决定开关要不要留）：

- 26 开关口径净减 **≥ 10%（≥ 1,177 条）且字节数不增** ⇒ 落地（这是「换模型」应有的量级，
  按 §1 的四条主项 4,844 条，10% 只要求吃到其中四分之一）；
- 5%–10% ⇒ 只登记，开关保留但默认关并在 README 写明收益量级；
- **< 5% ⇒ 撤回开关**（连代码一起回退，不留在树里）——不够 5% 就说明「换模型」这个判断
  本身错了，不值得为一万行新代码换 4%。

**正确性（五条同时满足，缺一条即判失败）**：

1. 95 TU 全部编译通过，26 开关口径的指令 / 字节在本文如实更新；
2. `tests/arm_exec` 全部用例 **0 failure**（模拟器执行级对账）；
3. 既有门禁全绿：`run_peep_tests.py` / `run_addr_tests.py` / `run_vreg_tests.py` /
   `run_cmat_tests.py` / `run_litpool_tests.py` / `run_bitmask_tests.py`，加
   `stm32_build_check.py --layout both` 两块 PASS；
4. **OFF IS OFF**：开关关掉时 95 TU 产物与今天**逐字节相同**；
5. **裁切**：`ARKCC_PROFILE=STM32_MIN` 构建里开关为 0，`-fopt-ra-model` 按名拒绝（`C3900U`），
   且默认档的体积不变。

新增夹具（S8b 之前必须写好，先写期望再写实现）：

- 一个值在同一个块里被三个不同表达式消费（只有一次 def，必须只分配一次）；
- 8 个值同时存活（正好压满 r4–r11），第 9 个必须 spill 且 spill 槽可复用；
- 地址被取走的局部（`&x` 逃逸到 `memcpy`），必须留在帧里、不得寄存器化；
- `volatile` 局部（必须留在内存，且 `DMB` 配对位置不变）；
- 调用前后都在用的值（先按「保存在 callee-saved」写期望，S8c 之前不许放宽）。

## 6 反假绿对照

三条，写死：

1. **强制单寄存器**：分配器实现之后加一个编译期探针 `ARKCC_RA_FORCE_R0`，让所有值都分到
   `r0` 并按今天的规则落内存——其 95 TU 产物必须与**今天逐字节相同**。这条证明的是
   「收益来自分配」，不是「重写之后恰好少了两条指令」。
2. **与 `-fopt-vstack` 的叠加必须非负**：`ra-model` 打开后，`-fopt-vstack` 的增量不得为负
   （模型改造吃掉的正是 vstack 的地盘，若叠加反而变差，说明两者在抢同一批站点且互相打架）。
3. **不许用 `MOVREG 总数` 当收益**：删掉一条 `MOV` 很可能引入一条 `LDR`（`docs/VREG.md`
   §18.3 的 1,178 就是这类「看起来是收益」的数）。判定只看**指令总数与字节总数的双向读数**。
