# 槽级寄存器化（S2 预注册）

> 状态：**预注册，未实现**。本文先冻结「要做什么、凭什么算成功、什么情况算失败」，
> 再动手写代码。数据全部来自本仓库自己的语料实测，命令与口径写在每一节里。

## 0 这份文档回答什么

`docs/OPTIMIZER_PLAN.md` 的 P12 把 S2 写成「函数内虚拟寄存器着色」，但一直没有落成文档。
从 P7 到 P14 的十二个开关把 HAL 语料从 47,885 条压到 19,066 条之后，**剩下的余量在哪里、
用什么度量确认、做到什么程度算成功**，必须先写下来，否则下一条 pass 又会变成「再加 0.1%」。

本文回答四个问题：

1. 现在的帧访问还剩多少、都是什么形状（§1）；
2. 为什么再加文本规则没有用（§2）；
3. S2 的第一个可验证切片精确是什么、它的正确性论证是什么（§3）；
4. 判据、否证条件、裁切与回滚（§4–§6）。

## 1 现状度量

口径：`examples/ark_test` 的 95 个 TU（`Core/Src/*.c` + `Drivers/STM32F4xx_HAL_Driver/Src/*.c`），
`-target arm -S -O2 -mcpu Cortex-M4 -D STM32F401xE -D USE_HAL_DRIVER --reloc-data`，
叠加现有十二个开关（vstack / addr / strength / cbz / branch / imm / peep / cbranch / copyprop /
live / prop / deadpush）。计数只算非指示、非标签行。

| 项 | 数值 | 占比 |
| --- | --- | --- |
| 指令总数 | 19,066 | 100% |
| `LDR`（几乎全是 `LDR r0, [r6, #off]`） | 2,443 | 12.8% |
| `STR`（几乎全是 `STR r0, [r6, #off]`） | 1,148 | 6.0% |
| 帧访问合计 | 3,591 | **18.8%** |
| `MOV` | 3,888 | 20.4% |
| 其中 `MOV rD, rS` | 1,615 | |
| 其中 `MOV rD, #0` | 967 | |
| 其中 `MOV sp, rS` / `MOV rD, sp` | 302 / 215 | |
| 相邻 `MOV`-`MOV` 对 | 943 | |

机会形态（同一口径，脚本数出来）：

| 形态 | 处数 | 说明 |
| --- | --- | --- |
| 直线块内同一帧槽重复 `LDR`、中间无 `STR`/clobber | 56 | 只占 0.3% |
| 块内 `STR → LDR` 同槽往返（含跨若干行） | 203 | 距离 1:51、2:25、3:44、4:14、5:6 |
| 死帧读（目的寄存器之后从不被读） | **0** | 「删死 `LDR`」这条方向无收益，已排除 |

既有 `-fopt-regalloc`（文本级「把槽换成 r8–r11 的名字」）在**同一语料**上的实测：

| 档位 | 结果 |
| --- | --- |
| 默认（只取远槽，靠省字节付 PUSH/POP） | 19,066 → **19,066**，一个槽都没选中 |
| `-fopt-regalloc-near`（近槽也取） | 19,066 → **19,066**：`LDR −73`、`STR −58`、`MOV +131` |

`-fopt-regalloc-near` 那行是本节最重要的一句话：**访问次数确实换了形式，但指令条数一条没少**，
因为被替换的 `LDR r0,[r6,#o]` 变成了 `MOV r0, rN`，仍然是一条指令。省的是访存延迟，
不是体积。

## 2 为什么不是再来一条文本规则

把上面两组数放在一起就得到结论：

- 形状精确、能被文本规则吃掉的部分（重复读 56 + 往返 203 + 死读 0）合计上限约 **0.7%**，
  其中往返那 203 处每处最多省 1 条（且要求中间没有可写的调用与标签）；
- 剩下的 3,500 余条帧访问**每一条都在做有用的事**：它把值从这里搬到那里。它们之所以存在，
  是因为后端的每一个中间值都必须经过 `r0` 这个唯一累加器（`LDR r0,[r6,o]` → 运算 →
  `STR r0,[r6,k]`）。要让它们消失，必须让运算**直接在 r8–r11 上做**，也就是真正的操作数分配。

所以 S2 不是「再写一条规则」，而是换一个模型。§3 给的是这个模型里**第一个能被证伪的切片**。

## 3 目标模型：影子槽寄存器（slice S2a）

### 3.1 选择（谁能被提升）

沿用 `ark_regalloc_function()` 已经写好并被门禁覆盖的 taint 证明：一个槽（偏移 `o`）只有在
**整个函数里**的每一次出现都恰好是 `LDR r0, [r6, #o]` 或 `STR r0, [r6, #o]` 时才可以被提升。
任何别的形状（`LDRB`、`STRH`、`ADD rX, r6, #o`、64 位高低半、结构体字段、volatile）都让这个槽
留在内存里。这条规则的含义是：**该槽的地址没有外流，所以只有本函数的这些指令能读写它。**

### 3.2 寄存器（用哪些）

`r8–r11`。理由与既有 pass 相同：后端从不命名它们，AAPCS 把它们列为 callee-saved，
`__aeabi_*` 与用户代码都会保持。一条函数里只要有一个槽被提升，prologue/epilogue 的
`PUSH`/`POP` 就要加宽（既有 `ra_` 已经实现，含「加宽后偏移平移」与「保存块保持 8 字节对齐」
两条帧规则，`tests/run_regalloc_tests.py` 覆盖）。因此**一个函数提升多个槽时，加宽的代价只付一次**。

### 3.3 缓存状态机（与既有 regalloc 的差别）

既有 `-fopt-regalloc` 的模型是「槽的家在寄存器」：每次 `STR` 都写寄存器，每次 `LDR` 都读寄存器，
不管块内有没有别的路径。S2a 要的是同一件事的**块内版本**外加一个明确的状态：

| 状态 | 含义 | 遇到 `STR r0,[r6,#o]` | 遇到 `LDR r0,[r6,#o]` | 块结束 |
| --- | --- | --- | --- | --- |
| `clean` | 内存与寄存器一致 | `MOV rC,r0` → `dirty` | `MOV r0,rC` | 什么都不做 |
| `dirty` | 内存是旧值 | `MOV rC,r0` | `MOV r0,rC` | `STR rC,[r6,#o]` → `clean` |

块 = 相邻满足「中间没有标签」的最大行段；任何分支（`B`/`Bcc`/`BL`）都**结束**当前块，
因为从它出发的所有出口都必须看到一致的内存。`BL` 之后寄存器仍然有效（callee-saved），
所以调用本身不需要写回——只要被调用的代码拿不到该槽的地址，而这一点由 §3.1 的选择规则保证。

### 3.4 成本模型（先算再改）

对一个块、一个槽，记 `R` = 被替换的 `LDR` 数、`S` = 被替换的 `STR` 数、`F` = 需要「先填寄存器」
的次数（块内第一次访问是 `LDR` 且之后还有访问）、`W` = 写回次数（块结束时是否 `dirty`）。
替换后指令数变化 = `(F + W) − (R + S)`。**只有净减才应用**：`F + W < R + S`。

这条门槛决定了本切片的真实收益形状：它吃的是「块内一次写、多次读」与「块内多次读写同一槽」，
而不是「一次写一次读」（那种情况下 `F=1, W=1`，正好打平，不动）。

加宽的 `PUSH`/`POP` 各 +2 字节是一次性代价，按既有 regalloc 的记账：每个被提升的槽至少要
省下 2 条指令（4 字节）才值得，所以**额外要求该槽在本函数内的净减 ≥ 2 条**。

### 3.5 已知不覆盖

- 跨块（标签两侧）的活跃值：不缓存，块边界强制一致；
- 64 位、`complex`、结构体、volatile、任何地址外流的槽：不提升；
- 溢出（r8–r11 都被占用）：不启用第 5 个槽，直接放弃该函数的剩余槽（**不做 spill**）。

## 4 判据（冻结，实现前不改）

`tests/run_slotreg_tests.py`，`make test-slotreg`：

1. **OFF IS OFF**：不带旗标时，95 TU 语料逐字节相同（与当前 HEAD 对拍）；
2. **默认关**：`-O2` 不加旗标时镜像逐字节相同；
3. **只减不增**：每个 TU 的指令数 `on <= off`，语料总数严格下降；
4. **块级一致性断言**：对每个被提升的槽，在函数文本里检查「块出口处内存一致」——即每个
   `dirty` 退出的块，末尾必有一条 `STR rC,[r6,#o]`（结构性检查，不依赖运行）；
5. **语义**：`tests/arm_exec` 全语料 off/on 同值（39 用例），另加至少 3 个新夹具：
   循环里累加的槽、`if/else` 两支都写同一槽、块内有 `BL`；
6. **裁剪**：`ARKCC_FEATURE_OPT_SLOTREG`（`STM32_MIN` 0），裁剪构建以 `C3900U` 拒绝旗标，
   不带旗标仍可编译，阶段表行 `built_in=0` 且函数指针 0；
7. **对拍**：x86_64 与 riscv32 后端不受影响（本 pass 只在 ARM 文本层），`make test` 全绿。

## 5 否证条件（写死，避免自我说服）

以下任何一条成立，就把本线**收档**，不再投入：

- 语料总指令数下降 < 0.5%（即 < 95 条）；
- 出现任何一个 TU 变大（加宽 PUSH 的代价没有付清）；
- 需要引入 spill 才能超过 0.5%（说明收益来自溢出策略而不是「块内缓存」这个机制）；
- 在 `-fopt-vstack` 已开的前提下，叠加后净收益为负（§6）。

## 6 与既有 pass 的关系

S2a 与 `-fopt-vstack` 抢的是**同一批栈往返**：vstack 管「表达式求值的值栈」，S2a 管「具名局部变量」，
在 HAL 代码里两者在同一个块内交织。因此必须做一次**叠加测量**：

- 若 `vstack + slotreg` 的净收益 ≤ `vstack` 单独（即 slotreg 只是把 vstack 已经消化的部分再吃一遍），
  默认只保留 vstack（即 S5 的「二选一」）；
- 若两者叠加为正且互不重叠，才允许两个都进默认档。

这条测量在实现完成后第一轮就做，结果写回本文件与 P15。

## 7 风险与回滚

- 实现全部在 `-fopt-slotreg` 之后，默认关，`OFF IS OFF` 逐字节门禁兜底；
- 复用 `ark_regalloc_function()` 的 taint / 选寄存器 / PUSH 加宽 / 偏移平移代码，不重写帧规则；
- 一旦 §4 任一项红，第一步是关掉旗标（零代价），第二步才是回退代码；
- 本文件在实现后**只允许追加**「实测」与「判决」两节，不允许修改 §4/§5 的判据文字。

## 8 实测（2026-11-23，S2a 之前）

本文件 §1 把「十二开关之上的文本层余量」估成 **≤0.7%**（口径：帧访问占比、块内重复读 56 条、
`STR → LDR` 同槽往返 203 处、死帧读 0 条）。实现 S2a 之前先做了一次全语料形态普查，
结论是这个估计**只覆盖了一族**：

- 重复读/同槽往返确实只有 0.7% 量级；
- 但「常量二次材料化」——值栈把同一个常量先搬进暂存寄存器、再让消费者把索引折回寻址方式，
  外加暂存寄存器连写两次——在十二开关之上占 **1.77%（337 条）**，比预注册的余量大一个量级。

因此顺序调整：先做 `-fopt-cmat`（P16，已落地：19,066 → 18,729，只动 `MOV`），
**S2a 顺延到 cmat 之后**，并且 S2a 的叠加测量基线改为「十二开关 + `-fopt-cmat`」。

本文件 §4 的七条门禁与 §5 的四条否证条件**一字不改**，只是前置条件与基线改变；
P15 已加一句指向 P16。

## 9 设计修订与实测（2026-11-23，S2a 实现后）

按 §7 的规矩，本节只**追加**，§4 的七条门禁与 §5 的四条否证条件一字未改。

### 9.1 被实测推翻的部分：§3 的影子寄存器模型

§3 的模型是「`MOV rC, r0` 替代 `LDR r0, [r6, #o]`」。这个替代是 **1→1**：
`-fopt-regalloc-near` 在同一语料上的实测是 `LDR −73`、`STR −58`、`MOV +131`，
**总条数 19,066 → 19,066**，一条没少。所以按 §3 实现最多能省访存延迟，省不了体积，
与本文 §1 定的目标（缩减指令数）不一致。

**修订**：S2a 改为「**只删不增**」——不做寄存器替换、不引入 `r8`–`r11`、不改帧布局，
只在已发射文本上删掉两类**可被局部证死**的帧访问：

- **R1**：`LDR r0, [r6, #o]`，且块内已知 `r0` 已持有该槽的值 ⇒ 删除；
- **R2(a)**：`STR r0, [r6, #o]`，且该槽全函数 `reads == 0` 且**地址未外流** ⇒ 删除；
- **R2(b)**：同块内后续又有对同槽的 `STR r0`、中间无读 ⇒ 删掉前一个。

### 9.2 对 §3.1 的修订：地址外流点

§3.1 只有「该槽的每一次出现都是 `LDR r0`/`STR r0`」这一条。实测发现它不够：`ADD rX, r6, #o`
**算出一个地址**（不是访问），该地址可以流进 `memcpy`，此后这个地址之上的所有槽都可能被间接写，
而文本层枚举不出来。因此新增：一旦出现这种算地址的行，把 `off >= 该偏移` 的所有槽标成
`indirect`（新槽也继承），`indirect` 槽禁止被 R2(a) 删除。

这条修订的价格是实测出来的：不带它时 −340 条（−1.82%）有 5 个 `arm_exec` 语义 failure；
带上它之后 −64 条（−0.34%），`arm_exec` 0 failure。

### 9.3 §4 七条门禁的落点

`tests/run_slotreg_tests.py`（`make test-slotreg`）逐条覆盖 §4 的第 1、2、3、6 条
（OFF IS OFF / 默认关 / 只减不增 / 裁剪），第 4 条（块级一致性）改写成两条更强的结构性断言
——「每一条被删的行必是 `LDR`/`STR r0, [r6, #n]`」与「输出是输入的子序列」（因为本实现不插入
任何行，这两条比原判据更严），第 5 条由 7 个夹具的三臂 unicorn 同值覆盖，
外层再由 `tests/arm_exec/run_arm_exec.py --extra=-fopt-slotreg` 跑整套 41 例执行级对拍。
第 7 条（跨后端不漂移）由 `make test` 的 x86_64 / riscv32 部分覆盖——本 pass 只在 ARM 文本层。

### 9.4 实测（基线 = 十二开关 + `-fopt-cmat`，18,729 条）

| 构建 | 指令数 | 变化 |
| --- | ---: | ---: |
| 基线 | 18,729 | — |
| + `-fopt-slotreg` | **18,665** | **−64（−0.34%）** |

助记符账：`LDR 2,443 → 2,408`（−35）、`STR 1,148 → 1,119`（−29）、其余全部不动。
逐 TU：95 个无一变大，85 个逐字节相同。

### 9.5 判决：收档

按 §5 第一条否证条件（总下降 < 0.5%），实测 −64 < 95，**本条线收档**。
§6 的叠加测量因此不必再做（前缀即「vstack 已开」，本 pass 在其上仍为正 −64，
只是量级不过线）。详细论证、三个误编译的根因与「为什么代码留在仓库」见
`docs/SLOTREG.md`（中文）/ `docs/SLOTREG.en.md`（英文）。
