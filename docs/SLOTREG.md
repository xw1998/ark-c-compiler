# `-fopt-slotreg`：删掉多余的帧访问

[English](SLOTREG.en.md) | 中文

> 一句话：`-fopt-slotreg` 在函数的已发射文本上删掉两类帧访问——「`r0` 里已经装着这个槽」的
> 重载、和「永远不会被观察」的死写。它**只删行、绝不插入**，所以正确性论证不需要活跃性分析，
> 只需要「删除后语义不变」这一条。HAL 全语料上少 **64 条指令（−0.34%）**，其中
> `LDR −35`、`STR −29`，其余助记符一条不动。
>
> **判决：按 `docs/SLOT_REGISTERS.md` §5 冻结的否证线（总下降 < 0.5% 即收档），本条线收档。**
> 代码保留在默认关闭的旗标后面，理由写在 §9。

---

## 1 为什么做这个、以及和 `-fopt-regalloc` 有什么不同

`docs/SLOT_REGISTERS.md` 是这条线的预注册。它先把 S2 的影子寄存器模型（`MOV rC, r0` 替代
`LDR r0, [r6, #o]`，块内 `clean`/`dirty` 两态）写成判据，再动手。动手时的第一个测量把那个模型
否掉了：

- 既有 `-fopt-regalloc` 家族的默认档在 HAL 上**一个槽都没选中**；
- `-fopt-regalloc-near` 把 `LDR −73`、`STR −58` 换成 `MOV +131`，**总条数一条不变**。

也就是说「把 `LDR` 换成 `MOV`」是 1→1 的替换，只能省访存延迟，**省不了体积**。而用户的目标是
体积（打过 armcc/gcc 的 `-O2`）。所以本 pass 换了一条不同的路：

> **不替换，只删除。**

帧访问只在两种情况下是多余的——值已经在 `r0` 里（重载）、值再也不会被读（死写）。这两类删掉
不需要任何新寄存器、不付 `PUSH`/`POP` 加宽的代价，也就没有「加宽没付清反而变大」这个风险。

## 2 两条规则

记一个「槽」= 帧偏移 `off`（`[r6, #off]`）。规则在**块内**生效。

### 2.1 R1：删除重复重载

> `LDR r0, [r6, #off]`，且本块内已知 `r0` 已经持有该槽的值 ⇒ 删除。

「已知 `r0` 持有该槽的值」只在一条路径上成立：块内刚执行过对同一槽的 `STR r0, [r6, #off]`
（或 `LDR r0, [r6, #off]`），中间没有任何写 `r0` 的指令。

### 2.2 R2：删除死写

> `STR r0, [r6, #off]`，满足下面任一条件 ⇒ 删除：
> - **(a)** 该槽在整个函数里 `reads == 0`，且它的地址没有外流（`!indirect`）；
> - **(b)** 本块内后面还有一次对同一槽的 `STR r0`，中间没有读。

(a) 是「这个槽写进去就再没人看」，(b) 是「这一写被下一写覆盖」。

### 2.3 为什么不需要活跃性分析

R1 的删除把一条 `LDR` 拿掉，前提是**同一时刻** `r0` 里就是同一个值——这是块内局部事实。
R2(b) 的删除前提是块内后写，块只有一个入口，后写发生在每条路径上。R2(a) 的前提是
**整个函数**的读数为 0，这是全函数事实，比活跃性更强，反而更好证明——难点不在「读懂」，
在「确认不漏掉间接读」，见 §3。

## 3 安全论证：只删不增 + 函数级弃权

本 pass 的结构保证是「**输出是输入的子序列**」：每一条删除都只是把一行标记为丢弃，重建时原样
拼接其余行，**没有任何一行是新写的**。门禁直接断言这一点（`is_subsequence`）。

剩下的风险全部集中在「有没有可能读到这个槽，而文本层看不出来」。实现里有三道闸：

1. **槽的形状判据**：一个槽只有在其**每一次**出现都恰好是 `LDR r0, [r6, #off]` 或
   `STR r0, [r6, #off]` 时才能被建模。任何别的形状——`LDRB`/`STRH`、`ADD rX, r6, #off`
   （取地址）、`[r6, rX]` 寄存器索引、写回 `!`、64 位高低半、`off` 不是十进制立即数——
   都让**整个函数**弃权（`sr_scan_line` 返回 5）。
2. **地址外流点**：一旦出现 `ADD rX, r6, #off` 这种「算出一个指向帧内 ≥off 的地址」的行，
   就把所有 `off >= 该偏移` 的槽标成 `indirect`，**并且此后新建的槽也继承这个标记**。
   `indirect` 槽不允许被 R2(a) 删除——因为地址可以流进 `memcpy` 之类的调用，从文本层无法
   枚举它会写哪些槽（这正是本轮第一个误编译的原因，见 §5）。
3. **volatile**：IR 层对 `IR_PUSH_VAR` / `IR_STORE` / `IR_PUSH_ADDR` 标的 `IR_AUX_VOLATILE`
   会传到本 pass（`ark_slotreg_function(..., IrFunc *f, ...)`），被标槽一律不清状态、不删写。

**不做 spill、不占 `r8`–`r11`**：本 pass 一个寄存器都不新增，帧布局、`PUSH`/`POP`、偏移全部不动。
这让「只减不增」成为结构保证，而不是一条需要验证的成本权衡。

## 4 块边界

块在这些位置结束（状态清零；`pending` 视情况保留）：

- 标签（`.L...:` / 函数名）；
- `B` 族、`BX`、`BL`、`BLX`、`CBZ`/`CBNZ`、条件跳转、`IT`；
- `POP` / `PUSH` / `LDM*` / `STM*`；
- 写 `r0` 的任何指令，以及任何不可建模的 `r6` 引用。

`DMB`/`DSB`/`ISB`/`SEV`/`WFE`/`WFI` **不是**边界——它们不写 `r0`、不碰帧，把它们当边界
只会无谓地丢掉机会（语料上有 139 条 `DMB`）。

没有 `MOV r6, sp` 的函数（`__naked`、无帧函数）整函数弃权：没有帧就没有 `[r6, #off]` 这个前提。

## 5 本轮抓到并修掉的三个误编译

第一版（外加 R2(a) 不带 `indirect` 判定）在 HAL 语料上拿到 −340 条（−1.82%），
但 `tests/arm_exec` 从 0 个 failure 涨到 5 个。三个根因：

1. **结构体条件表达式：`c = k ? a : b`**（`struct_cond` 用例，40 ≠ 46）。
   编译器先用 `ADD r0, r6, #0` 算出 `a` / `b` 的地址，再 `BL __aeabi_memcpy` 复制。
   两次 `STR r0, [r6, #4]`（`c.y`）、两次 `STR r0, [r6, #12]` 在文本上「全函数没有任何
   `LDR r0` 读这些槽」，于是被 R2(a) 当成死写删掉——真正的读在 `memcpy` 里，文本层看不见。
   **修法**：§3 第 2 条的地址外流点。代价是 −340 → −64。
   这一条就是「宁可少删，不可错删」的具体价格：0.34% 对 1.82%，安全版本只要前者的钱。
2. **`t==3` 行（`LDR r0, [r6, #n]` 之外的帧引用）不判 `r0` 被写**（`shift64` 10 ≠ 50、
   `abi_stack_args` 1 ≠ 50）。`LDR r0, [r6, #96]` 是合法帧读但落进了「其它含 `r6, #n`」的
   分支，它把 `r0` 换成了别的槽的值，而 `valid[0]` 仍然为真 ⇒ 后面 `LDR r0, [r6, #0]`
   被 R1 误删。**修法**：任何含 `r0` 作为目的寄存器的帧引用形态，一律把全部 `valid` 清空。
3. **`STR` 分支不清其它槽的 `valid`**：`STR r0, [r6, #16]` 之后，`r0` 里是槽 16 的值，
   不能同时认作槽 0 的值。**修法**：`valid[s] = 1` 之前 `for (k) valid[k] = 0;`。

三个修完之后 `run_arm_exec.py --extra=-fopt-slotreg` 是 **0 failure（41 用例）**。
每条都加了一个门禁夹具或一条断言（§8）。

## 6 实测（HAL 全语料，95 TU，Cortex-M4，`-O2 --reloc-data`）

基线 = 0.9.1 的十二个开关 + `-fopt-cmat`（P16，18,729 条）。

| 构建 | 指令数 | 变化 |
| --- | ---: | ---: |
| 基线（十二开关 + cmat） | 18,729 | — |
| + `-fopt-slotreg` | **18,665** | **−64（−0.34%）** |

助记符账（同一批 `.s` 上逐行统计）：

| 助记符 | 基线 | + slotreg | 差 |
| --- | ---: | ---: | ---: |
| `LDR` | 2,443 | 2,408 | **−35** |
| `STR` | 1,148 | 1,119 | **−29** |
| 其余全部 | 15,138 | 15,138 | 0 |

逐 TU 结果：**95 个 TU 无一变大**，其中 **85 个 TU 逐字节相同**，其余 10 个各少 1–17 条。
这条「无一变大」是结构保证（只删不增）的实测确认，不是巧合。

## 7 实现位置

`src/backend/arm/backend_arm.c`，一整段 `#if ARKCC_FEATURE_OPT_SLOTREG`，
调度点在 `#if ARKCC_FEATURE_OPT_CMAT` **之前**——先删 store，被删 store 的喂料常量再被 cmat 的
M3 吃掉，两个 pass 在同一个构建里叠加而不是互相干扰：

| 函数 | 作用 |
| --- | --- |
| `sr_pre8` | 前缀判等（区分 `LDR`/`STR` 与 `LDRB`/`LDRSH`） |
| `sr_scan_line` | 一行分类：0 无 `r6` / 1 `LDR r0` / 2 `STR r0` / 3 其它带 `#off` 的 `r6` 引用 / 4 `MOV r6, sp` / 5 不可建模 |
| `sr_writes_r0` | 该行是否写 `r0` |
| `sr_barrier` | 是否结束块 |
| `sr_slot` | 取/建槽（新槽继承 `off >= sr_esc_lo` 的 `indirect`） |
| `ark_slotreg_function` | 整个 pass：两遍扫描（Pass1 建槽表与读计数、Pass2 逐行决定删不删）→ 重建 |

静态表：`SR_MAX_SLOTS 128`、`SR_MAX_LINES 3000`、`SrSlot{off, reads, taint, indirect}`。
`-fopt-slotreg` 默认**关闭**；`ARKCC_PROFILE_STM32_MIN` 下宏为 0，代码与静态表都不进镜像，
裁剪构建以 `C3900U` 拒绝该旗标并给出宏名。

## 8 门禁（`make test-slotreg`）

`tests/run_slotreg_tests.py`，七组：

1. **OFF IS OFF**：`-O2` 与 `-O2 -fno-opt-slotreg` 逐字节相同（1200/1200 字节）；
2. **只减不增**（逐夹具）：每一条被删的行必须是 `LDR`/`STR r0, [r6, #n]`；输出是输入的子序列；
   镜像不增长；
3. **R1 命中**：`sr_pick`（参数 spill 后立刻重载）21 → 20 条；
4. **R2 命中**：`sr_dead`（写进去没人读）9 → 7 条；
5. **反过度删除**：`sr_esc`（帧地址外流进 `memcpy`）与 `sr_vol`（volatile）**逐字节不变**；
   `sr_bl` 里没有任何 `LDR` 被跨调用折叠；
6. **答案不变**：7 个夹具 × 三臂（off / on / alone）在 unicorn 上返回 Python 期望值；
7. **裁剪构建**以 `C3900U` + 宏名拒绝该旗标，不带旗标仍可编译。

更强的一层：`tests/arm_exec/run_arm_exec.py --extra=-fopt-slotreg` 把整套执行级对拍
（函数指针、64 位、软浮点、原子、TLS、setjmp、ABI 栈参数、结构体条件表达式…41 用例）
在开启 slotreg 的构建上跑了一遍，**0 failure**。`--selfcheck` 确认这套门禁本身会红。

## 9 判决：收档

`docs/SLOT_REGISTERS.md` §5 把否证条件冻结成四条，其中第一条是：

> 语料总指令数下降 < 0.5%（即 < 95 条）。

实测 −64 < 95，**这条线按预注册收档**。这不是「做失败了」，而是预注册起了作用：
在写代码之前就把「多少算成功」钉死，实测低于线就停，不再为了凑数字去加规则。

**为什么不是继续挖**：−340 那一档已经证明「更多删除」就在那里，但它的每一条都由文本层
看不见的间接读写支撑（§5 第 1 条）。把这条线推到 1.8% 的唯一办法是让文本层「猜」`memcpy`
会写哪些槽——那正是「宁可报错，不给错答案」的反面。**这条线的真余量不在文本层**：
剩下的 3,500 余条帧访问每一条都在做有用的事，要让它们消失必须让运算直接在寄存器上做，
即真正的操作数分配（`docs/OPTIMIZER_PLAN.md` P12 的 S3），那是另一个模型，不是更多规则。

**代码为什么留在仓库里**：`-fopt-slotreg` 默认关闭，关掉时逐字节零变化（§8 第 1 组），
在 41 个执行级用例上语义不变（§8 第 6 组），在 95 个 TU 上无一变大（§6）。它是一段
**被证明安全的 −0.34%**，且是先例——`-fopt-regalloc-near` 零收益也同样随仓发布。
需要最小体积的构建可以打开它；不需要的人付零代价。

**给下一条线的启示**：文本层的形态普查必须在写代码之前做完（P16 的教训），
并且「余量」要按「删得掉」而不是「看一眼觉得多」来估——帧访问占 18.8%，但其中能被安全删掉的
只有 0.34%。

## 10 修订（2026-11-24）：夹具 `escape` / `wide` 的误编译与两处漏识别

门禁在十九开关收尾时复跑，暴露出 `escape` 夹具**答案错误**（`off=16 on=8 alone=16`）。
本轮定位并修掉两个漏识别，两者同源：**pass 只认以 `r6` 为基址的帧访问，而帧基址可以被复制到别的寄存器。**

1. **帧基址别名（真误编译）**。`sr_sum(struct srP p)` 里编译器发的是
   `MOV r5, r6` 之后 `LDR r5, [r5, r7, LSL #2]`：按值传的结构体参数被**以复制出来的基址索引访问**。
   pass 搜索的是 `"r6, "`，`MOV r5, r6` 里没有这个子串 ⇒ 归为「非帧行」，于是 #0 槽被判「全函数无读」
   ⇒ `STR r0, [r6, #0]` 被当成死写删掉 ⇒ 答案从 16 变 8。
2. **帧地址被取到寄存器（漏识别）**。`main` 里 `MOV r0, r6` 把 `a` 的地址交给 `sr_esc`，
   同样不含 `"r6, "` ⇒ 既没 `taint` 也没抬高 `sr_esc_lo` ⇒ `a` 的两个槽的 store 被删。

**修法**（`sr_count_r6` + 两条特判）：先数一行里 `r6` 这个**令牌**出现的次数。
0 次 ⇒ 非帧行；2 次以上 ⇒ 弃权（`ADD r6, r6, #4` 这类）；恰好 1 次但形态不是 `[r6, #n]`
（`MOV r5, r6`、`MOV r0, r6` 等）⇒ **整函数弃权**。`MOV r6, sp` 与收尾的 `MOV sp, r6`
明确特判为「帧指针设置/拆除」，不算别名。

**代价**：十二开关口径 14,646 → **14,583（−63 条）**，旧读数是 −64 ⇒ 弃权只吃掉 **1 条**；
`smaller TU 10 / identical 85` 不变。十九开关口径 12,345 → 12,312（−33 条）。
95 TU 0 err；`tests/arm_exec` 0 failure。

**门禁断言同时修正一处过严**：`wide` 的 `LDR r1, [r6, #20]` 不是本 pass 删的，而是
**其后第二轮 `-fopt-live`** 看到 r1 已持有该值后删的。旧断言把两个 pass 的删除混在一起判。
现在比较臂关掉 `-fopt-live`（`NC = ['-fno-opt-cmat', '-fno-opt-live']`），断言「每一行被删的都是
`LDR/STR r0, [r6, #n]`」才真正只在检验本 pass。**修断言不是放宽**：动手前先确认删行来源，
否则会把「别的 pass 合法优化」误记成「本 pass 越界」。
