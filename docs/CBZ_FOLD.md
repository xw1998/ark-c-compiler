# 零比较跳转折叠（`-fopt-cbz`）

[English](CBZ_FOLD.en.md) | 中文

> 0.9.1 的第六块优化。一句话：**`CMP rX, #0` 紧跟一条 `BEQ/BNE` 时，把两条并成
> 一条 `CBZ/CBNZ`——指令少一条，字节少四个，语义不变。**
>
> 实现位置：`src/backend/arm/backend_arm.c`，`ark_cbz_function()`
> 门禁：`tests/run_cbz_tests.py`（`make test-cbz`），外加 `tests/arm_exec` 全语料
> 开关：`-fopt-cbz` / `-fno-opt-cbz`，INI `opt-cbz=` / `cbz=`

---

## 1. 为什么做，做在哪一层

`x == 0` 在 C 里是最常见的比较：`if (!p)`、`while (n)`、`if (state)`、指针判空。
arkc 的发射器把它老老实实发成两条：

```asm
CMP  r0, #0        ; 16 位
BEQ  .L_end        ; 32 位（B<cond>.W，T3）
```

ARMv7-M 有专门为这件事准备的指令：`CBZ rX, label`（等于零则跳）与
`CBNZ rX, label`（不等于零则跳），都是 16 位，`rX` 就是被比较的那个寄存器，
`#0` 不必单独占一条。于是上面两条变成一条：

```asm
CBZ  r0, .L_end    ; 16 位
```

省下的是**一条指令和四个字节**（见 §6：本后端的条件跳转一直发 32 位 T3，
所以 `CMP`+`Bcc` 是 2+4，`CBZ` 是 2）。

介入层次与 `-fopt-vstack` / `-fopt-addr` 相同：**发射后的函数级文本重建**。
理由还是一样——IR 层要做要动 irgen/MIR 和四个后端；文本层认不出来就原样保留，
**最坏情况是漏折叠，绝不会发出错指令**。

## 2. 一条规则

在函数的汇编行上按顺序扫描，对每个 `CMP rX, #0`：

| 条件 | 判据 |
| --- | --- |
| **C1 相邻** | 下一条「非空、非元数据」的行就是 `BEQ` 或 `BNE`（中间允许 `.loc`/`.CFI` 之类的元数据行，它们不产生字节） |
| **C2 操作数** | `CMP` 的两个操作数严格是 `r0`..`r7` 与 `#0`；跳转目标是以 `.` 开头、不含空格/逗号/`[` 的**单一符号** |
| **C3 前向有界** | 该符号在**后面**有定义，且从跳转下一条到该标签之间**上界不超过 64 字节** |
| **C4 标志位已死** | 从跳转下一条开始向后扫，在遇到任何**读标志位**的指令之前先遇到**写标志位**的指令、返回、或该函数的出口 |

四条全过 ⇒ 把 `CMP` 那一行改写成 `CBZ rX, .L_x`（`BNE` 时是 `CBNZ`），
把 `BEQ/BNE` 那一行标记删除。

`r8`..`r12` 即使出现在 `CMP` 里也不折：`CBZ` 的 T1 编码里 `Rn` 是**三位字段**，
只覆盖 `r0`–`r7`。这一条在早期设计稿里写错过（写成 r0–r12），被编码表纠正。

## 3. 偏移为什么是「区间字节数 − 2」

`CBZ` 的 T1 编码是 `imm5 = offset / 2`，而 `offset` 相对的是 **PC**（= 本条指令地址 + 4）。
融合前后地址会整体平移，很容易算错，所以这里把推导写死：

设 `CMP` 在地址 `p`，跳转在 `p+2`，跳转之后到标签之间有 `R` 个字节，
标签在 `p+2+4+R = p+6+R`。

融合后 `CBZ` 在 `p`（`CMP` 那两字节被它占用），跳转那 4 字节消失，
于是标签落到 `p+2+R`，而 `CBZ` 的 PC 是 `p+4`，所以

```
offset = (p+2+R) - (p+4) = R - 2
```

**与标签原来离 `CMP` 多远无关**，只与「跳转之后到标签」的字节数有关——因为
被删掉的 `CMP` 与跳转正好在两端各挪一次，相互抵消。因此只需要量 `R`：
`R ≤ 64` ⇒ `offset ≤ 62`（T1 的上限），再加上「区间里至少一条指令」保证 `R ≥ 2`
即 `offset ≥ 0`。

## 4. 保守上界：为什么不数真实字节

文本层看不见布局（指令宽度由汇编器第一遍决定），所以 `R` 只能估：
**每条指令按 4 字节计、元数据行 0 字节、`LDR rX, =sym`（会展开成 `MOVW`+`MOVT`）
按 8 字节计**。这是上界，于是

- 上界 ≤ 64 ⇒ 真实 `R` 一定 ≤ 64 ⇒ 发出的 `CBZ` 一定在范围内；
- 上界 > 64 时可能只是低估了收益，放弃这处即可。

区间里一旦出现数据指令（`.word`/`.align`/`.skip`/`.ascii` 之类），直接放弃候选——
它们的宽度不按「一条 4 字节」算，估不出来就不猜。

宁可漏折、不可错发，这是这个 pass 的第一条设计约束。代价是短区间里全是 16 位指令时
上界比真实值大一倍，会漏掉一部分本来放得下的站点（见 §6 的 396/814）。

## 5. 标志位扫描（C4）：为什么不能只靠「编译器不会去读旧标志」

`CMP` 的唯一作用就是写标志，融合能成立的前提是**没人再读那三个标志**。
发射器本身不会去读，但这段汇编可能是：

- 内联汇编（`__asm`）——用户写什么都有可能；
- 手写 runtime helper；
- 未来某个 pass 在中间插了一条 `ADC`/`SBC` 或 `IT` 块。

所以 C4 用扫描而不是假设：

| 遇到 | 判定 |
| --- | --- |
| 写标志位的指令：`CMP/CMN/TST/TEQ`、带 `S` 后缀的 ALU（`ADDS/SUBS/ANDS/…`） | **安全**，立刻停止扫描 |
| 读标志位的指令：`ADC/SBC/RSC`、`IT`、任何带条件后缀的指令 | **不安全**，放弃 |
| 返回：`BX lr`、`BLX`、`POP {…, pc}` | **安全**（返回之后本函数不再看标志） |
| `BL` | **不安全**（保守：调用返回后标志位状态未知） |
| 无条件 `B .L_x` | **跟随**跳转目标继续扫（最多 4 跳、64 步） |
| 其它 | 继续扫；走到函数末尾仍未定 ⇒ 安全（不可能再有人读） |

「跟随 `B`」这一条不是优化而是**必需**：每个 `if` 体末尾都有一条 `B .L_end`，
最初的版本把 `B` 判为不安全，于是 HAL 语料一处都没融合。改成跟随之后
5/5 站点全中。

## 6. 实测

条数是 `.s` 里非指示、非标签的行数；字节是整个 `.o` 的大小（我们的对象格式里
文本段是原样字节，符号表很小）。

| 语料 | 纯 `-O2` | 加 `-fopt-cbz` | 变化 |
| --- | --- | --- | --- |
| STM32F4 HAL（`examples/ark_test/ark_test_all.c`，`-O2 -mcpu Cortex-M4`） | 47,885 条 | **47,491 条** | **−394 条** |
| 同上，`-fopt-vstack -fopt-addr -fopt-strength` 之上 | 32,901 条 | **32,478 条** | **−423 条** |
| 同上，对象字节（纯 `-O2`） | 115,090 B | **113,506 B** | **−1,584 B** |
| 同上，对象字节（全链） | 86,940 B | **85,240 B** | **−1,700 B** |

字节是实测值，不按条数乘 4：被删掉的那一对宽窄不一（`CMP 16 位 + B 16 位 = 4 字节` 省 2 字节，`CMP 16 位 + B 32 位 = 6 字节` 省 4 字节，两个都宽时省 6 字节），
所以平均每处略高于 4 字节。指令数那一列是可直接复核的判据。

**为什么是 394 而不是全部**：HAL 语料里「`CMP rX,#0` 紧接着 `BEQ/BNE`、目标是本地标签、
寄存器在 r0–r7」的相邻对一共 **814 处**；融合了 394 处。剩下的散在三个上界里：

- **64 字节上界**：`if` 体一大就放不下（T1 只有 ±62 字节，没有别的编码）；
- **标志位仍被读**（§5）：典型是体内有 `BL` 调用；
- 顶层 `if (x == 0) { ... }` 的标签在函数末尾，区间常常上百字节。

三者各占多少没有逐条归因，这里不给拆分数字。

## 7. 门禁说了什么

`make test-cbz`（`tests/run_cbz_tests.py`）跑两份夹具 × 五个臂：

- `short`：6 个可融合站点（含一处 `if (s == 0) s = 7;` 与一次函数调用）；
- `long`：`if` 体 20 条语句，上界 80 字节 —— **必须一处都不折**；
- 五臂：`base`（`-O2`）、`off`（`-O2 -fno-opt-cbz`）、`on`（`-O2 -fopt-cbz`）、
  `va`（`-fopt-vstack -fopt-addr`）、`all`（再加 `-fopt-cbz`）。

共 14 项，全部 ok：

1. **OFF IS OFF**：`-O2` 与 `-O2 -fno-opt-cbz` 的镜像逐字节相同（1716/1716）。
2. **CBZ 只随旗标出现**：`base=0 / on=6`。
3. **条数真的下降**：`310 → 304`。
4. **相邻对被吃掉**：`CMP #0`+`BEQ/BNE` 的相邻对数 `base=6 / on=0`。
5. **叠加仍然有效**：`va` 216 → `all` 210。
6. **pass 排在另两个之后**：`all` 臂里 `CBZ=6`（顺序反了会被 vstack/addr 改写掉）。
7. **镜像只减不增**：`base/on = 1716/1692`、`va/all = 1528/1504`。
8. **五臂同值**：`23/23/23/23/23`。
9. **超范围的体不融合**：`long` 臂 `on=0 / all=0`。
10. **超范围时什么都不改写**：条数 `357 → 357`。
11. **镜像不因超范围而变**：`1768/1768`、`1450/1450`。
12. **五臂同值（长体）**：`195 × 5`。
13. **裁切构建按名字拒绝** `-fopt-cbz`（`C3900U`，退出码 1）。
14. **裁切构建不带旗标仍能编译**（退出码 0）。

另有一遍全语料执行等价（`tests/arm_exec`）：

```
tests/arm_exec/run_arm_exec.py --arkcc ./arkcc.exe "--extra=-fopt-cbz"
```

第 3/4 项是必须的：只断言「CBZ 出现了」会漏掉「`CMP` 删了但跳转没删」这类半融合，
而半融合在汇编期不报错、在真机上表现为条件跳转永远走错分支。第 9/10 项守的是
**上界不能漏判**——一旦上界算错，发出的 `CBZ` 会被汇编器以范围错误拒绝（硬错误，
不会静默出错），但那就等于把一个默认该编译通过的程序弄坏了。

开发中真正踩到的缺陷是**重建时用了 trim 过的行**：整个函数的缩进被抹掉，
看起来像改动了五万行（条数从 47,885 掉到 13,966）。现在每行同时保存「原始文本」与
「trim 后的分析文本」，重建写原始文本，融合的那一行才被替换。

## 8. 裁切

`include/arkcc_config.h` 的 `ARKCC_FEATURE_OPT_CBZ`：`ARKCC_PROFILE_STM32_MIN` 下为 0，
宿主 / 交叉编译为 1。为 0 时 `ark_cbz_function()` 整块被预处理掉，`src/main.c` 以
`C3900U: -fopt-cbz is not compiled into this build` 拒绝该旗标（拒绝而非静默忽略）。

运行期默认**关**（`g_config.enable_opt_cbz = 0`），所以不加旗标的产物与 0.9.0 逐字节相同。

**`CBZ`/`CBNZ` 不在 `--asm-extra` 名单里**：汇编器无条件接受这两条助记符。
理由与 `ADDS`/`SUBS`/`MRS`/`MSR` 那四条约好的一样——**编译器要能汇编自己的输出**，
而 `ARKCC_FEATURE_ASM_EXTRA` 在所有剖面恒为 1，把它留在名单里只是把「无条件」写成
「有条件」。两条指令的编码仍由 `tests/asm_cases/05_pcrel.s` 逐字节对账。

## 9. pass 顺序

```
ark_vstack_function()      # 先缩短函数，删掉 PUSH/POP
ark_addr_function()        # 再看剩下的 ADD/MOV 能不能折进寻址
ark_cbz_function()         # 在最终形状上找 CMP #0 + 跳转（第一遍）
ark_regalloc_function()    # 然后在更短的指令流上做寄存器分配
...                        # peep / copyprop / live / vreg / slotreg / cmat / litpool
ark_cbz_function()         # 所有改名结束后再扫一遍（第二遍，见 §12）
ark_frame_function()       # 帧裁剪，最后
```

放在最后有两条实际理由：

- vstack/addr 会删掉 `CMP` 与跳转之间的行（`MOV`/`ADD`），先做 cbz 会看着一对「不
  相邻」的指令而放弃；反过来，cbz 折掉 `CMP` 之后 vstack 已经没有东西可删。
- `regalloc` 会把值钉到固定寄存器上，之后 `rX` 是否落在 r0–r7 反而是玄学；先做能用
  发射器当时的编号。

**没有做「四个顺序各跑一遍」的对照**，所以这里不报顺序差多少条。

这张图只有前半段是「顺序选择」；后半段那次第二遍扫描不是顺序问题，而是
「第一遍根本看不见的站点」——理由与读数见 §12。

## 10. 明确不做的三件事

| 没做 | 原因 |
| --- | --- |
| 把 `TST rX, rX` + `BEQ/BNE` 也折成 `CBZ/CBNZ` | 发射器把「零比较」一直发成 `CMP rX, #0`（实测 814 处相邻对里 `TST` 0 处），规则写出来是死代码 |
| 短条件跳转（`B<cond>` T1，16 位） | 这是**另一件事**：本后端的条件跳转恒发 32 位 T3（见 `size_pass` 的注释：避免大函数里 ±256 字节截断）。做 T1 需要布局定点迭代。它在本次融合里被顺带吃掉一部分（融合后那条 32 位跳转消失了），但没有独立的「短跳转」pass |
| `CBZ` 的 32 位 T2 形（±64 KB、任意 `r0`–`r15`） | 收益一样（省一条指令），但要多一条编码路径与一套门禁；T1 覆盖了 99% 的 `if`，先不做 |

## 11. 已知代价

区间上界按每条 4 字节估，对「一整个短 `if` 体都是 16 位指令」的站点会高估一倍，
于是本来能放下的折不掉。这是「宁可漏、不可错」的另一面，与 `-fopt-addr` 的
64 条前向扫描上限同性质。

## 12. 第二遍扫描：在最终文本上再跑一次

### 12.1 为什么第一遍不够

第一遍 `ark_cbz_function()` 排在 `vstack` / `addr` 之后、但在 `peep` / `copyprop` /
`live` / `regalloc` / `vreg` / `slotreg` / `cmat` / `litpool` **之前**。这正是 §9 想要
的位置（在尽量短的文本上动手），代价是它看不见后面那些 pass **新造出来**的
`CMP rX, #0` + `BEQ/BNE` 对：

- `cmat` 删掉喂给比较的常量物化，一条 `MOV rX, #k` 消失，`CMP` 的操作数变成裸寄存器；
- `slotreg` 删掉一次已满足的 load，`CMP` 的两侧因此变成相邻；
- `litpool` 把 `MOVW/MOVT` 对换成一条 `LDR`，分支到标签之间的字节数变短，本来超
  64 字节上界的站点落回可折范围；
- `regalloc` / `vreg` 的重命名把被比较的寄存器搬进 `r0`–`r7`——`CBZ` 的 T1 形只吃
  低寄存器，这是最直接的一条。

这四条不是猜测：语料普查里 `CMP rX, #0` + 条件跳的相邻对在第一遍之后仍有
**146 处**，而第一遍当时已经折掉了它能证的全部站点。

### 12.2 怎么做

在第二遍 `live`、第二遍 `peep`、第二遍 `addr` 之后、`frame` 帧裁剪之前，再调一次
`ark_cbz_function()`：

```c
/* Second CBZ sweep, for the same reason as the second liveness, peep
 * and addressing sweeps: ... */
if (g_config.enable_opt_cbz) ark_cbz_function(&buf, fstart);
```

同一个旗标（`-fopt-cbz`）、同一份规则集：**没有新增开关**，所以裁切表、`--asm-extra`
名单、`docs/BUILD.md` 的开关清单都不用动（仍是 23 个）。开关关掉时这段代码整块不跑，
`OFF IS OFF` 的逐字节断言不受影响。

安全性靠规则本身：区间上界算不出、或标志位在体内被读（§4、§5），这一遍与第一遍
一样放弃该站点。所以「多跑一遍」只可能多折**后来变得可证**的站点，不可能折错——这
与第二遍 liveness / peep / addr 是同一个论据。

### 12.3 读数

95 个 TU（STM32F4 HAL + 应用）、`-O2 -mcpu Cortex-M4`，口径 = 十九开关 +
`frame` / `voldmb` / `constcond`（22 个 `-fopt-` 开关）。`-fopt-volbar` 不在这个口径里：
它是语义开关，会按前端标记真补发屏障（本语料 2,848 条 `DMB SY`），不是体积优化。

| | 第二遍之前 | 第二遍之后 | 变化 |
| --- | --- | --- | --- |
| 指令条数 | 12,266 | **12,215** | **−51（−0.42%）** |
| 对象字节 | 405,514 B | **404,970 B** | **−544 B（−0.13%）** |
| 编译错误 | 0 | 0 | — |
| `DMB SY` | 1 | 1 | — |

两个读数取自同一份二进制：把第二遍那一行临时注释掉重编一次再量，所以 −51 是同构建
差分而不是跨构建比较。没有任何一个 TU 变大。

普查复核（同一构建）：`CMP #0` + 条件跳的相邻对由 **146 处**降到 **95 处**，正好是
第二遍吃掉的 51 处。剩下 95 处仍被 §4 的 64 字节上界、§5 的标志位仍被读、以及
「目标标签在函数末尾、区间上百字节」三条挡着，不是可见而没折。

> **历史读数为什么不直接比**：本节早先记的是 12,034 → 11,966（−68）。那是在修掉
> `-fopt-addr` 第二遍丢立即数偏移、`-fopt-frame` base 偏移、`-fopt-slotreg` 越界加载、
> `-fopt-vreg` 读-改-写重命名这批误编译**之前**的构建上量的（见 `docs/ADDR_FOLD.md` §12、
> `docs/FRAME_TRIM.md` §6、`docs/SLOTREG.md` §11、`docs/VREG.md` §18.6）。修复让若干站点
> 不再被错误折叠，指令数因此上浮到 12,266；两个数不是同一份代码，不能相减当收益。

`make test-cbz` 的 14 项全过（同一批断言，`base=0 / on=6`、`va 216 → all 210`、
`long` 臂一处不折、裁切构建 `C3900U`）；`tests/arm_exec` 全语料执行等价 0 failure；

## 13. 修订（2026-11-25）：与 `-fopt-cmat` / `-fopt-live` 同时开启时另外三处真缺陷

`-fopt-cbz` 自己没错，错在它把文本变成另外两个 pass 看得懂、但**看错了**的形状。
三处都是真误编译或硬错，全部已修：

### 13.1 cmat 的 M8 读集漏了 `CBZ`/`CBNZ` 的寄存器

`cm_modelled` 里没有 `CBZ`/`CBNZ`，`cm_no_reg_effect` 又把它们当「不读任何寄存器的分支」，
于是 M8（函数级活跃性）算出的块内 use 集里没有 CBZ 的操作数；同时块后继用
`cm_label_block(nb, u->ops)` 找**整串**里的标签，而 `CBZ r0, .L_x` 的目标在逗号之后，
分支边**完全缺失**。后果：`if ((a==b)&&(b==c))` 在 `-fopt-cbz -fopt-cmat` 下，
join 之前的 `MOV r0, #0` 被当死写删掉，`CBZ r0` 读到旧 `r0`，`&&` 返回 1 而不是 0。

修法（四处）：`cm_modelled` 收 `CBZ`/`CBNZ`；`cm_boundary` 保留其为块边界；
`cm_no_reg_effect` 明确「读首操作数」；后继计算新增 CBZ/CBNZ 分支，取逗号之后的目标标签。
详见 `docs/CMAT.md` §3.2。

### 13.2 live 不把 `CBZ`/`CBNZ` 当分支

见 `docs/LIVE.md` §14 第 1 条：`lv_branch_kind` 只认 `B` 开头，导致块尾与目标边都缺，
`-fopt-vreg` 提升出来的循环上界寄存器没有序言拷贝，循环拿垃圾比较（返回值 17 → 2）。

### 13.3 `CBZ r8`：live 重定向 + 汇编器掩码两处叠加

见 `docs/LIVE.md` §14 第 2、3 条。摘要：L2 会把 `CBNZ r0` 重定向到 `r8`，而 T1 只有
r0–r7，编码器又与 `&7`，于是**静默**变成 `CBNZ r0`；同时 `lv_repl_reg` 按 7 字符截断
长标签，把 `.L_HAL_RCC_OscConfig_0` 写成 `.L_HAL_R`（未定义标签）。两处都已修，
汇编器现在对 `CBZ r8` 直接报错并点名 r0–r7。
