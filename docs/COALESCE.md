# `-fopt-coalesce`：把本地拷贝重命名掉

[English](COALESCE.en.md) | 中文

> 一句话：值栈后端为满足两操作数 Thumb ALU「`Rd == Rn`」的编码要求，会把左操作数
> 先 `MOV` 进一个暂存寄存器；这条拷贝本身不产生任何值，只要把**后面用到的都是它**
> 的那段直线代码统统改名，拷贝就能整条删掉。HAL 全语料上再少
> **358 条指令（−1.93%）**，95 个 TU 无一变大。

---

## 1. 为什么做这个

在 `docs/OPERAND_ALLOC.md` 量过的家族拆解里，`MOV rD, rS` 有 **1,305 条**，其中
`MOV rD, rS` 紧跟「定义 `rS` 的指令」的有 455 处、紧跟两操作数 ALU 的有 316 处，
而「源在块内死亡、因此拷贝可以整体重命名掉」的估算上界是 **1,373 处（≈7.4%）**——
是文本层剩下所有候选里最大的一块。

它的形状非常固定：

```asm
    LDR  r5, [r6, #0]      ; a
    LDR  r7, [r6, #8]      ; b
    MOV  r0, r5            ; 左操作数先搬进 r0
    AND  r0, r7            ; r0 = a & b（16 位编码要求 Rd == Rn，所以不能写 AND r5, r7）
    LSL  r0, r0, #3        ; 消费者继续用 r0
    STR  r0, [r1]
```

`r0` 在这段里从头到尾只是 `r5` 的影子。把整段里的 `r0` 都改名成 `r5`、再删掉那条
`MOV`，得到：

```asm
    AND  r5, r7
    LSL  r5, r5, #3
    STR  r5, [r1]
```

值一样、标志一样、少一条指令，而且**没有任何一条指令变宽**——参与的寄存器全在
`r0`–`r7`，16 位编码照旧。IAR 侧对应的是 `CgRegalPhase` 里
「copy coalescing / `MovElimination`」这一层（见 `c_compiler/iar/docs/06-optimizer.md`）。

## 2. 规则

> `MOV rD, rS`（`rD`、`rS` 都是 `r0`–`r7`，互不相同，且都不是 `r6`）之后的那段直线
> 代码里，凡是出现 `rD` 的地方都改名成 `rS`；**只有**在这段代码结束时
> `rD` 不再活跃（且如果 `rD` 在这段里被重新定义过，`rS` 也不再活跃），才删掉这条拷贝。

「那段直线代码」的边界（遇到就停，绝不跨过）：

| 停下 | 原因 |
| --- | --- |
| 标签 | 改名不能跨控制流：别的路径上的 `rD` 读不到改名结果 |
| 基本块边界 / 条件分支 | 同上 |
| `IT` 块内的指令 | 条件执行，改写它的寄存器集合等于改语义 |
| 带 `!` 写回的寻址、任何寄存器列表 `{...}` | 操作数文本没有完整描述读集/写集 |
| `BL` / `BLX` | 调用**隐式**读 `r0`–`r3`、隐式写 `r0`–`r3`，文本里看不到 |

段内的三个判定：

1. **写 `rS`**：拷贝源被覆写 ⇒ 段到此为止。如果这一行同时**读** `rD`，说明后面的值
   依赖这条被删掉的拷贝，整段放弃；
2. **写 `rD`**：暂存值被带进了 `rS`（改名后这一行写的是 `rS`）。从这以后 `rD` 不再
   承载任何值，所以此后**任何**对 `rS` 的读（不是对 `rD` 的读）都会读到新值 ⇒ 整段放弃；
3. **读 `rD`**：这是改名的主要目标，记下位置。

最后：`rD` 在最后一行改写之后必须**不活跃**（否则段外还有人期待拷贝结果在 `rD` 里）；
如果段内重新定义过 `rD`，还要 `rS` 也不活跃（它的旧值已经被覆盖掉了）。

## 3. 落点与顺序

它是 `-fopt-live` 的**第五条规则**（`L5`），不是独立 pass：活跃性（`la[]` 逐指令
live-after 掩码、`bof[]` 块号、`it[]`、`kd[]`）只算一次，`-fopt-coalesce` 单独开启时
`ark_live_function()` 照样会跑（`enable_opt_live || enable_opt_coalesce`），但 L1–L4
各自带 `enable_opt_live` 门，所以只开 coalesce 时它们不生效——OFF IS OFF 因此是
逐字节保证。

流水线位置不变（`live` 之后、`regalloc` 之前）：

```
vstack → addr → cbz → peep → copyprop → live(+coalesce) → regalloc → slotreg → cmat → fix_far_offset
```

`lv_pass` 最多跑 4 轮，改名删拷贝后常常会**解锁**新的 L1/L2 机会，所以同一次编译里
后续轮次还会继续删——这正是「实测减少的条数可以多于合并次数」的原因。

## 4. 踩过的真缺陷

两处都是**先写错、再由门禁/emulator 抓出来**的：

1. **只处理「用后即死」的形状，几乎不命中**。第一版要求 `rD` 在段内最后一次被读之后
   立刻死掉，但最常见的形状是 `MOV r0, r5 / AND r0, r7 / LSL r0, r0, #3`——`rD` 在段内
   被**重新定义**。结果 95 个 TU 只少 1 条指令。修法就是 §2 的第 2 条判定。
2. **`BL` 的隐式读写**。`MOV r0, r5` 常常是在**给调用准备参数**，`BL` 从 `r0`–`r3`
   读参数、却不写任何操作数文本。改名只看操作数文本，`BL` 那行"看起来"不读 `r0`，
   于是拷贝被删、参数没了——emulator 上 `br(12,10,0)` 返回 5 而不是 9。修法：段内
   遇到 `BL`/`BLX` 一律停；并且任何一行「读或写 `rD` 但操作数文本里根本没出现 `rD`」
   都直接放弃（防的是同一类隐式寄存器）。

## 5. 实测

语料同 `docs/COMPARISON.md`：`examples/ark_test` 95 个 TU（`Core/Src` +
`Drivers/STM32F4xx_HAL_Driver/Src`），`-O2`、十五开关、`--reloc-data`。

| 口径 | 指令数 | 变化 |
| --- | --- | --- |
| 十五开关（不含 coalesce） | 18,509 | — |
| 十五开关 + `-fopt-coalesce` | 18,151 | **−358（−1.93%）** |

- 95 个 TU 中 81 个逐字节相同、14 个变小，**没有一个变大**；
- 减少量前列：`stm32f4xx_hal_dma.c` −82、`stm32f4xx_hal_flash_ex.c` −48、
  `stm32f4xx_hal_gpio.c` −38、`stm32f4xx_hal_rcc.c` −34、`stm32f4xx_ll_utils.c` −33；
- 不加旗标时 95 份汇编与改动前**逐字节相同**（OFF IS OFF）。

与 7.4% 的估算上界有差距，差距全部集中在保持保守的三条：段内写 `rS`、
段内 `BL`、结束时 `rS` 仍活跃。这些都能做，但每放开一条都要多一条「凭什么仍正确」
的论证，收益（每条几百条指令）不值得现在冒错答案的风险——**宁可少删，不给错答案**。

## 6. 门禁（`tests/run_coalesce_tests.py`，`make test-coalesce`）

| 组 | 断言 |
| --- | --- |
| 1 | **OFF IS OFF**：`-O2` 与 `-O2 -fno-opt-coalesce` 逐字节相同 |
| 2 | `merge`：夹具真的有 5 条 `MOV r0, r5` 暂存；on 臂至少删掉 3 条、总指令数不减；`AND r0, r7` 2 → 0、`AND r5, r7` 0 → 2、`ORR r5, r7` 0 → 1；`LSL r0, r0, #3` 1 → 0 且 `LSL r5, r5, #3` 0 → 1（值被带过段内重定义）；剩下 2 条不可合并的拷贝保留 |
| 3 | `selfsrc`（`MOV r0, r5` + `LSL r0, r7`，两操作数读目标）：两臂**逐字节相同** —— 反过度删除 |
| 4 | `ret`（暂存值就是返回值，`rD` 在出口活跃）：两臂**逐字节相同** |
| 5 | 四个夹具 × 三臂（off / on / on-alone）在 emulator 上返回 Python 答案（86 / 35 / 8 / 9） |
| 6 | 新增行只可能是改名的结果：每一行的助记符都在 off 臂出现过，且都提到 `rS` |
| 7 | 裁切构建（`-DARKCC_FEATURE_OPT_COALESCE=0`）按名拒绝 `-fopt-coalesce`（`C3900U`），不带该旗标仍能编译 |

夹具必须带完整开关集：暂存形状只在 `-fopt-vstack` 之后出现，活跃性来自 `-fopt-live`。

## 7. 裁切

`ARKCC_FEATURE_OPT_COALESCE`（`include/arkcc_config.h`）：

- `ARKCC_PROFILE_STM32_MIN` ⇒ `0`；
- 否则 ⇒ `ARKCC_FEATURE_OPT_LIVE`（规则骑在 `lv_pass()` 上，live 被裁掉时它也无处可挂）。

裁切构建里传 `-fopt-coalesce` 得到
`Fatal error: C3900U: -fopt-coalesce is not compiled into this build (rebuild with -DARKCC_FEATURE_OPT_COALESCE=1)`
并返回 1。因为共用 `lv_pass()`，**不开**时体积与行为零变化（无新增静态表）。

## 8. 没做（登记）

- **段内写 `rS` 之后继续**：需要「`rS` 旧值此后确实无人需要」的证明，等价于再做一次
  存活区间拆分；收益小、论证长。
- **跨分支合并**：同一拷贝在不同路径上的改名结果不同，要做 SSA 化或路径敏感分析。
- **真正的寄存器分配**：这仍然是 `docs/OPTIMIZER_PLAN.md` P12 的 S4/S5（IR 级），
  本地拷贝合并只能吃掉「已经搬过一次」的那部分开销。
