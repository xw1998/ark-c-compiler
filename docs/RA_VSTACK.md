# 值栈 → 寄存器分配（`-fopt-vstack`）

[English](RA_VSTACK.en.md) | 中文

> 0.9.1 的第四块优化。一句话：**ARM 后端的表达式求值把每个中间值都 `PUSH` 到栈上再
> `POP` 回来，这个 pass 把它们改成留在 r5/r7 里；只有真正需要「同一个值在栈上存两份」
> 或寄存器池不够用时才落内存。**
>
> 实现位置：`src/backend/arm/backend_arm.c`，`ark_vstack_function()`
> 门禁：`tests/run_vstack_tests.py`（`make test-vstack`），外加 `tests/arm_exec` 全语料
> 开关：`-fopt-vstack` / `-fno-opt-vstack`，INI `opt-vstack=` / `vstack=`

---

## 1. 为什么要做，做在哪一层

`arkc` 的 ARM 后端是**栈机式发射**：一个二元表达式从左到右求值，每算完一个子表达式就
`PUSH {r0}`，第二个子表达式算完再 `POP {r1}` / `POP {r0}` 取操作数。这套形状**天然正确**
（不用考虑寄存器冲突），代价是每个中间值两次访存。

三条可能的介入点：

| 层 | 代价 | 结论 |
| --- | --- | --- |
| IR 上做 SSA + 图着色 | 要动 irgen / irser / MIR / 四个后端 | 10k 行后端里的高风险改造，不做 |
| 发射期边发射边记值栈 | 需要重写整个 `gen_expr` 递归 | 回调结构不允许「先看后写」，不做 |
| **发射后的函数级文本重建** | 全有全无，最坏情况一个函数一个字节都不改 | **本 pass** |

选第三条的理由是**「宁可报错，不给错答案」**：识别不了就整函数原样输出，正确性由
`before/after memcmp` 之外的既有测试直接保证。它与仓库里既有的 `ark_regalloc_function()`
是同一范式（逐函数、bail-out、可门禁）。

## 2. 影子值栈

pass 在函数的汇编行上做一遍扫描，维护一个**影子值栈**：

```
skind[depth]  = 0 表示这个值在内存栈上（真的 PUSH 过），1 表示在寄存器池里
spool[depth]  = 池槽号（skind==1 时有效）
pend[r]       = 寄存器 r 的逻辑值现在住在哪个池槽（-1 = 不在池里）
pref[p]       = 池槽 p 的引用计数（栈条目 + pend 映射都算一次）
pbusy[p]      = 池槽 p 是否被占用（派生量，便于找空槽）
```

关键点：`pend[r] >= 0` 时**寄存器 r 本身可能根本没有那个值**——`POP {r0}` 从一个寄存器
槽弹出来时，pass 只是记下「r0 的语义值就是池槽 p」，一条指令都不发。于是**后面任何用到
r0 的地方都必须能被改写**，这正是这个 pass 全部难点的来源。

## 3. 寄存器池为什么只有 r5/r7

| 候选 | 不用它的原因 |
| --- | --- |
| r0–r3 | caller-saved；`BL` 之后值就没了，池化的收益立刻变成 bug |
| r4 | 原本不用，因为它会让 `sp` 在函数中途变成非 8 字节对齐（AAPCS 要求），浮点/`ldrd` 都会踩；现在**有条件**地拿来当第三个槽，见 §3.1 |
| r5、r7 | prologue 已经 `PUSH {r5, r6, r7, lr}` 保存 ⇒ **零帧变化**；callee-saved ⇒ 跨 `BL` 有效 |
| r8–r11 | 同上能存，但高寄存器在这套编码里只能走 32 位形，指令变大，与 P6 的 size 权重冲突 |

函数体里**原本就用到了** r5 或 r7 时，survey 阶段把该寄存器从池里剔除（宁可少优化，不改
既有语义）。

### 3.1 r4 作为第三个槽（有条件）

两个槽装不下三个同时存活的值时，第三个值只能退回真 `PUSH`。r4 是 callee-saved、这套代码
生成器**从不用它**（`ark_regalloc_function()` 只用 r8 往上），所以它可以当第三个槽——前提
是把代价付清楚：

- **门槛**：survey 阶段用影子深度模拟算出「同一个节拍上最多有几个值压在机器栈上」
  （`sdmax`，遇 `BL` 归零，因为调用会吃掉参数 push）。只有 `sdmax >= 3` 才动用 r4：
  深度永远到不了三的函数多一个被保存的寄存器纯亏，一个指令都省不下来。引入跨界之前的一次
  HAL 统计里，203 个可改写函数只有 59 个过线，剩下 63 个「够深」的函数省下的指令条数正好
  是 0 —— 门槛不是保守估计，是实测出来的（跨界后哪些函数能进 pass 本身变了，但这组数字
  要说明的是「门槛该不该有」，与后来的总数不互相引用）。
- **帧必须跟着涨一个字**：`PUSH {r5, r6, r7, lr}` 是 16 字节，加 r4 是 20 字节，`sp` 就
  ≡4 (mod 8)，AAPCS 的 8 字节对齐当场破掉；所以 `SUB sp, sp, #N` 与 `ADD sp, sp, #N`
  必须同改 `N+4`（`N` 由代码生成器保证是 8 的倍数，`frame % 8 == 0` 是断言之一）。
- **全有或全无**：prologue / `SUB` / `ADD` / epilogue 四行先各自生成好字符串，四次内存分配
  都成功才一次性替换；任一步失败就整条路放弃，绝不留下「push 了 r4 但帧没涨」的半成品。
- **只认唯一形状**：扫描必须找到唯一一条 `PUSH {r5, r6, r7, lr}`、唯一一对
  `SUB sp, sp, #N` / `ADD sp, sp, #N`（`N` 相同）、唯一一条 `POP {r5, r6, r7, pc}`，
  且原函数体里没有 r4。大帧被拆成多段 `SUB`/`ADD` 的函数（`nsub != 1 || nadd != 1`）
  自然被排除。

### 3.2 没有帧的函数（`frame == 0`）

无参数、无局部变量的函数，代码生成器根本不分配帧：序言是 `PUSH {r5, r6, r7, lr}` 紧跟
`MOV r6, sp`（没有 `SUB sp`），收尾是 `MOV sp, r6` 跟 `POP {r5, r6, r7, pc}`。0.9.1 最早
的 r4 实现拿不到这类函数——整条路的落点是「把 `SUB sp, sp, #N` 改成 `#N+4`」，而它没有
`SUB`。引入跨界之前的一次 HAL 统计里，203 个可改写函数有 81 个是零帧函数，因此这一块
补上后，过线的函数多出 28 个（同上，这组数字只用于说明零帧路径的必要性）。

零帧路径只换三处：`PUSH`/`POP` 改成五寄存器，再加**一条** `SUB sp, sp, #4`。

- **不加 `ADD`**：收尾的 `MOV sp, r6` 本来就把 sp 恢复成「PUSH 之后」的值，插入的 4 字节
  被它直接丢弃。加了 `ADD` 反而会在 `MOV sp, r6` 之后把 sp 再抬 4 字节。
- **`SUB` 必须排在 `MOV r6, sp` 之后**：r6 必须等于 PUSH 之后的 sp，否则收尾
  `MOV sp, r6` 会让 sp 停在比入口低 4 字节处，`POP` 之后每次调用都从调用者栈上漏掉一个
  字。`VsLine::after` 字段就是为「在指定行之后再发一行」准备的。
- **r6 不再被当基址**：零帧函数没有局部变量，也就没有 `[r6, #off]`，所以把 sp 变成
  4 (mod 8) 不改变任何寻址。防御性检查：函数体（`MOV r6, sp` 之后到收尾 `POP` 之前）只要
  还提到 r6（收尾那条 `MOV sp, r6` 除外）就整条路放弃。

## 4. 四条改写规则

| 原序列 | 改写 | 条件 |
| --- | --- | --- |
| `PUSH {rN}`，池里有空槽 | 上一条生产者指令的**目的寄存器改成池寄存器**，或者补一条 `MOV p, rN` | 生产者只写目的（`wmask[0] && !rmask[0]`）、`last_dest == rN`、且后续到下一次写 rN 之前没有读 rN |
| `PUSH {rN}`，`pend[rN] >= 0` | 一条都不发，只把同一个池槽再压进影子栈一次 | —— |
| `POP {rN}` 且栈顶在池里 | 一条都不发，只记 `pend[rN] = p` | —— |
| 消费者只读某操作数 | 把操作数里的 `rN` 文本替换成池寄存器名 | 该操作数 `rmask && !wmask` |

### 4.1 必须「先物化」的三种形状

只做文本替换是不够的，下面三种情况下池槽是**唯一副本**，直接替换会让消费者的结果落到
错误的寄存器：

1. **同行读写**：`LDR r0, [r0, #0]`——操作数既读又写，必须先 `MOV r0, p`。
2. **跨操作数读写**：`ADD r0, r0, r1`——r0 在一个操作数里被读、在另一个里被写，必须
   `MOV r0, p`；否则会得到 `ADD r0, r7, r7` 这种语义完全不同的指令（真实踩过：结果是
   一个 64 位乘法恒返回 0）。
3. **原地三操作数**：`ADC/SBC/MUL` 的 16 位形要求 `Rd == Rn`——`vs_is_inplace3()` 强制走
   `MOV rN, p`（真实踩过：`ADC r1, r1, r7` 汇编器直接拒绝）。

### 4.2 引用计数：为什么槽不能「用完就还」

一个池槽可以同时被**多个**地方引用：影子栈里的条目、`PUSH` 留下的 `pend` 映射、`POP`
建立的 `pend` 映射。第一处消费者用完之后如果把槽直接还给池，第二个引用就会读到别人的值。

最典型的就是 5..8 字节结构体的返回-存储序列（`POP r0; PUSH r0; PUSH r0`：同一个字要在
栈上出现两次）。`pref[p]` 每引用一次 +1，归零才真正释放；`vs_ref_add()` / `vs_ref_rel()`
是唯一入口。

## 5. 安全护栏：任一触发，只截断到那一行

- 未知助记符且含寄存器 token（`vs_form()` 返回 `VS_F_UNKNOWN`）
- 函数体里出现 `[sp` 或 `sp` 参与运算
- 多寄存器 `PUSH`/`POP`（prologue 的 `PUSH {r5,r6,r7,lr}` 与 epilogue 的 `POP {..,pc}` 除外）
- label / `B` / `Bcc` / `BX` / `BL` / `IT` 处**影子栈不空**且**不能全部物化为内存**（§5.1）
- `MOV sp, r6` 时影子栈不空

在这些边界上还活着的那几个 `pend` 映射，先由 `vs_flush_all()` 用 `MOV rN, p` 物化再清空
（`IT` 之前的条件指令写寄存器可能不执行，所以一律物化）。

**触发不等于整函数放弃**（0.9.1 起）：命中护栏只把**这一行到函数末尾**原样复制，前面已经
改写的部分保留，见 §5.2。只有「已优化前缀的形状没法按原样复原成机器栈」时才整函数 `bail`。

### 5.1 跨界：值已经在内存里就可以继续（`cross`）

上面那条「边界上栈不空就整函数原样输出」收得太紧：很多函数在 label 之前已经把值**全部**
放回机器栈（影子栈上的每一项都是 `MEM`），此时边界两边并没有任何寄存器私有约定，跨界是
安全的。于是放宽成下面这条规则——**只有满足条件才跨，不满足照旧 bail**：

1. **预扫描标 `cross`**：从函数体（`pro_end + 1`）起按 `PUSH` / `POP` 开括号计数，遇到
   label / `VS_F_CALL` / `VS_F_BRANCH` 时，把当前所有**未闭合**的 `PUSH` 行标上 `cross`。
   这是一次词法近似（可能多标，绝不会少标），多标只会让结果更保守。
2. **`cross` 行强制真发 `PUSH`**：重建到这一行时不再把值留在池寄存器里，而是发一条真正的
   `PUSH {r}`（如果该槽已有 `pend[r] >= 0`，就从那个池寄存器 push 当前值），同时 `nmem++`、
   该槽释放回池。**理由**：值还在影子栈上时物理上必须已经在内存里——多路径进入 label 时，
   机器栈必须与原码逐字一致；池寄存器是不可重建的（对方路径并不知道它们装了什么）。
3. **边界处判 `vs_all_mem()`**：到 label / `CALL` / `BRANCH` 时若 `depth != 0` 或
   `nmem != 0`，只有影子栈**全部为 `MEM`** 才 `vs_flush_all()` 后**从空寄存器状态继续
   优化下一个基本块**；不是全 `MEM` 就按 §5.2 截断。epilogue（`MOV sp, r6`）不同：把
   影子栈归零并继续优化——前提是随后的 restore 序列真的离开函数（`pop` 里含 `pc`、`BX*`、
   `MOV pc, ...` 或裸 `B`），否则按 §5.3 保持逐字。
4. **预扫描必须先判 label 再判指示行**：`.L3:` 既是标签又以 `.` 开头。pre-scan 曾经先
   按 `isdot` 跳过，于是所有 `B`/`Bcc` 的目标都没被打上 `cross`，这些值在边界前没被钉进
   内存，18 个 HAL 函数整体退化成 bail（净亏 2,659 条）。判定顺序现在与 rebuild 一侧一致。

绝大多数函数的边界本来就已经把值写回内存，只是以前没人去检查。检查后又能继续优化下一个
基本块、并在遇到无法重建的形状时保留前缀（§5.2），两者合计在 HAL 全语料上再省 1,445 条
（37,977 → 36,532，−3.8%）：30 个函数有变化，没有一个变大。

### 5.2 中途放弃时保留已优化的前缀

只放宽跨界还不够：少数函数在某个 `POP {ip}`、`PUSH` 深度越界或叫不出名字的指令上仍然
没法继续。旧行为是整函数 `bail`，把前面几百条已经改好的指令一起退回去——`HAL_DMA_IRQHandler`
因此比不改还多 262 条（重排后 prologue 多存了 r4，收益却没吃到）。现在的做法是**截断**：

- `vs_cut_shape_ok(skind, depth)`：要求影子栈形状是 `00…011…1`——所有 `MEM` 字都在池
  寄存器字**下面**。这样只要按影子栈顺序发一串 `PUSH {池寄存器}` 就能把机器栈复原成原码
  的逐字状态，不需要先弹再压。
- `vs_cut_verbatim()`：按栈序物化还在池里的影子项，再 `vs_flush_all()` 吐出剩余寄存器
  映射；之后这一行到函数末尾 verbatim 落地。
- 形状不满足（`MEM` 与池字交错）才 `bail`，回到「整函数原样输出」。

这条改动同时给出本 pass 的**不劣化保证**：一个函数只有三种结局——整体改写（更少或同样
多的指令）、改写到某一行后原样复制（前缀只会更少指令）、整函数原样输出。HAL 全语料逐函数
对比因此是「30 个函数变化、0 个函数变大」。

收尾判定因此从「`depth != 0 || nmem != 0` 就 bail」改成「`bail || (!verbf && (depth != 0 ||
  nmem != 0))`」。

`MOVW`/`MOVT` **永远不 retarget**：这两条指令是用两条指令合成一个值，只改后半个目的
寄存器会留下 `0xFFFF` 在前半个里（真实踩过：`__aeabi_lmul(-3, 7)` 返回 0）。

### 5.3 逐块恢复：`verbf` 不再是函数级永久标志

§5.1 早期的实现里，一旦在某个边界置了 `verbf`，这个函数**剩下的全部**就永久逐字复制——
包括 label 之后以及 `MOV sp, r6` 之后的收尾序列。可优化点其实还在那里：全语料 trace 下来
只有一处会置 `verbf`（`MOV sp, r6` 的 `epi-all`），而损失散布在它后面的每一条指令上
（十开关臂上单这一项就是 1,066 条 / 2,182 字节）。

现在 `verbf` 只在「尾部无法建模」时永久生效，两个地方会**恢复**：

1. **label 处**：重建循环先 `vs_parse`，若当前行是 label 且 `verbf` 尚未 stuck，就把
   `verbf` 清零、从空寄存器状态继续优化。此时 `vs_cut_verbatim()` 已经把池里的值实体
   `PUSH` 进机器栈并把映射全部 flush，机器栈在 label 处与未优化版逐字一致，所以 label
   之后从「全 MEM」接着优化与原码同义（与 `vs_all_mem()` 通路同态）。物化池项时同时把
   `skind[k]` 归零、`nmem++`——语义是「这个字已经在内存里」。
2. **真正离开函数的 epilogue 之后**：`MOV sp, <reg>` 不再直接置 `verbf`，而是
   `vs_flush_all` + 输出 + 排空到下一个 label，并在排空时检测 restore 序列是否 `leaves`
   （`pop` 里含 `pc`、`BX*`、`MOV pc, ...`、裸 `B`）。`leaves` ⇒ `depth = 0; nmem = 0;`
   ——帧已拆、body 里的值随帧丢弃、restore 弹的是 prologue 存下的字（本 pass 从没建模），
   下一个 label 之后继续优化；不 `leaves` ⇒ `verbf = 1; verbf_stuck = 1`，保持逐字。

**逐字复制期间维持影子栈**（`vs_tail_track`）：单寄存器 `PUSH` / `POP` 调整 `depth` /
`nmem`；`LDM` / `STM`、任何**写 `sp` 的指令**（按 `vs_masks` 的写掩码）、未知 form
（`vs_form() < 0`）或解析失败 ⇒ 返回 0 ⇒ `verbf_stuck = 1`，后续保持逐字（旧行为）。
这是保守的：**最坏不劣于现状**。即使影子栈估偏，后续 `POP` 撞到 `depth <= 0` 也会退回
`cut_verbatim`，属于失败安全。

## 6. 一项 peephole

重建之前先做一遍**紧邻配对**消除：`PUSH {rN}` 紧跟 `POP {rN}` 两条直接删掉。单遍扫描
（删除后不重新配对），所以它只吃「本来就相邻」的那一类。

| retpaths 夹具（多返回路径）指令 / `PUSH`/`POP` | 218 / 118 | 147 / 20 | −32% / −83% |

HAL 那一行是唯一可复现的 headline（语料在仓库里，命令见本节末）；早先引用过的
`bench_opt/bench1.c` 是历史会话的临时语料，**不在本仓库**，因此不再作为证据列出。

**镜像只减不增**是硬判据（`tests/run_vstack_tests.py` 逐夹具断言），因为 retarget 与
替换都是「用更少或同样多的字节表达同一件事」。

HAL 那一行的命令（在仓库根目录）：

```
./arkcc.exe -target arm -S -O2 -mcpu Cortex-M4 -D STM32F401xE \
  -I examples/ark_test \
  -I examples/ark_test/Drivers/STM32F4xx_HAL_Driver/Inc \
  -I examples/ark_test/Core/Inc \
  -I examples/ark_test/Drivers/CMSIS/Device/ST/STM32F4xx/Include \
  -I examples/ark_test/Drivers/CMSIS/Core/Include \
  -I include -I src -I stdlib/include -D USE_HAL_DRIVER \
  examples/ark_test/ark_test_all.c -o hal.s
# 计入条数时排除以 '.' 开头的指示/标签行与以 ':' 结尾的标签行
```

再加 `-fopt-vstack` 跑一遍，两条命令的计数差就是表中的 −26.93%；把旗标换成
`-fopt-vstack -fopt-addr` 得到 32,838，三条旗标（再加 `-fopt-strength`）齐开得到 30,824。
r4 第三槽、跨界续优化与逐块恢复都是本 pass 的内部行为、没有单独的旗标，所以 34,672 就是
`-fopt-vstack` 一条命令的直接结果。逐函数对比（同一 `name:` 切分，208 个共有函数）显示
**203 个函数有变化、没有一个变大**：最大收益 `HAL_RCC_OscConfig` 4,902 → 3,742、
`HAL_DMAEx_MultiBufferStart_IT` 9,266 → 8,445、`HAL_GPIO_Init` 1,560 → 999、
`HAL_DMA_IRQHandler` 2,518 → 2,055。r4 第三槽与零帧 `SUB sp, sp, #4` 的字节记账是这些
特性上线时量的（见 §3.1 / §3.2），本轮没有单独重测。

## 8. 门禁说了什么

`make test-vstack`（53 项）：

- **默认构建忽略这个 pass**：`-O2` 与 `-O2 -fno-opt-vstack` 的对象逐字节相同（1392/1392）。
- **真的省了**：指令数与 `PUSH`/`POP` 条数下降、镜像不变大。
- **改写过的函数里没有孤立的 PUSH/POP 对**（逐函数断言 `leftovers none`）。
- **答案一样**：arith / loop / struct / variadic 四份夹具在 off / on / on+regalloc 三种
  构建上返回值分别 73 / 85 / 12 / 24，全部一致。
- **第三槽是要来的，不是默认给的**：`deep` 夹具（三层嵌套表达式）必须出现
  `PUSH {r4, r5, r6, r7, lr}` / `POP {r4, r5, r6, r7, pc}`，且帧 `SUB sp, sp, #N` 的 `N`
  满足 `N % 8 == 4`（16+8k 变成 20+8k+4 才回到 8 字节对齐）；`shallow` 夹具（`a + b`）
  的 prologue 里**不能**出现 r4 —— 省不下指令的函数多存一个寄存器就是净亏。
- **零帧函数也要拿得到**：`frameless_deep` 夹具（无参数无局部变量、三层嵌套）必须出现
  `PUSH {r4, r5, r6, r7, lr}`、`MOV r6, sp`、`SUB sp, sp, #4`、`MOV sp, r6`、
  `POP {r4, r5, r6, r7, pc}` 五条，且**顺序就是列出来的顺序**（`SUB` 在 `MOV r6, sp` 之后，
  见 §3.2）；`frameless_shallow`（两值相加）的序言里不能出现 r4；两条臂（关/开）都返回 29。
- **跨界后继续优化**：`branch` 夹具（两个 `?:`，标签前值已在内存）在开臂必须指令数与
  `PUSH/POP` 都下降（82 → 58、46 → 8），且镜像只减不增。
- **截断保留前缀**：`callptr` 夹具（`PUSH {r}; POP {ip}; BLX ip`，`POP {ip}` 是 pass 叫不出
  名字的形状）必须（a）体内仍有 `POP {ip}`（那一行原样复制）、（b）`POP {ip}` 之前的前缀
  里没有残留的相邻 PUSH/POP 对、（c）返回 70。三条一起才能区分「保留前缀」与「整函数退回」。
- **返回之后还继续**：`retpaths` 夹具（三条返回路径）必须（a）第一个 `return` 之后的块也被
  改写（85 → 52 条）、（b）任何返回路径上都无残留 `PUSH`/`POP` 对（0 对）、（c）三条臂都
  返回 65。旧实现在第一个 `MOV sp, r6` 之后整段逐字复制，这三条一起才能区分「逐块恢复」与
  「一个 return 就收工」。
- **裁得掉**：`-DARKCC_FEATURE_OPT_VSTACK=0` 的构建以 `C3900U` 拒绝 `-fopt-vstack`；不带
  该旗标仍正常编译。

另外每次改动都跑**整个 ARM 执行语料**：
`tests/arm_exec/run_arm_exec.py --arkcc ./arkcc.exe "--extra=-fopt-vstack"` —— 39 个用例
0 失败。这一道不是可选项：本 pass 的五处语义缺陷（跨操作数读写、同行读写、只读过早释放、
`MOVW`/`MOVT` 半 retarget、同一个字被 `PUSH` 两次）**全部**是它抓到的，逐夹具的字节对比
一个都看不见。

## 9. 裁切

`include/arkcc_config.h` 的 `ARKCC_FEATURE_OPT_VSTACK`：`ARKCC_PROFILE_STM32_MIN` 下为 0，
宿主为 1。为 0 时 `ark_vstack_function()` 整块被预处理掉，`src/main.c` 以
`C3900U: -fopt-vstack is not compiled into this build` 拒绝该旗标（拒绝而不是静默忽略）。
运行期默认**关**（`g_config.enable_opt_vstack = 0`），所以不加旗标的产物与 0.9.0 逐字节相同。

## 10. 已知代价

池默认两个槽，三个值同时存活时（且函数形状允许）才把 r4 加进来当第三槽；`pend` 映射存活
期间会占着槽，槽不够就退回真 `PUSH`。因此这个 pass 是
**「组合形状友好」**的：链式求值收益最大，寄存器压力大的表达式收益趋零——但它从不产生
比原序列更差的代码，这是「镜像只减不增」判据在守的那条线。
