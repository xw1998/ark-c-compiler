# 表达式求值模型（0.9.2 预注册，S9）

[English](EXPR_MODEL.en.md) | 中文

> 一句话：**今天的发射器为每个 C 表达式的每个中间值做一次「生到 r0 → 搬进池 → 必要时落帧」
> 的三段往返；0.9.1 的二十六条文本规则把这条往返能削的都削了，剩下的差距只有改发射模型本身
> 才拿得走。**

> 状态：**S9a 只读测量完成；S9b（`-fopt-expr`）已实现并实测
> −16 条 = 0.137%，按 §6 判据撤回（见 §9）**。判据与切片见 §5/§6。

## 2 为什么文本层拿不走这 3,802 条

0.9.1 这一轮把文本层能做的都做完了，而且都有读数：

| 已关闭的族 | 结论 |
| --- | --- |
| 九族残形（重复载入/物化、`PUSH`/`POP` 空转、`STR→LDR` 往返、`MOV` 往返/链） | 167 条 = 1.42%（11,766 口径），全部按 F1 收档 |
| 地址链折叠（基址形成后没被折掉） | 189 个候选，兑现 100 条，残形归零（`RA_MODEL.md` §4.1b） |
| 帧槽寄存器化上界 | L1 133 / L2 32 / L3 718，跨调用净收益 S7a 只有 220 条 |
| 常量池（32 位常量 `MOVW`+`MOVT` → `LDR`） | 已落地 705 条 / −1,134 B |

**文本规则结构上碰不到的那一截，本轮按 26 旗标口径单独量了（`D:/tmp/bm/r0shapes.py`）**：

| 形态 | 命中 | 说明 |
| --- | ---: | --- |
| `MOV rD, r0`（`D≠r0`） | 428 | 值从 `r0` 搬出去的全部站点 |
| ├ 上一条指令刚写 `r0` | **314** | 「结果在 `r0` 里出生、再搬进目的寄存器」的直接读数（上界；含调用参数与返回值这类不可省的） |
| `MOV r0, rX` | 305 | 值被搬进 `r0` 的全部站点 |
| └ 下一条是读 `r0` 的算术/逻辑/移位 | **124** | 操作数前送（`MOV r0,rX` + `op rD,r0,rY`）的上界 |

两族各占 2.7% 与 1.1%，**按 F1 的门槛（<5% 只登记）本来就该收档**——这是文本层的判定，
不是遗漏。而它们恰恰证明了这个模型的形状：值**必须**先到 `r0`，文本层只能看着它走。

根因不是「规则写得不够好」，而是**这三段往返在发射那一刻就写死了**：栈机 IR 里每个表达式
节点都真的压一次栈，后端按行发射，`r0` 是唯一的工作寄存器，池（`r4`/`r5`/`r7`）只是把
「栈往返」换成「寄存器往返」。文本层看到的永远是已经决定好的搬运，它能删相邻的、能合并成对
的，但**决定不了「这个值出生在哪个寄存器」**。`docs/RA_MODEL.md` §3.1 已核实：`IrInst` 没有
vreg 字段，也没有 IR dump。

## 3 目标模型：语句内的三地址求值

一句话：**把一条表达式语句的 IR 缓冲起来，建成值图，按 Sethi–Ullman 次序排进寄存器，
不再有 r0 往返、不再有池搬运。**

```
今天（一个 a*b+c 的语句）              目标（同一个语句）
  POP  r1        ; 右操作数               MUL  r4, r0, r1      ; 直接算进目的寄存器
  POP  r0        ; 左操作数               ADD  r5, r4, r2
  MOV  r1, r7    ; vstack：池 -> r1       ...
  MOV  r0, r5    ; 池 -> r0
  MUL  r0, r0, r1
  MOV  r5, r0    ; 结果回池
  ...
```

- **缓冲单位**：一条语句的 IR（`IR_LINE` 之间、或遇到 `IR_LABEL`/`IR_JMP`/`IR_CALL` 为止）。
  跨语句不缓冲，因此活跃性、volatile 次序、屏障位置全都不变。
- **寄存器**：`r0–r3` 作叶与临时，`r4`/`r5`/`r7` 作语句内的目的寄存器，`r6` 保持帧基址，
  `r8–r11` 只做 callee-saved 的长生命周期值（沿用今天）。
- **溢出**：语句内寄存器用尽时，落一个 spill 槽（`[r6, #o]`），与今天同一套槽；
  语句结束时把结果写回它该在的地方（帧槽或池）。
- **不动的部分**：调用参数落位、`volatile` 顺序、`DMB`、返回与尾声、控制流结构。
  这些不是「求值」的一部分，缓冲器遇到它们就 flush。

## 4 上界：即使全做成也到不了 1.0×

- 3,802 条超出量全吃掉 ⇒ **7,864 条 = 1.40×**；
- 再把算术差额（+470，地址重算）与访存差额（+534）里属于「每次重算地址」的部分吃掉，
  大约再 500–700 条 ⇒ **7,200 条左右 = 1.28×**；
- 要真的到 5,619，四类里每一类都必须削到接近 armcc 的水平，也就是**发射模型整体换成
  寄存器机**（表达式 + 分配 + 寻址 + 分支四处同时换），不是一条切片能完成的。

结论写死：**S9 是让「2.08× 变成 1.28×–1.40×」的一步，不是「打过 armcc」的一步。**
「打过 armcc」要么按四块模型一起换（一个新项目），要么接受文本层+局部模型改造的天花板。

1. **强制走旧路**：编译期探针 `ARKCC_EXPR_FORCE_LEGACY` 让缓冲器每条语句都退回今天的
   逐行发射 ⇒ 产物必须与今天**逐字节相同**。这条证明收益来自调度，不是「重写之后碰巧少两条」。

- §1 的 4,606 条值运输里，**能归到语句内算术的部分在这份语料上接近零**；
- §4 的 1.40×/1.28× 上界**不能**靠这一层兑现——差值在别处。

## 10 跨块值传递（S10 预注册，2026-11-25）

§9 判词把下一步指向这里，而 §9 的 641 条是**混着两件事**的粗账。逐函数做栈 LIFO 模拟
（`D:/tmp/bm/stacksim.py`，只读）之后，账目是：

| 形态 | 条数 | 占比 | 能不能拿 |
| --- | ---: | ---: | --- |
| `PUSH {r0}` 到函数收尾都没被弹出（死存） | **355** | 3.0% | 删掉即可，**不需要补任何指令** |
| 活对，`POP {r0}`（臂上已经在 r0） | 96 | — | push+pop 两条都消，净省 2 |
| 活对，`POP {r1}`/`{r2}`/`{r3}` | 44 | — | pop 换成臂尾一条 `MOV`，净省 1 |

上界：**355 + 96×2 + 44 = 591 条 = 5.1%** ⇒ 11,666 → 11,075 = **1.97×**。

**为什么死存会存在**：发射器把「本臂算出的值」压进机器栈等汇合点读，而有的汇合点根本不读
（外层表达式已经用别的方式拿到值），于是这条 `PUSH` 一直留到 `MOV sp, r6` 被整帧丢掉。
全语料产物里**没有任何 `[sp, #n]` 访存**（armcc 有 46 条），所以「没被 POP 读回」= 「没人读」，
这个等价关系在 0.9.1 的输出上是可判的。

**为什么不能只做窥孔**：活对那一半的 `POP` 在几十个块之外（`hal_dma_ex` 317 推只配 62 弹），
臂尾要写进哪个寄存器得先知道外层 pop 的目标 —— 这是**跨块的值活跃性**，属于 §5 的 S9c 前置。

### 10.1 切片

- **S10a 删死存**（先做，最大且最安全）：函数内栈 LIFO 模拟，删除「推入后到 `MOV sp, r6`
  之前无对应 POP、且全函数无 `[sp` 访存」的单寄存器 `PUSH {rR}`。整函数跳过条件：
  有 `sub sp`（VLA/`alloca`）、有 `setjmp`/`longjmp` 调用、有内联汇编、栈上有异常/`__svc` 帧。
- **S10b 汇合点寄存器合并**：对活对，把 `PUSH {r0}` + `B .Ljoin` 改写成臂尾
  `MOV rY, r0`（`rY == r0` 时直接删两条），join 处的 `POP {rY}` 删掉。

26 旗标、95 TU，基准 11,666 / 396,986：

- **净减 ≥ 4%（≥ 467 条）且字节不增** ⇒ 落地；
- 2%–4% ⇒ 登记，开关保留、默认关；
- **< 2% ⇒ 撤回开关（连代码回退）**。

正确性五条与 §6 相同（95 TU 全过 / `tests/arm_exec` 0 failure / 既有七套门禁 +
`tools/stm32_build_check.py --layout both` / OFF IS OFF / `ARKCC_PROFILE=STM32_MIN` 下按名拒绝）。

### 10.3 反假绿（写死）

1. **删完自检**：逐函数 `push 数 − pop 槽数` 的差必须等于基线差减去删除数（栈平衡没被破坏）；
2. **槽位回溯自检**：每条被删的 `PUSH` 记下「函数名 + 序号 + 当时的栈深度」，回放时在该函数
   全范围内断言：没有 POP 落在该深度、没有 `[sp` 访存。自检必须能**报错**（故意放一条应保留的
   `PUSH` 进去，检查必须报警）；
3. **不许把「少了几条 PUSH」当收益**：只认指令总数 + 字节总数的双向读数，且镜像字节不得变大；
4. **不许动多寄存器帧 `PUSH`/`POP`**（那是 ABI 的一部分，与本项无关）。

### 10.4 不许的写法

- 不得把 S10 说成「做完了跨块活跃性」——它只覆盖「栈往返」这一种形态；
- 不得在 VLA/`alloca`/`setjmp` 函数里试手（栈不是 LIFO 的，模拟本身不成立）；
- 不得为了凑数把 `PUSH {r0}` 换成 `STR r0, [sp, #-4]!`（字节更多，等于作弊）。

### 10.5 实测与判词：上界被证伪（2026-11-25）

实现的不是 §10.1 的「栈 LIFO 线性模拟」，而是按 CFG 判定的合并形态：**对每条
`PUSH {rX}`，若离开它的每一条路径都到达一个 `POP {rX}`，且中途没有指令写 rX，则
这一对（以及汇合点那条 POP）一起删除**。逐条账因此和 §10 的表不同：

- **§10 的 355 条死存是线性模拟的产物。** 菱形两侧各 `PUSH {r0}` 的臂，汇合点的
  `POP {r0}` 在汇编文本里排在分支之后，线性扫描走在「只看本条通路」的假设上，于是把
  这些「已经在 r0 里的值」全算成了死存。**CFG 感知后真死存只有 3 条**，S10a 几乎不产出。
- 真正拿走条数的是 S10b 的**同寄存器**情形：`POP {rX}` 的目标寄存器就是臂尾已经持有的
  那个，于是 `PUSH` 与 `POP` 两条一起消失，不需要补任何指令。
  `stm32f4xx_hal_dma_ex.c` 的 `HAL_DMAEx_MultiBufferStart_IT` 一个函数就删掉
  286 条 PUSH + 28 条 POP = **314 行**；95 TU 语料合计 **331 行**。

读数（26 旗标，95 TU，同一台机器、同一命令行）：

| 口径 | 指令 | 字节 |
| --- | ---: | ---: |
| 26 旗标基线 | 11,404 | 392,907 |
| + `-fopt-spill` | 11,073 | 388,303 |
| 差 | **−331（−2.90%）** | **−4,604（−1.17%）** |

**判词：按 §10.2 落在 2%–4% 档 ⇒ 登记，`-fopt-spill` 开关保留、默认关。**
不是落地（够不到 4%），也不是撤回（远高于 2%）。§10 的 5.1% 上界**作废**，真实可拿量
是 2.90%——这是本轮最值钱的一条纠正：上界错在把「分支两侧的活值」当成了死存。

**没有做的部分**（明确留作欠账）：`POP {r0}` → `POP {r1}` 那 44 条需要把臂尾改写为
一条 `MOV rY, r0`，净省 1 条，属于「改指令」而不是「删指令」，本轮不做。

**实现边界**（每一条都写进代码注释，并由 `tests/run_spill_tests.py` 守着）：

- 骑在 `-fopt-live` 的 CFG/活跃性机器上：`!ARKCC_FEATURE_OPT_LIVE` 或
  `ARKCC_PROFILE_STM32_MIN` 时 `ARKCC_FEATURE_OPT_SPILL` 强制 0，驱动按名 `C3900U`；

  分支目标找不到、同一汇合点两条路径栈深不一致；
- `MOV sp, rB` 视为「绝对恢复」：帧基址由直线序言唯一确定（`MOV rB, sp` 且全函数只写一次），
  这条让「帧上方深度未知」也能安全重建，是让 pass 真的跑起来的关键一层；
- **自检**：删掉的条数必须等于「配对的 PUSH 数 + 配对的 POP 数」，两类有一个为 0 就不落地；
- 门禁：`tests/run_spill_tests.py` / `make test-spill`（OFF IS OFF、只删不增、删掉的
  每一行都是 PUSH/POP、镜像不涨、两个反假绿形态逐字节不变、unicorn 四臂同值、裁剪档按名拒绝）。

### 10.6 后续实测与判词：BIC 不是分支（2026-11-25）

§10.5 落地之后仍剩 418 PUSH / 421 POP。下一刀切哪里，本轮**先做 bail 归因普查**，
而不是照 §10.5 末尾那 44 条 `POP {r0}`→`POP {r1}` 的估计直接开工。

**方法**（一过性插桩，跑完即删，不入库）：在 `ark_spill_function` 的每个 `return 0`
处打印 `SPILLBAIL <原因> np=<该函数候选单寄存器 PUSH 行数>`，函数末尾打印 `SPILLOK`；
95 TU、26 旗标。**修复前**的归因：

| 原因 | 函数数 | 候选 PUSH 行 |
| --- | ---: | ---: |
| `selfcheck`（`npair == 0`，无物可删） | 174 | 59 |
| **`tgt-missing`（分支目标找不到）** | **29** | **101** |
| `depth-disagree`（汇合点栈深不一致） | 5 | 6 |

**根因**：`tgt-missing` 的 101 行有 93 行集中在两个 TU（`stm32f4xx_hal_rcc.c` 52 行、
`stm32f4xx_hal_dma.c` 41 行），打印出来的「分支」是

```
BIC r7, r7, #0x10000
```

`lv_branch_kind()` 里那句 `if (L == 3) return 2;` 是给 `BNE/BEQ/BLT/...` 兜底的，
但它把所有「三个字母、以 `B` 开头」的助记符都当成了条件分支；`BIC`/`BFI`/`BFC` 只是
名字以 `B` 开头的数据处理指令。后果有两份：

- **spill 侧**：把 `#0x10000` 当标号去查，查不到 ⇒ 整函数 bail，该函数的所有栈往返
  分析全部丢掉（这就是「宁可少删」的代价被一个拼写判断放大）；
- **live 侧**：该块被当成「目标未知的条件分支」，`bsx = 2`（所有寄存器按被读处理）
  并且块在此结束 —— 每出现一处 `BIC` 就白丢一片活跃性精度。

**修法**：只认真正的两字母条件后缀
（`EQ NE CS HS CC LO MI PL VS VC HI LS GE LT GT LE AL`）。
`BLT/BLE/BLS` 仍然被判成分支（它们的后缀在后缀表里），`BIC/BFI/BFC` 不再。

**实测**（95 TU，同一台机器、同一命令行）：

| --- | ---: | ---: |

| 26 旗标（+`-fopt-spill`） | 11,073 / 388,303 | **11,044 / 387,872**（−29 / −431） |
| spill 自身增量 | −331 / −4,604 | −331 / −4,604（不变，仍 2.90%） |

**判词**：这是**精度修正**（改的是 `-fopt-live` 与 `-fopt-spill` 共用的
`lv_branch_kind`），不是新优化，也不是判据层面的翻转；`make test-spill` 全绿、
`test-live`/`test-option`/`test-slotreg`/`test-addr`/`test-coalesce`/`test-deadpush`/

形状**。剩下的 418 PUSH 里绝大多数是函数序言的 `PUSH {r5,r6,r7,lr}`，不属于本 pass

### 10.9 发射层最后的余量：1.01%，以及 S11/S12 的分界（2026-11-25）

§10.8 把「真正的钱」指到发射/IR 层之后，必须先把**发射层还剩多少**量清楚，否则立项没有边界。
本节用一个**跑前冻结了五条规则**的只读脚本（`D:/tmp/bm/s11_ldreuse_ub2.py`）量「同一目标
寄存器的重复装载」，并用同一口径复核 §10.8 的三条候选。

规则（写死，不留事后调参的余地）：

1. 候选是 `LDR Rd,[Rb,#imm]`（`LDRB/H/SB/SH/D` 同论，宽窄不混）；
2. 在它之前、同一函数内、**离它最近**的一条 `LDR Rd,[Rb,#imm]` 的目标也是 `Rd`（同寄存器、
   同基址、同位移），且两者之间没有任何对 `Rd` 或 `Rb` 的写；
3. 两者之间没有 `STR/STRB/STRH/STRD/STM/PUSH`（可能别名的一律按别名处理）、没有 `BL/BLX`；
4. 两者之间没有第二处 `LDR R?,[Rb,#imm]`（第二个持有者会让「删哪一条」有歧义）；
5. 跨越的每一个标签，前驱数必须为 1（多前驱时上一处的持有关系不成立）。

| 项 | 条数 | 占 11,044 |
| --- | ---: | ---: |
| 可删的重复装载 | **112** | **1.01%** |
| 其中 `stm32f4xx_hal_dma_ex.c` | 109 | — |
| 其中 `stm32f4xx_hal_pwr.c` / `stm32f4xx_hal_dma.c` | 2 / 1 | — |

**为什么 262 条重装只剩 112 条可复用**：`HAL_DMAEx_MultiBufferStart_IT` 里 `hdma->Instance`
被重装 262 次（`LDR r0,[r8,#0]` 135 + `LDR r5,[r8,#0]` 127），但链上每一层的 `MOV r0,#k`
（选中常数）恰好把持有该值的 `r0` 清掉，所以只有 `BLS/BHI` 二分骨架里的 109 处满足规则 2。
这条读数把 §10.8 第 1 条差异（「被比较值只装载一次」）**精确化**成：它不是一条窥孔，而是
「为一个跨 19 层的值挑一个不被结果常数覆盖的寄存器」——一次局部寄存器分配。推论：只在
发射层做，上界就是 112。

另两条同口径复核（都不构成新开关）：

| 候选 | 上界 | 判读 |
| --- | ---: | --- |
| 常量等差序列化（`chainub.py`，后继池字 = 前一池字 + 可编码立即数） | 109 处 | **指令条数一条不省**：`ADD Rd,Rx,#imm` 与 `LDR Rd,.Llit` 都是 1 条，省的是池字（每处 4 B，约 436 B）。按「一键一义」不单独开开关 |
| 地址经机器栈 staging（`s11c.py`） | `PUSH` 418 / `POP` 421，但「`POP` 后紧接同一寄存器的访存」只 **11** 处（0.10%） | staging 的两端普遍相隔 30 条以上指令，文本层看不见配对的另一端 |

**本节判词**：**指令条数的发射层余量合计 112 条 = 1.01%**，低于 `docs/BOUNDARY.md` F1 的 5%
门槛，按 F1 收档。**S11（发射层切片）不立项、不发开关**——与 §10.7 的四条、§10.5 的 S10、
§10.6 的饱和判词并列，本节不改动其中任何一条。

**S11 与 S12 的分界**：§10.8 解剖出的三类大头——286 条结果常数物化、262 条 `B .Ljoin`、77 条
栈 staging——**都不是局部替换**：要拿到它们必须「把 store 沉进各臂」或「换块布局」，也就是
改变「一条语句怎么发射成形」这件事本身。这超出「一键一义的小替换」的粒度，按仓库纪律属
项目级改动，登记为 **S12（IR 结构层）**；其范围与上界见 §10.8 的解剖表，判据不在本节冻结。

S12 的第一片（S12-1「同一地址的装载提升」）已经按同一手法量过上界（`D:/tmp/bm/s12_1_ub.py`）：
`LDR Rd,[Rb,#imm]` 之后三条指令内到达 `CMP Rd,Rn`、且同一 `(Rb,imm)` 在同一函数里出现两次以上
的情形共 **270 条（2.44%）**，其中 254 条在 `stm32f4xx_hal_dma_ex.c`。它比 S11-1 的 112 条大
一倍多，差别只在「允许把值搬到一个**不被结果常数覆盖**的专用寄存器」——也就是 §10.8 第 1 条
差异的原样。代价是：需要一个 ABI 允许改写的寄存器（`r4`–`r11` 里未被该函数引用的那个，
并按需扩 `PUSH/POP`），且必须拒绝「区间内有别名写、有调用、基址被改写」的全部情形。
这一片仍然是 2.44%，**低于 F1 的 5%**，所以它不能按 F1 单独立项，只能作为 S12 的第一步登记。
### 10.10 S12-1 预注册：同一地址的装载提升（`-fopt-ldhoist`）

§10.9 判定发射层余量 1.01% 之后，项目级裁定开 S12 的第一片。本节把它的规则、判据、
反假绿与裁切在**动代码之前**冻结。上界见 §10.9 末段：**270 条 = 2.44%**（`s12_1_ub.py`）。

**做法**：把「同一个 `(Rb,#imm)` 在一段区域内被反复装载」改成「装载一次进一个专用寄存器
`D`，其后所有同类装载删掉」。与 §10.9 的 S11-1 只差一条：**允许换目标寄存器**——这正是
§10.8 第 1 条差异（「被比较值只装载一次」）的原样，也是 dma_ex 里 262 次重装能救回来的原因。

**冻结规则**（实现与实测都按这七条，跑后不改）：

1. 候选是 `LDR Rd,[Rb,#imm]`（`LDRB/H/SB/SH/D` 同论，宽度不混）。
2. **专用寄存器** `D` 从 `{r4,r5,r6,r7,r8,r9,r10,r11}` 里按升序取第一个**全函数文本里一次都
   没出现**的寄存器（既不被读也不被写，含 `PUSH/POP` 列表）。取不到 ⇒ 整个函数放弃
   （具名放弃点 `ldhoist: no dedicated reg`）。
3. 函数必须有**一个**含 `lr` 的前缀 `PUSH` 且**所有**函数出口的 `POP` 都含 `pc`；`D` 加进
   每一个这样的 `PUSH`/`POP`。不满足 ⇒ 放弃（`ldhoist: prologue/epilogue shape`）。
4. 区域从一条候选装载起，向后延伸到第一次出现下列任一事件为止：对 `D` 的写、可能别名的
   `STR/STRB/STRH/STRD/STM`、`BL/BLX`、对 `Rb` 的写、前驱数 > 1 的标签。
5. 区域内符合规则 1 且 `(Rb,#imm)` 相同的装载，全部删除；其 `Rd` 在「本装载之后到下一次
   写 `Rd` 之前」的用法只能有三种形态，出现第四种就**放弃这一条**（不动整段）：
   `CMP Rd,Rn` / `CMP Rn,Rd` / `MOV Rn2,Rd`；这三种里出现 `Rd` 的位置改写成 `D`。
6. 区域里第一条候选装载改成 `LDR D,[Rb,#imm]`（不新增指令），它的用法按规则 5 改写。
7. 被删装载的 `Rd` 若在**区域外**仍被读（区域结束点之后到下一次写 `Rd` 之前），放弃这一条
   ——这一条靠「区域内 `Rd` 的每次写都清了它的值」来保守保证，不引入跨区域活跃性。

**判据**（按 §10.2 的先例按上界比例重设，不套 F1 的 5%）：

| 档 | 全语料净减（26 旗标，基线 11,044） | 处置 |
| --- | --- | --- |
| 落地 | ≥ 2.0%（≥ 221 条） | 保持默认关，登记为可用档 |
| 登记 | 1.0% – 2.0%（110–220 条） | 开关保留、默认关，判「未达立项门槛」 |
| 撤回 | < 1.0%（< 110 条） | 代码回退，只留本节读数 |

**反假绿（四条，缺一不算通过）**：

1. `ARKCC_FEATURE_OPT_LDHOIST=0` 与不传 `-fopt-ldhoist` 两种构建，对 95 TU 的 `.s` 必须与
   今天**逐字节相同**（OFF IS OFF）。
2. 一个**必须触发**的夹具：同一 `(Rb,#imm)` 在单前驱链上被装载两次，中间只有 `MOV` 到别的
   寄存器 ⇒ 必须只剩一条 `LDR`，且目标寄存器是 `D`。
3. 一个**必须不触发**的夹具：两次装载之间夹一条 `STR [Rb,#other]`（潜在别名）、或一条
   `BL`、或一个前驱数 > 1 的标签 ⇒ 两条 `LDR` 都必须原样保留。
4. `make test-arm-exec` 与 `tests/run_vreg_tests.py`、`tests/run_regalloc_tests.py` 全绿：
   `PUSH/POP` 扩了一个寄存器，任何一条寄存器恢复路径写错都会在这里现形。

**可裁切**：新增 `ARKCC_FEATURE_OPT_LDHOIST`，`ARKCC_PROFILE_STM32_MIN` 下恒为 0，
板上按名拒绝 `-fopt-ldhoist`（`C3900U`），与既有 21 个 `-fopt-*` 同一条路径。
默认关：`-fopt-ldhoist` 必须显式给出。

**不许的写法（写死）**：

1. 不许在**没有** `PUSH/POP` 可扩的函数里插新的 `PUSH/POP` 对——那会改帧与调用约定。
2. 不许用「区域外看起来没人读」这种没有活跃性支撑的推断去删装载。
3. 不许把 `D` 从 `r0`–`r3` 里取——那是调用者保存的暂存寄存器，跨 `BL` 必错。
4. 不许为了让计数好看而把「换目标寄存器但不删装载」算进收益。

`HAL_DMAEx_MultiBufferStart_IT` 是本片唯一的真实战场：

- 该函数里 `LDR r?, [r8, #0]`（`hdma->Instance`）从 **266 条降到 140 条**；
- `PUSH {r5, r6, r7, r8, lr}` → `PUSH {r4, r5, r6, r7, r8, r9, lr}`（`D = r4`，
  帧 52 字节 ⇒ 7 个寄存器 = 28 字节，28 + 52 = **80**，仍是 8 的倍数）；
- 3 个出口 `POP {r5, r6, r7, r8, pc}` 全部扩成 `POP {r4, r5, r6, r7, r8, r9, pc}`；
- 12 个锚点装载，19 层嵌套三元比较全部折叠成 `CMP r4, ...`，**没有新增任何指令**。

### 11.3 为什么 127 小于上界的 270

上界脚本（§10.9 的 `s12_1_ub.py`）把「同一个 `(Rb,#imm)` 在**同函数**里出现 ≥2 次」
都算候选，**不区分是否落在同一个区域**。而规则 4 让区域在写 `Rb`、别名存储、
调用、多前驱标签处终止——跨区域的两条装载在规则上根本不可能删。

对 `lh_on` 的输出重跑同一个上界脚本，得 **142**（其中 dma_ex 128）⇒ 上界里
**只有约一半**是「区域内重复」。剩下没吃的：

- 12 条 `LDR r0, ...` 的消费者是 `ADD` / `STR`，不是 `CMP`（规则 5 只认三形态）；
- 116 条 `LDR r5, [r8, #0]` 同样不是候选（消费者不在三形态内，或区域被别名存储截断）。

**结论：冻结规则内的候选基本吃干净了。** 127 / 142 = 89%。

### 11.4 剩余余量的唯一明确方向（登记，不改口径）

规则 5 的三形态是 `CMP Rd,Rn` / `CMP Rn,Rd` / `MOV Rn2,Rd`，**不含 `CMP Rd,#imm`**。
而 armcc 的大量比较是立即数形态（`CMP r0, #1`）。放宽这一条预计能再捞一批，
但 §10.10 写死了「跑后不改」，所以本轮**不动口径**，只把它登记为下一片 S12 的
候选（须新预注册）。

1. **OFF IS OFF**：`-O2 <passes>` 与 `-O2 <passes> -fno-opt-ldhoist` 的 `.s` 与镜像
   逐字节相同；裁剪版（`-DARKCC_FEATURE_OPT_LDHOIST=0`）在不带旗标时与完整版
   输出逐字节相同。
2. **必须触发**：两条 `[r8,#0]` 收敛成一条；落在 `r4`（全函数一次都没提过的寄存器）；
   两个 `CMP` 都改成读它；`PUSH`/每个出口 `POP` 扩张同一集合；sp 仍 8 字节对齐
   （6 个保存寄存器 + 16 字节帧 = 40）；指令数正好少 1；无悬空标号；镜像不增长。
3. **必须不触发**：别名 `STR` / `BL` / 两前驱标签夹在两条装载之间，三者与纯 C

4. **裁剪out**：`-DARKCC_FEATURE_OPT_LDHOIST=0` 的构建按名拒绝

### 11.6 一条工程事实：纯 C 造不出「必须触发」夹具

七条规则窄到 arkc 当前 codegen 下**无法从 C 构造出合格函数**。已系统排查六种形态，
全部不触发，原因各自不同：

- 指针参数被重算地址（`MOV r5, #0x20000000` / `ADD`），写 `Rb` ⇒ 区域立刻终止；
- `-fopt-vreg` 把指针提到 `r8` 后，分支体开头的 `STR [r6, #8]` 是别名存储 ⇒ 区域被砍成一格；
- 嵌套三元形状对了，但规则 7 的保守实现要求「被删装载的 `Rd` 在区域内被写过」，
  小函数里结果常量写的不是同一个寄存器 ⇒ `killed == 0` ⇒ 放弃。

所以夹具改用 `__asm volatile`——汇编器把这段文本**逐字**透传。这里有一个必须
记住的坑：文本 pass 逐字比助记符，**内联汇编必须大写**，小写的 `ldr` 会被静默跳过
（本轮第一次夹具就是因为这个「不触发」，而它看起来和真的一样）。

### 11.7 不许的读法

1. 1.15% **不是**「pass 没实现」——dma_ex 的 126 条是逐条核过折叠形态的。
2. 不许把 1.15% 与 §10.9 的 1.01% 相加当成「已消除的差距」：两者量的是不同层，
   且合起来仍是 2% 量级，改不了 +122% 的量级。
3. 「登记档」不等于「下一片一定值得开」：§11.4 那条放宽要不要做，仍然要一次
   项目级裁定（§10.9 的先例：余量低于 5% 不开新片）。
