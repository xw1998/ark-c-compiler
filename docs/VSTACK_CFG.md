## 1 现状：线性扫描 + 边界清空

`-fopt-vstack` 是发射之后的文本层 pass（`ark_vstack_function()`，见 `docs/RA_VSTACK.md`）。
它有一张影子栈记录「第 i 个值在哪个池寄存器 / 是否已经写回机器栈」，池只有 `r5`/`r7`
两槽（三值同时存活时才临时加 `r4`）。它的求解方式是**线性扫描**：一遇到 label、分支或
调用，所有还活着的值必须**真的压进内存**（pin），否则跨过这条边之后影子栈的假设不成立。

19 开关口径（95 TU，`-target arm -O2 -mcpu Cortex-M4`…）下实测：

| 项 | 处数 | 说明 |
| --- | ---: | --- |
| 真 pin（值被边界钉住） | **589** | 埋点在 pinned-PUSH 分支，`ARKCC_VSTACK_STATS` 开关，量完即撤 |
| 池位用完退化成真实 `PUSH` | **471** | 不是边界问题，是**容量**问题（池只有 2–3 槽） |
| 只被 label 钉（mask=1） | 115 | 这 115 处**全部** `edges = 2`（前驱都不是一条） |
| label + 分支（mask=3） | 366 | 分支边界之后必然紧跟一个 label，故 2 不出现在掩码里 |
| 只被调用钉（mask=4） | 5 | |
| 三者都有（mask=7） | 103 | |

按「第一道边界是什么」分：**474 处**的第一道边界是分支或调用，**115 处**是 label，
而这 115 处没有一处是单前驱 label（这就是 §18.3 便宜版收益 0 的来源）。

当前总账：**12,304 条指令 / 32,690 B**；armcc `-O2` 5,619 / 13,920 ⇒ 2.19× / 2.35×。
差值 6,685 条里 **4,303 条（64.4%）是「值运输」**（`PUSH`/`POP`/`LDR`/`STR`/`MOV` 这一类
纯粹把值搬一手的指令）。`-fopt-vstack` 一个开关就值 3,364 条（21.5%）/ 6,682 B——
它是十九个开关里最大的一笔，这解释了为什么「值栈模型」是唯一还能动的结构性杠杆。

## 2 为什么文本层已经没得吃

四条候选都在**实现之前**用只读量测量过，并且都写死了判据：

| 线 | 量到的数 | 判决 |
| --- | --- | --- |
| 便宜版（只保留单前驱 label） | **0 处** pin | 精确值不是上界，收档（§18.3） |
| 扩池到 `r8`–`r11` | 买到上界 942 条，卖掉 vreg 的 882 条（r8–r11 占最终文本 11.6%） | 净负，收档（§18.4） |
| 寄存器拷贝 1,506 条 | 块间活跃性上界 **208 条 = 1.63%** | 按 F1 收档（BOUNDARY §5.4） |
| 重复常量物化 1,198 条 | 乐观上界 **297 条 = 2.41%** | 按 F1 收档（BOUNDARY §5.3） |

四条都是「文本层能看见的余量」，四条都小于 5%。剩下能省的只有一条：**值在边界上不该
被写回内存**——而这一条不是再多写一条文本规则能解决的，它要求求解器知道每条边的另一端
是什么状态。

## 3 目标模型：函数 CFG + 基本块 + join 状态

把求解单位从「整函数的线性序列」换成「基本块的 DAG + 回边」，状态从一个线性影子栈换成
**块入口状态**：

```
State = { depth,                     // 逻辑值栈深度（逻辑值个数）
          slot[i] -> { reg | MEM },  // 第 i 个值当前在哪：池寄存器号 或 已写回机器栈
          pool[R]  -> slot index }   // 反向映射，用于处置复用
```

- **块内**沿用现有规则（引用计数、读写同操作数先物化、`MOVW`/`MOVT` 不 retarget、`ADC/SBC/MUL`
  原地形先物化…），一行不改。
- **块边界（join）**：一个值能在 label 处**不进内存**，当且仅当
  **所有前驱**在到达该 label 时对同一个值给出**同一个池寄存器、同一个 slot 下标**。
  任何一个前驱说「它在内存里」或「它在别的寄存器里」，这个值在 join 处必须落内存。
  这条是保守的，且必须是保守的——池寄存器在别的路径上不成立，写出来的代码就是错的。
- **调用边界**：`r5`/`r7` 在 AAPCS 下是 callee-saved，跨调用本来安全；当前实现把调用当
  墙是**模型选择**而不是 ABI 约束。但实测只被调用钉住的 pin 只有 **5 处**（上界 10 条），
  所以这件事单独做不划算，登记给 S7c（§4.3）。
- **容量**：保留值会占住池位。471 处 pool-full 说明池本来就紧，所以必须**同时报告**
  「保留之后 pool-full 变成多少」。这一条是 §5 判据里最容易被自己骗过去的地方：
  如果保留把 pool-full 从 471 推到 900，净收益会被吃回去一大半，而指令数仍然好看。

## 4 三个切片

### 4.1 S7a：只读影子求解（不改发射）

在同一份发射文本上**并行**跑一套 CFG 求解：建基本块、把 §3 的 `State` 迭代到不动点
（`in[B] = join(in[pred])`，块内用现有规则推进），**但不改动任何一行输出**，只报告四个数：

| 报告项 | 含义 |
| --- | --- |
| `retainable` | 现有 589 处 pin 里，在 join 处**所有前驱一致**、可以保留的处数（×2 条即上界） |
| `must_spill` | 反过来：任何路径上不一致、必须落内存的下界 |
| `poolfull_after` | 若按 S7a 的保留执行，471 处 pool-full 会变成多少 |
| `net` | `retainable × 2 − (poolfull_after − 471) × 2`，即**净**指令收益的只读估计 |

`net` 才是判据看的数。`retainable` 单独看没有意义（§18.3 的 1,178 就是只有前一半的数）。

### 4.1.1 实测（S7a 已跑完，判据 `net ≥ 300` 未达，收档）

探针是**只读**的：在 `ark_vstack_function()` 里对同一份 `VsLine` 数组并行跑一遍 CFG 求解，
不写任何一行输出；量完用 `git checkout -- src/backend/arm/backend_arm.c` 撤除，重编后
`lp19.py` 复核仍是 `12,304 insns / 32,690 B / 95 units / 0 err`，与预注册前逐字节一致。

**实现过程中先踩了一次自己的坑**：第一版只在 label 处切块。结果 `reach` 塌成个位数
（`hal_dma_ex.c` 第一大函数 10 块里只有 2 块可达），因为块**中间**的条件分支是真实边，
只按 label 切块会把整条尾巴判成不可达。改成「label 与分支终止符后都切块」后，
语料 3,061 块中 2,763 块可达（90.3%），212 个函数参与求解，`unk = 0`
（`vs_form` 不认识的指令按无操作处理，不再杀块）。这一点本身就是可复用的教训：
**在文本层做 CFG，块切分必须含分支，不能只看 label。**

全语料读数（19 开关口径，95 TU）：

| 报告项 | 实测 | 预注册基线 | 说明 |
| --- | --- | --- | --- |
| `retainable` | **591** | 589 处 pin | 几乎全部 pin 在 join 处前驱一致，可保留 |
| `must_spill` | **0** | — | 没有一个 pin 因池满而必须落内存 |
| `poolfull_after` | **952** | 471 处 pool-full | 保留把寄存器占住，pool-full 翻了一倍 |
| `net` | **220** | 判据 ≥300 | `2×591 − 2×(952−471)` |
| 交叉核对 | 248 | — | `2×(sim_r 4,203 − cur_r 4,079)` |

`retainable` 比基线 589 多 2，是因为仿真在少数被真实 pass 提前 `bail` 的函数里仍然走完；
两者之差 0.3%，不影响判决。

两条独立算法给出 220 与 248，都在 300 以下。**机制是清楚的**：保留确实把 591 处 pin
（≈全部 589）变成池寄存器值，省下 1,182 条；但寄存器跨边界不放手，后面本该池化的 push
落进空池，pool-full 从 471 涨到 952，赔回 962 条。净赚 220 条 = **1.79%**，不到 2.4% 的门槛。

分布很集中：`retainable` 的 306 条（一半以上）来自 `stm32f4xx_hal_dma_ex.c` 一个 TU，
其后 `hal_rcc.c` 123、`hal_rcc_ex.c` 36、`ll_utils.c` 28、`hal_dma.c` 26。也就是说，
即使按最乐观的读法，这条线的收益也压在三四个大函数上，不是全语料普遍形态。

**口径须知**：95 TU 里只有 **17 个** TU 产出非零读数，其余 78 个一个读数都没有。
根因本轮查清了，**不是编译器缺陷**：`examples/ark_test/Core/Inc/stm32f4xx_hal_conf.h` 只开了
7 个模块（`HAL_GPIO/EXTI/DMA/RCC/FLASH/PWR/CORTEX_MODULE_ENABLED`），其余外设驱动源文件
通篇落在 `#ifdef HAL_xxx_MODULE_ENABLED` 之外，预处理后本来就是空翻译单元，产出的 `.s` 只有
5 行（`.thumb` / `.text` / `.file` …）、`.o` 20 字节。所以「12,304 条来自约 18 个 TU」是语料
配置的结果，不是漏编译；「95 TU」是名义口径，本文所有比例的分母都按 12,304 计，不按 TU 数计。

**判决（按 §5 冻结判据）**：`net = 220 条 < 300 条` ⇒ **S7b 不开工，值栈保持线性扫描 +
边界清空**。§4.2/§4.3 保留为设计记录，不落地。这是负结果，不是「没做完」：上界（1,178 条）
与真实净收益（220 条）差 5.4 倍，差的那部分正是 §4.1 表里早就点明的 `poolfull_after` 项，
现在有实测数字了。



### 4.2 S7b：实现（新开关，默认关）

新开关 `-fopt-vstack-cfg`（配置宏 `ARKCC_FEATURE_OPT_VSTACK_CFG`，宿主 1、板端 0，
默认关），开关**关**时：`ark_vstack_function()` 与今天逐字节相同（OFF IS OFF）。
开关**开**时：vstack 内改走 CFG 求解，只有属主（owner）寄存器与 join 一致的值跨过边界，
其余仍按今天的规则物化。裁切表（`include/arkcc_config.h`）与 `src/main.c` 的按名拒绝表
（`C3900U`）同步加一行——这是每加一个开关的固定动作。

### 4.3 S7c：跨调用保留（登记，不单独开工）

把 `BL`/`BLX` 从边界里拿掉（`r5`/`r7` 是 callee-saved）。上界 **10 条**，不值得单独立项；
S7b 落地后如果结构上顺手（边界判据从「label/分支/调用」拆成「label/分支」两组掩码），
再顺带做，判据同 S7b。

## 5 判据（冻结，实现前不改）

> **S7a 判决（已执行）**：`net = 220 条`（1.79%）< 300 ⇒ 按本节第二条收档，
> 值栈模型保持线性扫描。读数与推理见 §4.1.1。

**S7a 的判据**（决定要不要做 S7b）：

- `net ≥ 300 条`（= 当前指令数的 **2.4%**）⇒ 继续 S7b；
- `net < 300 条` ⇒ **收档**，值栈模型保持线性扫描，本文改记为负结果。

**S7b 的判据**（决定开关要不要留）：

- 19 开关口径净减 **≥ 3%（≥ 370 条）且字节数不增** ⇒ 落地；
- 1%–3% ⇒ 只登记，开关保留但默认关并在 README 写明收益量级；
- **< 1% ⇒ 撤回开关**（连代码一起回退，不留在树里）。

**正确性（四条同时满足，缺一条即判失败）**：

1. 95 TU 全部编译通过，且 19 开关口径的指令 / 字节在这份文档里如实更新；
2. `tests/arm_exec` 39 用例 **0 failure**（模拟器执行级对账）；
3. 五套既有门禁全绿：`run_peep_tests.py` / `run_addr_tests.py` / `run_vreg_tests.py` /
   `run_cmat_tests.py` / `run_litpool_tests.py`，加 `stm32_build_check.py --layout both` 两块 PASS；
4. **OFF IS OFF**：开关关掉时 95 TU 产物与今天**逐字节相同**；开关打开时内建汇编器的
   编码与 GNU `as` 交叉核对（至少对新增夹具）。

新增夹具（必须覆盖，且必须在 S7b 之前写好）：

- 嵌套分支两道 join（同一个值在三条路径上各处于不同池位）；
- 循环回边（值在回边上被重新定义，join 必须落内存）；
- 调用之后仍在用的值（S7c 的形态，先按「落内存」写期望）；
- 多重前驱 label（`edges > 2`，语料里 115 处 label pin 全是 2 前驱，夹具要更狠）。

## 6 反假绿对照

一条，写死：**打开开关但每个块尾强制 flush** 的构建（编译期探针
`ARKCC_VSTACK_CFG_FORCEFLUSH`），其 95 TU 产物必须与**今天逐字节相同**。

这条对照证明的是「收益来自 join 保留这一件事」，而不是「改写了 vstack 之后恰好少了两条
指令」。没有这条对照，任何正读数都不可信——`docs/VREG.md` §18.3 已经被 `kind` 读错槽
坑过一次（乱码 `kind` 值），说明这套埋点很容易量出一个「看起来对」的数。

## 7 不许的写法（写死）

- 不得把 `retainable × 2` 当成收益上报（§18.3 的 1,178 是这个数，它不是收益）；
- 不得为了过判据放宽「所有前驱一致」这条条件（放宽就是错答案，违反「宁可报错，不给
  错答案」）；
- 不得以「armcc 的指令构成」为目标反推规则（`docs/BOUNDARY.md` §3 已写死）；
- 不得改动 §5 的七条冻结门禁与 `docs/VREG.md` 的 F1–F4 否证线；
- 不得顺手把 `-fopt-vstack` 的默认值改成开（裁切剖面不变：宿主 1、板端 0）。
