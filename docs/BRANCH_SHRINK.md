# 短分支收缩（`-fopt-branch`）

[English](BRANCH_SHRINK.en.md) | 中文

> 0.9.1 的第七块优化。一句话：**目标落在 16 位范围内的 `B` / `B<cond>` 从 4 字节缩成
> 2 字节——条数不变，字节变少，语义不变。**
>
> 实现位置：`src/backend/arm/backend_arm.c`（汇编器内部：`pass1_a` /
> `arm_decide_branches` / `pass2_a` / `emit_b16_a`）
> 门禁：`tests/run_branch_tests.py`（`make test-branch`）
> 开关：`-fopt-branch` / `-fno-opt-branch`（别名 `branch`），INI `opt-branch=` / `branch=`

---

## 1. 为什么做，做在哪一层

本后端的条件跳转与无条件跳转一直发 32 位：`B.W`（T4，±1 MB）与 `B<cond>.W`
（T3，±1 MB）。理由在 `op_size_a()` 上写得很直白——**16 位形式一旦越界会被静默截断**，
而汇编器在「量指令大小」的那一遍里还不知道标签最终落在哪里。一个循环回边被截断，
就是跳到指令中间执行，本仓库在启用 `-fopt-vstack` 之后真踩过一次（`UC_ERR_WRITE_UNMAPPED`，
pc 落在一条 `PUSH` 的第二个半字上）。

保守的代价是每条短跳多两个字节。绝大多数分支其实就在门口几行之内。所以这个 pass
做的事只有一件：**先把整个汇编文件完整测一遍（所有分支都按 4 字节），
量出每个分支的真实偏移，然后只把确实放得下的那些改成 16 位。**

它坐在**汇编器内部**，不是文本层 pass：文本层算不出标签地址，而这里已经有两遍结构。
好处是四个前端（IR 层、三个后端）都不用动，任何来源的 `B`/`B<cond>` 行都受益。

## 2. 三条规则

`pass1_a()` 在测量轮里对每条 `B` / `B<cond>` 记录三元组 `(pc, cond, 目标名)`，
同时记下每条 `.align` / `.balign` 所在位置。然后 `arm_decide_branches()` 逐条判：

| 条件 | 判据 |
| --- | --- |
| **C1 目标已定义** | `find_label_a()` 能找到该标签（外部符号留给链接器，不参与） |
| **C2 落进 16 位范围** | 无条件：`-2048 ≤ off ≤ 2046`（T2，imm11）；条件：`-256 ≤ off ≤ 254`（T1，imm8）。`off` 相对 `pc+4`，必须偶数 |
| **C3 跨度里没有 `.align`** | padding 是非线性的，收缩会改变 padding 又反过来改变偏移，可能振荡；含 `.align` 的跨度一律拒绝 |
| **C4 前向按上界算** | 前向目标再减 2（本分支自己 4→2 把目标拉近 2），其它收缩只会让跨度更短 ⇒ 这是上界，保守 |

三条全过 ⇒ `shrink = 1`，pass 2 在同一个序数位置发 2 字节形式。

**为什么只跑两遍 pass1**：决策用的是保守上界（C4），且「更多收缩 ⇒ 跨度更短」，
所以第二轮布局里原本放得下的分支只会更放得下——决策单调，不会来回翻。
第一轮测量 → 决策 → 若有任何决策变化，再跑一轮 pass1（此时按 2/4 字节真实布局，
对齐填充自动精确）→ pass2 发射。没有定点迭代。

## 3. 最大的那个坑：pass1 必须按最终宽度量

第一版实现里，第二轮 pass1 仍然把每条分支算 4 字节，而 pass 2 却发 2 字节：
标签地址没被重排，**pass 2 之后的每条指令都提前了 2 字节**，于是分支跳进指令中间
（`UC_ERR_WRITE_UNMAPPED`，`addr=0`、`pc=0x8000C2A`，落在 `__arkcc_globals_init`
入口上）。反汇编同时暴露出 `bne.n 0xc44` 应当是 `0xc36`。

修法是让 `add_branch_a()` 返回「这条分支这一轮按几字节排」，pass1 直接
`pc += add_branch_a(...) ? 2 : 4`。这条改动之后四臂执行结果全部一致。

这件事的教训是：**布局与发射必须共用同一个宽度来源**。所以发射前还有一道自检——
`emit_b16_a()` 重新算一次 `off`，越界就报 hard error（`internal layout error: shrunk
B does not fit its 16-bit range`）并输出 `0xBF00`（`NOP`），而不是把截断的偏移编出去。
宁可编译失败，也不发出错跳转。

## 4. pass 2 怎么对上号

pass 2 按**出现序数**走 `branches[]`：每遇到一条分支就取当前条目，
校验 `cond` 与目标名一致才采用它的 `shrink`；不一致（说明两遍看到的文本顺序不同）
就退回 32 位编码。这条回退是必需的保险：宁可不缩，也不能让布局与发射错位。

## 5. 实测

### 5.1 夹具（`tests/run_branch_tests.py`）

| 夹具 | 纯 `-O2` | 加 `-fopt-branch` | 说明 |
| --- | --- | --- | --- |
| `near`（循环 + 小 `if`） | 1,386 B / 160 条 | **1,368 B / 160 条** | 省 18 B（9 条），条数不变 |
| `near` 叠 `-fopt-vstack -fopt-addr` | 1,294 B | **1,276 B** | 在更短的形状上仍省 18 B |
| `far`（200 语句 `while` 体） | 6,466 B | **6,456 B** | 条件出口与回边都在 2 KB 外，**只省运行时 helper 的 10 B** |
| `vfar`（300 语句循环） | 9,366 B | **9,356 B** | 同上，省 10 B |

后两行的「只省 10 B」是**正确行为**：每个镜像尾部都会附上运行时 helper
（`__arkcc_globals_init` 的清零循环、`memcpy` 循环），其中确实有几条真正的短分支。
门禁用「一个没有任何用户分支的最小程序」量出这个基准值（实测 `save=10`），
要求 `far` / `vfar` 的节省量与之**完全相等**——多省一个字节就说明那条远跳被错误地
挤成了 16 位。

### 5.2 STM32F4 HAL 全语料

`examples/ark_test` 的 99 个翻译单元（`Core/Src` + `HAL_Driver/Src`），
`-c -O2 -mcpu Cortex-M4 --reloc-data`，5 个分开的 `-I`：

| 口径 | 纯 `-O2` | 加 `-fopt-branch` | 变化 |
| --- | --- | --- | --- |
| 成功编译的单元 | 96 | 96 | 3 个 `*_template.c` / 需外部符号的单元被跳过，两臂一致 |
| 代码段字节（对象头 len 字段求和） | 116,480 B | **113,058 B** | **−3,422 B / −2.94%** |
| 对象文件字节（含符号表） | 136,352 B | **132,930 B** | −3,422 B（符号表一字未变 ⇒ 省的全是代码） |
| 缩小的文件数 | — | **96 / 96** | 没有单元变大，最大 −1,020 B（`stm32f4xx_hal_dma_ex`） |

## 6. 门禁说了什么

`make test-branch` 跑三个夹具 × 五个臂（`base` / `off` / `on` / `va` / `all`），
外加一个参考程序与一个裁切构建，共 18 项：

1. **OFF IS OFF**：`-O2` 与 `-O2 -fno-opt-branch` 逐字节相同（1,386/1,386）。
2. **参考程序隔离出 helper 分支**：`save=10`，且是偶数（否则后两项无从比较）。
3. **`near` 条数不变**：160 → 160（宽度变化不是重写）。
4. **`near` 按整 2 字节下降**：`1,386 → 1,368`（−18）。
5. **`near` 字节下降**。
6. **`near` 叠 `-fopt-vstack -fopt-addr` 仍有收益**：`1,294 → 1,276`。
7. **镜像只减不增**。
8. **五臂同值**：`42 × 5`。
9. **`far` 远目标保持 32 位**：`save=10` 与参考值相等。
10. **`far` 叠另两个 pass 仍保持**：`3,622 → 3,612`（同样 10）。
11. **`far` 镜像不增**。
12. **`far` 五臂同值**：`132 × 5`。
13. **`vfar` 同理**：`save=10`、`va 5,198 → 5,188`。
14. **`vfar` 五臂同值**：`94 × 5`。
15. **裁切构建按名字拒绝** `-fopt-branch`（`C3900U`，退出码 1）。
16. **裁切构建不带旗标仍能编译**（退出码 0）。

第 3–8 项一起守的是「省字节但不许改语义」：只断言变小会漏掉「跳转目标算错」
（它同样会让镜像变小）；所以每个臂都要在 unicorn 上跑出 Python 算好的值——
偏移错一位就会走错分支或取到指令中间，返回值立刻不同。

开发中踩到的两个门禁设计问题，也都写在这里备查：

- **`if` 夹具不适合测「远目标」**：`if (n) { 200 条 }` 的 if 体末尾有一条跳到汇合点的
  `b.w`，偏移是 0，**缩它是对的**，于是 `save` 永远比参考值多 2。改成 `while` 循环体后
  条件出口与回边都真的在范围外，`save` 才干净地等于参考值。
- **100 条语句在 `-fopt-vstack` 下不够远**：vstack 把每条 `s += k` 从 ~27 字节压到 ~12 字节，
  100 条只剩 ~1,200 字节，回边落进 T2 范围、合法收缩。夹具因此定在 **200 条**。

## 7. 裁切

`include/arkcc_config.h` 的 `ARKCC_FEATURE_OPT_BRANCH`：`ARKCC_PROFILE_STM32_MIN` 下为 0，
宿主 / 交叉编译为 1。为 0 时 `ArmAsm` 里整块计划字段（`branches` / `align_pcs` /
`plan_branches` …）连同 `pass1`/`pass2` 的调用点都被预处理掉——**没有字段、没有代码、
没有体积变化**；`src/main.c` 以 `C3900U: -fopt-branch is not compiled into this build`
拒绝该旗标（拒绝而非静默忽略）。

运行期默认**关**（`g_config.enable_opt_branch = 0`），所以不加旗标的产物与 0.9.0 逐字节相同。

## 8. 与其它 pass 的关系

这个 pass 在汇编器内部，**排在所有文本层 pass 之后**：它看到的是
`vstack` / `addr` / `strength` / `cbz` 改完之后的最终指令流，所以

- 前面几个 pass 把函数改短，本来在界外的分支可能落进范围 ⇒ 收益是叠加的
  （夹具 `near` 在 `va` 之上仍省 18 B，HAL 全链同理）；
- 反过来说，它不会给前面几个 pass 制造新的机会（宽度变了但指令数没变）。

与 `-fopt-cbz` 也不冲突：cbz 会**删掉**一条条件跳转，删掉之后序数表自然少一项，
两条 pass 都只在自己的那一层动手。

## 9. 已知代价与没做的部分

| 没做 | 原因 |
| --- | --- |
| 跨 `.align` 的分支 | padding 非线性，可能振荡；直接拒绝 |
| 迭代到不动点 | 决策单调（C4 上界），两遍 pass1 已经足够；再迭代只多花时间 |
| 16 位 `CBZ` 的引入 | 那是 `-fopt-cbz` 的事，已在 0.9.1 落地 |
| 第三遍校验 pass2 与布局一致 | `emit_b16_a()` 的越界自检就是这道校验（硬错误而非静默） |

代价是：**每次启用都要多跑一遍 pass1**（测量轮）。HAL 语料上这一遍的耗时与常规
pass1 同级，没有单独计时；换取的是 2.94% 的代码体积。
