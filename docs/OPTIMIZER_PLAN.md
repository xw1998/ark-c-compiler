# 0.9.x 优化演进路线（从三份逆向证据到 arkc 的阶段表）

[English](OPTIMIZER_PLAN.en.md) | 中文

0.9.0 是稳定版：**先把"编译对了"钉死，再动"编译得更好"**。这份文档是 0.9.x 的
作战地图——每条优化都写清四件事：**证据从哪来、落在哪个阶段、怎么裁掉、怎么判它真的有用**。

---

## 0 三条纪律（先立，否则后面全是空话）

1. **优化的默认值就是契约。** 新 pass 一律：代码按 profile 编进来（`ARKCC_FEATURE_*`）、
   运行期开关默认关（`g_config.enable_*`）。不开开关时产物与不含这个文件的构建
   **逐字节相同**，这条由门禁比对镜像，不靠承诺。要改默认值是单独的决策，单独一轮。
2. **每条"不做"都要有一个具名放弃点。** 逆向里最值得抄的不是算法，是形态：
   IAR 的 C1–C10 判据表里几乎每条"不能做"都对应一个诊断串。arkc 的对应物是
   **pass 注释里逐条写明的拒绝条件 + 门禁里的负例**——被拒绝的输入必须产出与开关关闭时
   逐字节相同的汇编。
3. **能裁切才算做完。** 板端（`ARKCC_PROFILE_STM32_MIN`，H743 上自举）没有 RAM 也没有
   Flash 装完整优化器。所以每个 pass 都要能在编译期整块消失：`#if ARKCC_FEATURE_X`
   包住实现、`built_in=0` 的行留在阶段表里保持编号、选项在裁切构建里以 `C3900U` 拒绝。
4. **收益必须能被量出来，而且要在小样本上量。** 不写"更小更快"这种话，只写
   "这个构造从 N 字节变 M 字节"。

## 2 路线：十条，按投入/收益排序

### P1 块尾合并（block-level cross-jump）——**0.9.1 已落地**

- **证据**：AC5 `CrossJumps` 一趟在 RA 之后、收尾之前；两轮候选（先零出口块，再主表）；
  `BLKLIFTABLE` / `on_savepath` 两条块级自检；`zip` 合并；跳距变化 ⇒ `need another pass`。
  实测：共享 1/2/3/5 条语句分别省 8/16/24/40 B，**小 N 就有正收益**。
- **arkc 落点**：`ir.tailmerge`，在 `ir.inline`/`ir.const-global` 之后、`ir.vectorize` 之前。
  放在内联之后是刻意的：cross-jump 清理的正是别的 pass 造出来的重复
  （AC5 的 `cj_in.c` 实验：`-O2` 内联出两份相同尾巴后，cross-jump 才合成一份）。
- **实现要点**（与逆向逐条对应）：
  1. 匹配是**逐指令相同**，不是语义等价（`cj6.c` 反例：`r1` vs `r0` 就不合）。
     IR 层没有寄存器分配，所以匹配比机器层更容易命中——这是 IR 层的红利。
  2. 只合并**栈深度为 0**的尾段：IR 是栈机，跳进非空栈的位置意味着把求值栈当状态
     跨边携带，这需要后端保证，不值得为一点收益去赌。
  3. 收益判据：`len >= ARK_TAILMERGE_MIN_LEN`（每条入口付一条 `JMP`），
     且合并后每一份都要真的变短；不省就不做。
  4. 每轮只做一次最优合并，重建 CFG 再来——与 `opt_licm_func` 同型，
     轮数以代码长度为上界，天然带终止护栏（对应 `Jump size optimization will not terminate!`）。
  5. 深度分析失败（标签入口深度不一致、出现 `IR_ALLOCA`）就**整函数放弃**，
     不是"跳过这一块"——半对的控制流比不优化更糟。
- **裁切**：`ARKCC_FEATURE_TAILMERGE`（STM32_MIN / 无 MIR ⇒ 0）；运行期 `--tailmerge`
  默认关，`-O1` 以上才允许。
- **判据**：`tests/run_tailmerge_tests.py`（23 项检查，`make test-tailmerge`）——
  静态（开关开则汇编变、关则逐字节相同，且与"把该 pass 编出构建"的对象逐字节相同）、
  负例（末条语句不同 / 相同后缀起始于栈深 1 / 后缀短于下限 / 函数含内联汇编，
  四者都必须一模一样；另有**同 TU 混合文件**证明"只合并可合并的那个函数"，
  排除"整个文件没跑过 pass"的假绿）、动态（ARM 模拟器上同结果且非平凡值）、
  字节账（构造用例必须**真的变小**并打印前后数）。
- **实测（0.9.1，宿主 gcc/MinGW）**：`merge.c` 汇编指令行 481 → 448，对象 1146 → 1086 B；
  内联汇编用例整函数放弃、深度 1 后缀不合并、`-O0` 产物逐字节相同；
  `-DARKCC_FEATURE_TAILMERGE=0` 构建以 `C3900U` 拒绝 `--tailmerge` 且默认对象与完整构建逐字节相同。

### P2 尾调用 → 跳转（**已落地 0.9.1**，省 4 B/处）

- **证据**：`07` §3.5 真跑——`f(x){return g(x+1);}` 从 `PUSH{lr}/BL/POP{pc}` 变 `B.W g`，
  `h2/h3` 因为返回后还要用返回值**不能**转；对应 IAR 的 `PreservesLR` 判定。
- **arkc 落点（与初稿不同，已改）**：不新增 `IR_TAILCALL`，而在 **ARM 后端的发射期**判定
  「`IR_CALL` 紧跟 `IR_RETURN`」（或 void 调用的「`IR_CALL` + 假值 `PUSH_INT 0` + `IR_RETURN`」），
  再要求**实参全部装进 r0–r3**（`stack_args == 0`）。发射序列为
  `MOV sp, r6` → `ADD sp, sp, #local` → `POP {r5, r6, r7, lr}` → `B callee`：
  `lr` 必须留着（用 `POP {.., lr}` 而不是 epilogue 的 `pc` 变体），被调方的 `POP {.., pc}`
  直接回到我们的调用者。拒绝：有栈参 / 间接调用 / sret / `_Complex` / `__naked` / `__irq` / 可变参。
- **裁切**：`ARKCC_FEATURE_TAILCALL`（STM32_MIN ⇒ 0，判定块整个折叠）；运行期 `--tailcall`
  默认关。**未加 `-O` 级别闸门**（与 `--reg-top` 一致：显式开关就是意图表达），
  此处以 `docs/TAILCALL.md` 为准。
- **判据**：`tests/run_tailcall_tests.py`（29 项检查，`make test-tailcall`）——开关真变汇编、
  三个正向形状逐行断言 `B <callee>` 与 `POP {r5, r6, r7, lr}` 且**没有** `BL`、自递归转成分支、
  六种拒绝形状逐字节不变、同 TU 选择性（一个改写一个不动）、模拟器同值且非平凡、
  默认关闭产物逐字节相同、裁剪构建以 `C3900U` 拒绝选项且默认对象与完整构建哈希相同。
- **实测（0.9.1，宿主 gcc/MinGW，Cortex-M7）**：`tc.c` 汇编 424 → 413 行、对象 1171 → 1157 B；
  `tf`/`tf64`/`vt`/`tsum` 分别 23→21、23→19、18→15、55→53 条；模拟器 `off=81 on=81`。
- **未做**：栈参尾调用的搬移、其它后端（x86-64 / RISC-V 上 `--tailcall` 是无害空操作）。
  细节见 `docs/TAILCALL.md`。

### P3 除常数 → 乘魔数 + 移位（**已落地 0.9.1**）

- **证据**：两侧都有（IAR `GoDivideByConstant`/`TaDivByConstant`；AC5 `constant_multiply.c` +
  `no_constdiv`）。ARM 无硬件除法时 `/const` 走 `__aeabi_idiv`，20+ 周期变 3–6 周期。
- **arkc 落点（与初稿不同，已改）**：不是新的 IR pass，而在 **ARM 后端发射期**——
  `IR_PUSH_INT c` 紧跟 `IR_DIV`/`IR_MOD` 即除数已知，丢掉那次 push 改发魔数序列。
  前瞻要两步（`x / -5` 的 IR 是 `PUSH_INT 5` + 32 位取负的 `IR_UNARY` + `DIV`，
  用计数器 `divconst_skip` 吞掉那条取负）。无符号三种形状（2 的幂 → `LSR`、
  `m < 2^32` → `UMULL` + 移位、`m >= 2^32` → add 形，`L == 32` 时 `m = (2^64-1)/d + 1`）；
  有符号走**幅值法**（符号保存/复原 + 无符号序列 + 余数 `n - q*c`），负除数只多一条
  `MVN` 翻符号寄存器。拒绝：`c == 0`、`c == 1`、有符号 `c == -1`、有符号 `|c| == 2^31`、
  无符号 `c == 1`（拒绝即逐字节不变）。
- **裁切**：`ARKCC_FEATURE_DIVCONST`（STM32_MIN ⇒ 0，前瞻块与发射函数整块消失）；
  运行期 `--divconst` 默认关（与 `--tailcall` 一致，不加 `-O` 级别闸门）。
  此处以 `docs/DIVCONST.md` 为准。
- **判据**：`tests/run_divconst_tests.py`，45 项，`make test-divconst`：静态形状（16 个用例
  各自命中标记、`SDIV`/`UDIV` 归零）+ 单 TU 选择性 + 五种拒绝逐字节相同 + 执行三方一致
  （16 除数 × 66 被除数，checksum `0x40F32C43`，含 `--reg-top`/`--tailcall` 组合）+
  防假绿（默认关、`--no-divconst`、裁剪构建 `C3900U` 与 INI 守卫）+ 如实字节账。
  数学先经 Python 全量验证：无符号 9,150,609 组、有符号 4,030,257 组 0 失败。
- **实测**：对象 4293 → 4533 B（**+240 B**）、指令行 1743 → 1836（**+93 行**）；
  换的是周期不是字节，只有无符号 2^k 的两个形状真的变短。特性代码体积（宿主 gcc -O2
  只编 `backend_arm.c`）`.text` 93376 → 95056 B（+1680 B）、符号 186 → 189。

### P4 块级重复块消除（cross-jump 的整块形态，**已落地 0.9.1**）

- 与 P1 同一个匹配器，只是不限尾段：整块相同 ⇒ 只留一份 + 其余改为跳转。
- **落地时的三处关键决定**（都是踩出来的，各自对应一种错答案）：
  ① **拒绝以条件分支收尾的块**——taken 后继写在块体里，fall-through 后继由块在指令表里的
  位置决定，两块块体相同也可能跌进不同的代码；只有单后继且后继写在块体里才允许合并。
  ② **跳转目标按「块」比较而不是按 label id**——`irgen` 给 `if`/`else if` 每个分支各造一个
  合并点标签（`.L_two_1` vs `.L_two_3`），按 id 比较会把最典型的重复块全部漏掉
  （初版就是这样，开开关产物「一点变化都没有」）。
  ③ **只能标签的块要先归一化**——相邻合并点标签各成 leader，出现「块里只有标签、直接跌到
  下面」的块，`xb_resolve_block()` 沿单后继穿过它们再比块号，成环则拒绝。
  另外要求入口栈深为 0、块体无标签、块体不含 `FUNC_BEGIN/FUNC_END`、长度 ≥ 4。
- **裁切**：`ARKCC_FEATURE_XBLOCK`（STM32_MIN 或无 MIR ⇒ 0），共享段由
  `ARKCC_FEATURE_TAILMERGE || ARKCC_FEATURE_XBLOCK` 包住；运行期 `--xblock` 默认关，
  走阶段表 `ir.xblock`（`-O1` 以上可跑）。此处以 `docs/XBLOCK.md` 为准。
- **判据**：`tests/run_xblock_tests.py`，26 项，`make test-xblock`：静态形状与调用点计数
  （`BL` 5 → 2）+ 四种拒绝形状逐字节相同 + 同 TU 选择性 + 模拟器同值且非平凡 +
  防假绿（默认关、`--no-xblock`、裁剪构建 `C3900U` 且默认对象哈希相同、INI、阶段表、`-O0`）
  + 字节账。
- **实测**：构造用例汇编 320 → 272 行、对象 869 → 767 B（`BL g` 5 → 2）。
  细节见 `docs/XBLOCK.md`。

### P5 cross-call（跨过程共享）——**明确不做，理由写死**

- 收益依赖"工程里存在大量相似函数前缀"，而代价是调用约定、返回标签、unwind 链三件事
  （`07` §2.3 的四条 `isn't set`）。arkc 目前没有 unwinder，也没有跨 TU 的 IR 池，
  做出来只能在单 TU 内生效——收益与复杂度不成比例。**记录在案，不排期。**

### P6 size/speed 连续权重（`--size-weight` 0..9，**已落地 0.9.1**）

- **证据**：IAR 把 `-z0..9` / `-s0..9` 做成连续权重（0–2 Debug / 3 Low / 4–6 Medium / 7–9 High），
  AC5 是 `-Ospace`/`-Otime` 二元。
- **落地形态**：一个全局权重 `g_config.size_weight`（0..9，默认 5）同时移动**四个门槛**——
  内联上限、展开上限、尾合并最小长度、整块合并最小长度。权重 5 的四张表项与 0.9.0 的
  编译期常量逐一相等（12 / 8 / 3 / 4），所以「不写这个选项 = 0.9.0 逐字节相同」。
  原来的四个宏（`ARK_INLINE_THRESHOLD` 等）已删除：一个值只有一个来源。
- **与初稿不同，已改**：不新增 `-Oz/-Os/-Ot`。`-O` 决定跑哪些 pass，这四个门槛只调同一个
  pass 的取舍；做成 `-Oz` 会让人以为顺带改了 `-O` 级别。只加一个与 `-O` 正交的数值权重。
- **裁切**：`ARKCC_FEATURE_SIZEWEIGHT` 是**派生**宏（= 四个 pass 宏的或），且先 `#undef`
  再派生——单独 `-D...=0` 会让访问器无定义（踩过一次：`ld returned 1`）。四个 pass 的代码
  本身不按开关裁，只是不进阶段表，所以裁剪构建里访问器退化成历史常量。
- **判据**：`tests/run_sizeweight_tests.py`，31 项，`make test-sizeweight`：四张表 + 「5 = 历史
  常量」+ 单调性 + 两端不平；不写与 `=5` 的对象逐字节（6 夹具 + `hello.c`）；四个门槛各自在
  `-S` 与模拟器上生效（`BL h` 0/0/2 与 0/2/2、展开 467/135/135 与 275/275/135、尾合并
  313/302/244、整块 353/159/137）；六种非法值拒绝且不落盘；裁剪构建拒绝且 `-v` 无该行；
  INI 两种拼写 + 越界警告；四种夹具在 0/5/9 同值；语料字节 5040 → 3094。
- **实测**：`examples/*.c` 全部 80 个文件在 HEAD 与本轮产物上 **0 处不一致**。
- **带参函数内联（0.9.1-wip 已修）**：P6 交付时登记在 `docs/SIZEWEIGHT.md` §6 的欠账是
  `irgen` 给 `IR_GETARG` 的 `aux` 写 `(size<<8)|slot`（标量也写 size），而内联判定用
  `(aux>>8)!=0` 认 struct-by-value ⇒ **任何带参数的函数永不内联**（`forceinline` 也绕不过）。
  判定现在改读参数类型（`irgen_param_slots()`，见 §2 末），1 字与 2 字参数都能内联；按地址
  传参的聚合、C 后端（8 字节槽）与 x86-64（指针一字）仍一律拒绝。门禁
  `tests/run_inline_tests.py`（`make test-inline`，25 项）。注意两点：① P6 那一轮的权重内联
  维度只能用无参被调函数观察，且「`examples/*.c` 80 个文件 0 处不一致」只对 P6 那一轮成立
  ——0.9.1-wip 起带参内联会改变 `-O2` 默认产物；② `--tailcall` 与 `--xblock` 的门禁现在
  一律带 `--no_autoinline`：前者夹具正是「带参小函数」形态，不隔离内联就看不到 `B leaf`；
  后者的重复块就是 `two()`/`three()` 里各两次 `g()` 调用，内联之后重复块整片消失（全量
  `make test` 里 7 项一起 FAIL，隔离后恢复，对象 865 → 763 字节）。
  另留一条测量陷阱：内联是单遍的，夹带启动文件时被内联进 `Reset_Handler` 的那份 `main`
  副本仍带着未展开的 `BL h`。

### P7 值栈 → 寄存器分配（`-fopt-vstack`，**已落地 0.9.1-wip**）

- **证据**：IAR `08-backend-passes.md` 把「表达式求值的值栈」列为后端第一顺位的收益项，
  ARMCC `13-regalloc-selection.md` / `14-regalloc-internals-and-open-items.md` 把「让中间值
  在寄存器里活着」写成寄存器分配的**前置**（分配器再强，值已经落内存了也没得选）。
- **做法**：不发新 IR opcode、不动 `gen_expr`，而是在**已发射的汇编文本上做函数级重建**
  （与既有 `ark_regalloc_function()` 同范式）。影子值栈 + 双槽池（r5/r7，prologue 已保存
  ⇒ 零帧变化）+ 目的寄存器 retarget + 只读操作数文本替换；池不够用就退回真 `PUSH`。
- **池槽必须引用计数**：`POP r0; PUSH r0; PUSH r0`（5..8 字节结构体返回的存储序列）让同一个
  槽被三处引用，「用完就还」会把别人的值递出去。
- **必须物化的三种形状**：同行读写（`LDR r0,[r0,#0]`）、跨操作数读写（`ADD r0,r0,r1`）、
  原地三操作数（`ADC/SBC/MUL` 要求 `Rd==Rn`）；`MOVW/MOVT` 一律不 retarget（成对构造一个值）。
- **裁切**：`ARKCC_FEATURE_OPT_VSTACK`（STM32_MIN 0 / 宿主 1）；运行期默认**关**，`-fopt-vstack`
  才开，裁剪构建以 `C3900U` 拒绝该旗标。
- **跨界（续做）**：原先 label / `B` / `Bcc` / `BX` / `BL` / `IT` 处**影子栈不空或内存栈
  不空**就整函数 bail，太紧——大量函数在边界处已经把值全部写回机器栈。现改为：从
  `pro_end+1` 起按 `PUSH/POP` 开括号预扫描，遇 label/调用/分支把未闭合的 `PUSH` 行标
  `cross`；`cross` 行强制发真 `PUSH`（有 `pend` 则从池寄存器 push），使机器栈与原码逐字
  一致；边界处若影子栈**全为 MEM** 则置 `verbf` 继续，之后整段 verbatim 输出，否则照旧
  bail。池寄存器不可重建，所以只有「值已在内存」才允许跨。
- **第三槽 r4（续做）**：池从两槽扩到三槽，但 r4 是**有条件**取的——survey 用影子深度
  模拟算出「同一节拍最多几个值压在机器栈上」（`sdmax`，遇 `BL` 归零），只有 `sdmax >= 3`
  才动用 r4（深度到不了三的函数一个指令都省不下，多存一个寄存器是净亏；HAL 上 203 个
  可改写函数只有 59 个过线，被挡掉的 63 个实测收益恰好为 0）。代价必须付清：prologue/epilogue
  加 r4 会把 `sp` 变成 ≡4 (mod 8)，所以 `SUB`/`ADD sp, sp, #N` 同改 `N+4`；四行先各自格式化、
  四次分配都成功才一次性替换，任何一步失败整条路放弃。**零帧函数**（无参数无局部变量，序言
  没有 `SUB sp`）走另一条：PUSH/POP 改成五寄存器，并在 `MOV r6, sp` **之后**补一条
  `SUB sp, sp, #4`（不加 `ADD`——收尾 `MOV sp, r6` 会把这点 padding 丢弃；放错位置就会每次
  调用漏掉调用者一个字）。HAL 上 81 个零帧函数里有 28 个因此过线，全语料再降 28 条。
- **判据**：`tests/run_vstack_tests.py`，31 项，`make test-vstack`：默认关闭逐字节相同、
  指令与 `PUSH/POP` 下降、**镜像只减不增**、逐函数断言无孤立 PUSH/POP 对、六夹具
  off/on/on+regalloc 同值、裁剪构建拒绝；另有两条专测第三槽——`deep` 必须出现
  `PUSH {r4, r5, r6, r7, lr}` / `POP {r4, r5, r6, r7, pc}` 且帧 `N % 8 == 4`，`shallow`
  的 prologue 里**不能**出现 r4。另每次改动跑 `tests/arm_exec` 全语料
  （`--extra=-fopt-vstack`，39 用例 0 失败）——**本 pass 的五处语义缺陷全部是它抓到的**。
- **实测**（跨界 + 第三槽）：STM32F4 HAL 全语料（`-O2 -mcpu Cortex-M4`，非指示非标签行）
  47,884 → 37,976 条（**−20.71%**，已含 r4 第三槽）；再叠 `-fopt-addr` 到 36,524 条
  （−3.82%）。夹具：arith 171 → 121 条、`PUSH/POP` 88 → 14、镜像 1392 → 1292；
  loop 203 → 140、100 → 12、1480 → 1354；struct 1400 → 1294；variadic 1556 → 1458；
  deep 1384 → 1354；shallow 1274 → 1226。r4 的记账要诚实：59 个函数各多 push/pop 一个字
  （约 +472 字节），换 340 条指令，逐字节对象大小未单独测量。细节见 `docs/RA_VSTACK.md`。

### P8 寻址折叠（`-fopt-addr`，**已落地 0.9.1-wip**）

- **证据**：IAR `08-backend-passes.md` 的 peephole 清单把「地址算术折进寻址方式」列在
  「值栈」之后的第二顺位；ARMCC `09-addressing-modes.md` 说明 AC5 让 `LDR/STR` 直接吃
  `[Rn, #imm]` / `[Rn, Rm, LSL #n]`，不为每次下标另算一条 `ADD`。
- **做法**：同样在**已发射的汇编文本上**做函数级 pass（调用点位于 `ark_vstack_function()`
  与 `ark_regalloc_function()` 之间）。定点迭代 ≤6 轮，三条规则：**R1** 常量偏移
  `ADD RD,RB,#imm` + `mem Rt,[RD(,#off)]` → `mem Rt,[RB,#imm+off]`；**R2** 寄存器索引
  `ADD RD,RB,RI[,LSL #n]` + `mem Rt,[RD]`（`off` 必须 0）→ `mem Rt,[RB,RI[,LSL #n]]`；
  **R3** `MOV RB,RS` + 经 `RB` 的访问 → 基址换成 `RS`，删 `MOV`。
- **安全性靠死值分析**：`ADD/MOV` 写入的寄存器在本函数内若还被后续指令读就**不折**；
  例外是紧跟的那条 `mem` 本身就读它（`ad_is_load`）——值被地址吃掉，无条件可折。
  屏障 `DMB/DSB/ISB` 不参与（它们没有寄存器操作数，`ad_rw()` 的「未知=全读写」兜底会把
  `volatile` 访问永久卡住；不加这条开口 HAL 语料残留计数停在 3）。
- **明确不做**：ARMv7-M 的两种写回形（`[Rn,#imm]!` 前索引、`[Rn],#imm` 后索引）实测
  本代码生成器**一次都没发射**（`*p++` 发射为「寄存器加法 + 存回帧槽」），全目标文件里
  仅两处手写 `__arkcc_mcpy` 使用且 pass 不遍历；写进来也是死代码，故不实现（见文档正文明细）。
- **裁切**：`ARKCC_FEATURE_OPT_ADDR`（STM32_MIN 0 / 宿主 1）；运行期默认**关**，
  `-fopt-addr` 才开，裁剪构建以 `C3900U` 拒绝该旗标。
- **判据**：`tests/run_addr_tests.py`，`make test-addr`：默认关闭逐字节相同（OFF IS OFF）、
  四臂（base/off/on/both）**镜像只减不增**且索引寻址形态真的出现、**NO RESIDUE**
  （on/both 里可折的三类就地模式计数必须为 0，只折前两处的错误实现过不了这关）、
  改写后的操作数全在助记符白名单、四臂在 unicorn 上算出同一个答案、裁剪构建拒绝旗标。
- **实测**：HAL 全语料 `examples/ark_test/ark_test_all.c`（STM32F401xE，`-O2`），基线是
  已过 vstack（含 r4 第三槽）的 37,976 条：37,976 → 36,524 条（**−1,452 / −3.82%**）；
  寄存器索引形残差 1,075 → 0，`MOV` 形 0 → 0；总减少量大于 1,075，说明 R1（常量偏移形）
  在新基线上确实会触发（逐条归因未做，不报数字）。与纯 `-O2` 的 47,884 叠加看：
  47,884 → 37,976 → 36,524。细节见 `docs/ADDR_FOLD.md`。

### P9 强度削减（`-fopt-strength`，**已落地 0.9.1-wip**）

- **证据**：AC5 对 `x * 4` 发 `LSLS`、对 `p[i]` 直接发 `LDR r4, [r3, r2, LSL #2]`、
  对 `x * 3` 发一条 scaled `ADD`（`armcc --c99 -O2 -c --cpu Cortex-M4` + `fromelf --text -c`
  实测）。也就是说「乘常量」在真实编译器里从不走 `MUL`。
- **两个落点，一个开关**：HAL 语料 1,105 条 `MUL` 里 1,052 条是 `IR_LOAD_IDX` 的 stride
  缩放（`i * sizeof(elem)`，`MOV r2,#4` 1,043 / `#2` 9），53 条是源码里的常量乘。前者
  **IR 层根本看不见**（IR 里只有 `IR_LOAD_IDX` 节点），所以：**A** `src/opt.c` 的
  `opt_strength_func()` 把相邻 `PUSH k` + `MUL`（k 为 2 的幂）改成 `PUSH log2(k)` + `SHL`，
  k==1 两条都删；**B** `backend_arm.c` 的 `IR_LOAD_IDX` 在 `es` 为 2 的幂时用
  `LSL r1, r1, #n` 取代 `MOV r2, #es` + `MUL r1, r2`。拆成两个旗标等于逼用户记着开两个。
  另有后段 **R4**（同在 `-fopt-strength` 开关下、实现在 `ark_addr_function()` 的 round 循环）：
  `-fopt-addr` 的 R2 把 `ADD` 折掉后，`LSL` 与访问相邻，R4 再把两者并成
  `[Rn, Rm, LSL #n]` 一条（只认 `LDR`/`STR`、`n∈1..3`、`rI!=rB`、`rS` 事后已死）。
  顺带修掉 `ad_rw()` 把 `POP` 当读的活跃性缺陷（`POP {r1}` 让 r1 永活）；折叠数 243→924。
- **只做 2 的幂**：Cortex-M4 的 `MUL` 一周期，`LSL`+`ADD` 链不会更短（这是量出来的，
  不是猜的）；`x*3` 保留 `MUL` 并写成门禁断言，防后人「顺手」扩成 shift/add 链。
- **阶段位置是踩出来的**：第一版放在 `ir.dce` 之后，结果**开了反而变大**（pow2 夹具
  512→533 条、镜像 2128→2170 B）——`x*1` 的删除让一个函数 IR 从 12 掉到 10，跌破
  `opt_inline` 阈值而被内联。整行移到 **`ir.xblock` 之后、`ir.vectorize` 之前**后
  inline/const-global/tailmerge/xblock 看到与原版相同的 IR 形状，问题消失（512→503）。
- **裁切**：`ARKCC_FEATURE_OPT_STRENGTH`（STM32_MIN 0 / 宿主 1，板端裁掉是对的——
  默认关，留着只是躺在 Flash 里）；默认关，`-fopt-strength` 才开，裁剪构建以 `C3900U` 拒绝。
- **判据**：`tests/run_strength_tests.py`，**18 项**，`make test-strength`：OFF IS OFF 逐字节、
  条数下降、**`MUL` 归零**、**`LSL r1,r1,#n` 出现**（只做 IR 层过不了）、**无残留
  `PUSH #2^k`+`MUL`**、`odd` 夹具逐字节不变、镜像只减不增、五臂同值、裁剪拒绝；R4 四面：
  合出的 `[rB,rI,LSL #n]` 在 `all` 臂存在（1 条）、在 `on` 臂为 0、在 `va` 臂为 0、
  `LSL #1..3` 严格减少（3→2，残留 1 条来自 `ad_dead_after` 遇 label 的保守退出）。
- **实测**：纯 `-O2` 47,884 → **46,779** 条（**−1,105 / −2.31%**），`MUL` **1,105 → 12**
  （剩下 12 条全是值×值，无一常量乘）；在 `-fopt-vstack -fopt-addr` 的 36,524 之上 →
  **35,424**（−1,100 / −3.01%）；后段 R4 再折 924 条 → **34,500**（−924 / −2.61%）。
  完整链：**47,884 → 37,976 → 36,524 → 35,424 → 34,500（−27.95%）**。
  对象字节：115,090 → 112,878（−2,212 B）；92,408 → 90,208（−2,200 B，**R4 前后不变**：
  它的每次合并是两条 16 位换一条 32 位，只降指令数不降字节）。
  细节见 `docs/STRENGTH.md`。

### P10 零比较跳转折叠（`-fopt-cbz`，**已落地 0.9.1-wip**）

- **证据**：AC5 对 `if (!p)` 一类判零跳转发 `CBZ`/`CBNZ` 单条（`armcc --c99 -O2
  -c --cpu Cortex-M4` + `fromelf --text -c` 实测），arkc 一直发 `CMP rX, #0` + 32 位
  `B<cond>.W` 两条。
- **一条规则**：`CMP r0-r7, #0` 紧跟 `BEQ/BNE`（中间只有元数据行）→ 改写成
  `CBZ/CBNZ rX, .L_x` 并删掉跳转。四条必要条件：相邻、操作数窄、目标前向且上界 ≤ 64 字节、
  **标志位已死**（写标志/返回/函数末尾之前不得出现读标志者；无条件 `B` 跟随目标继续扫）。
- **偏移推导写死**：融合后 `offset = 区间字节数 − 2`，与标签原本离 `CMP` 多远无关
  （被删的 `CMP` 与跳转在两端各挪一次相抵）。
- **保守上界**：文本层看不见真实宽度，每条指令按 4 字节、`LDR =sym` 按 8 字节估；
  区间里有数据指令直接放弃。上界只可能让 pass 放弃，不会发出越界 `CBZ`。
- **为什么是难点**：`if` 体末尾总有 `B .L_end`，首版把它判为不安全 ⇒ 一处都不折；
  改成跟随 `B` 后 5/5 全中。另一个真缺陷是重建时用了 trim 过的行，把整个函数的缩进抹掉。
- **裁切**：`ARKCC_FEATURE_OPT_CBZ`（STM32_MIN 0 / 宿主 1），默认关；裁剪构建以 `C3900U` 拒绝。
  `CBZ`/`CBNZ` 已从 `--asm-extra` 名单移出（编译器要能汇编自己的输出，同 `ADDS`/`SUBS`）。
- **判据**：`tests/run_cbz_tests.py`，**14 项**，`make test-cbz`：OFF IS OFF 逐字节、
  CBZ 只随旗标出现、条数下降、相邻对被吃掉、叠加仍有效、顺序在 vstack/addr 之后、
  镜像只减不增、五臂同值、**超范围体（上界 80 字节）一处不折**、超范围时不改写、
  镜像不变、裁切拒绝且不带旗标仍可编译；另跑 `tests/arm_exec` 全语料（0 失败）。
- **实测**：纯 `-O2` 47,884 → **47,489**（−396 条 / −1,584 B）；全链 34,500 → **34,080**
  （−420 条 / −1,680 B）。每处融合正好省 4 字节（16 位 `CMP` + 32 位 `Bcc` → 16 位 `CBZ`）。
  HAL 语料 814 处相邻对里折了 396 处，其余卡在 64 字节上界与标志位仍被读。
  细节见 `docs/CBZ_FOLD.md`。

### P11 短分支收缩（`-fopt-branch`，**已落地 0.9.1-wip**）

- **证据**：本后端的 `B` / `B<cond>` 一直发 32 位（`B.W` T4 ±1MB、`B<cond>.W` T3 ±1MB），
  因为 `op_size_a()` 那一遍还不知道标签地址，16 位形式越界会被静默截断——`-fopt-vstack`
  之后真踩过一次（循环回边被截断，`UC_ERR_WRITE_UNMAPPED`）。
- **做法**：坐在**汇编器内部**，测量轮把所有分支按 4 字节排完并记录 `(pc, cond, 目标名)`
  与 `.align` 位置；`arm_decide_branches()` 用 `off = target − (pc+4)` 判定，
  条件跳转 `−256..254`（T1 imm8）、无条件 `−2048..2046`（T2 imm11），奇数偏移拒绝；
  前向目标再减 2（本分支自身 4→2 的上界）；**跨度跨 `.align` 一律拒绝**（padding 非线性
  会振荡）。有决策变化就再跑一轮 pass1（此时按 2/4 字节真实布局，对齐填充自动精确），
  然后 pass2 按序数表发射 2 字节形式；`cond`/目标名不匹配则回退 32 位。
- **最大的坑**：第二轮 pass1 必须按最终宽度量。首版仍算 4 字节而 pass2 发 2 字节，
  标签没重排 ⇒ 之后每条指令提前 2 字节，分支跳进指令中间（`addr=0`、`pc=0x8000C2A`）。
  现在 `add_branch_a()` 返回本轮宽度，pass1 用它推进 `pc`。
- **宁可报错**：`emit_b16_a()` 重新算一次偏移，越界报 `internal layout error` hard error
  并输出 `NOP`，不把截断偏移编出去。
- **裁切**：`ARKCC_FEATURE_OPT_BRANCH`（STM32_MIN 0 / 宿主 1），默认关；为 0 时计划字段与
  调用点整块消失（零字段、零代码、零体积变化），裁剪构建以 `C3900U` 拒绝该旗标。
- **判据**：`tests/run_branch_tests.py`，**18 项**，`make test-branch`：OFF IS OFF 逐字节、
  条数不变、按整 2 字节下降、叠加 vstack/addr 仍收益、镜像只减不增、五臂同值、
  **远目标（`while` 体 200 条 / 300 条）分支保持 32 位**、裁切拒绝且不带旗标仍可编译。
  「远目标」用**差分判据**：最小参考程序量出运行时 helper 的固有节省（10 B），
  要求 far/vfar 的节省与之相等——多 1 字节就说明远跳被错误挤成 16 位。
- **实测**：夹具 `near` 1,386 → 1,368 B（−18，条数 160 不变），`va` 臂 1,294 → 1,276 B；
  STM32F4 HAL 96 个单元代码段 116,480 → **113,058 B（−3,422 B / −2.94%）**，
  96/96 全部缩小、无单元变大（符号表不变 ⇒ 省的全是代码）。细节见 `docs/BRANCH_SHRINK.md`。

## 3 与阶段表的关系（裁切的两个层次）

| 层次 | 手段 | 关掉时的保证 |
| --- | --- | --- |
| 编译期 | `ARKCC_FEATURE_*` | 代码与字符串整块消失；阶段表保留编号但 `built_in=0`；选项以 `C3900U` 拒绝 |
| 运行期 | `--<pass>` / `-fno-<pass>`、INI 键 | 产物与不含该 pass 的构建逐字节相同 |
| 剖面 | `--pipeline=lite` | 贵阶段被跳过并留下原因；`full` 与不写逐字节相同 |

三条都要有门禁覆盖：**能被关掉** 与 **关掉后真的没留下痕迹** 是两件事。

## 4 已知欠账（与优化无关，登记在案）

见 `docs/BOARD_VALIDATION.md` §8：每语句约 1.3 KB arena、长 `double` 字面量差 1 ulp、
板端未上传 `aeabi_float.c`、串口 RX 偶发丢字节、`pyocd -m` 需固定 cwd。
优化线不碰这些，但**它们会限制优化的验证方式**（例如板端跑不动大函数的全展开）。
