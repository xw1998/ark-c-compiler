# 0.9.x 优化演进路线（从三份逆向证据到 arkc 的阶段表）

[English](OPTIMIZER_PLAN.en.md) | 中文

0.9.0 是稳定版：**先把"编译对了"钉死，再动"编译得更好"**。这份文档是 0.9.x 的
作战地图——每条优化都写清四件事：**证据从哪来、落在哪个阶段、怎么裁掉、怎么判它真的有用**。

---

## 0 三条纪律（先立，否则后面全是空话）

1. **优化的默认值就是契约。** 新 pass 一律：代码按 profile 编进来（`ARKCC_FEATURE_*`）、
   运行期开关默认关（`g_config.enable_*`）。不开开关时产物与不含这个文件的构建
   **逐字节相同**，这条由门禁比对镜像，不靠承诺。要改默认值是单独的决策，单独一轮。
2. **每条"不做"都要有一个具名放弃点。** 逆向里最值得抄的不是算法，是形态：
   IAR 的 C1–C10 判据表里几乎每条"不能做"都对应一个诊断串。arkc 的对应物是
   **pass 注释里逐条写明的拒绝条件 + 门禁里的负例**——被拒绝的输入必须产出与开关关闭时
   逐字节相同的汇编。
3. **能裁切才算做完。** 板端（`ARKCC_PROFILE_STM32_MIN`，H743 上自举）没有 RAM 也没有
   Flash 装完整优化器。所以每个 pass 都要能在编译期整块消失：`#if ARKCC_FEATURE_X`
   包住实现、`built_in=0` 的行留在阶段表里保持编号、选项在裁切构建里以 `C3900U` 拒绝。
4. **收益必须能被量出来，而且要在小样本上量。** 不写"更小更快"这种话，只写
   "这个构造从 N 字节变 M 字节"。

## 2 路线：六条，按投入/收益排序

### P1 块尾合并（block-level cross-jump）——**0.9.1 已落地**

- **证据**：AC5 `CrossJumps` 一趟在 RA 之后、收尾之前；两轮候选（先零出口块，再主表）；
  `BLKLIFTABLE` / `on_savepath` 两条块级自检；`zip` 合并；跳距变化 ⇒ `need another pass`。
  实测：共享 1/2/3/5 条语句分别省 8/16/24/40 B，**小 N 就有正收益**。
- **arkc 落点**：`ir.tailmerge`，在 `ir.inline`/`ir.const-global` 之后、`ir.vectorize` 之前。
  放在内联之后是刻意的：cross-jump 清理的正是别的 pass 造出来的重复
  （AC5 的 `cj_in.c` 实验：`-O2` 内联出两份相同尾巴后，cross-jump 才合成一份）。
- **实现要点**（与逆向逐条对应）：
  1. 匹配是**逐指令相同**，不是语义等价（`cj6.c` 反例：`r1` vs `r0` 就不合）。
     IR 层没有寄存器分配，所以匹配比机器层更容易命中——这是 IR 层的红利。
  2. 只合并**栈深度为 0**的尾段：IR 是栈机，跳进非空栈的位置意味着把求值栈当状态
     跨边携带，这需要后端保证，不值得为一点收益去赌。
  3. 收益判据：`len >= ARK_TAILMERGE_MIN_LEN`（每条入口付一条 `JMP`），
     且合并后每一份都要真的变短；不省就不做。
  4. 每轮只做一次最优合并，重建 CFG 再来——与 `opt_licm_func` 同型，
     轮数以代码长度为上界，天然带终止护栏（对应 `Jump size optimization will not terminate!`）。
  5. 深度分析失败（标签入口深度不一致、出现 `IR_ALLOCA`）就**整函数放弃**，
     不是"跳过这一块"——半对的控制流比不优化更糟。
- **裁切**：`ARKCC_FEATURE_TAILMERGE`（STM32_MIN / 无 MIR ⇒ 0）；运行期 `--tailmerge`
  默认关，`-O1` 以上才允许。
- **判据**：`tests/run_tailmerge_tests.py`（23 项检查，`make test-tailmerge`）——
  静态（开关开则汇编变、关则逐字节相同，且与"把该 pass 编出构建"的对象逐字节相同）、
  负例（末条语句不同 / 相同后缀起始于栈深 1 / 后缀短于下限 / 函数含内联汇编，
  四者都必须一模一样；另有**同 TU 混合文件**证明"只合并可合并的那个函数"，
  排除"整个文件没跑过 pass"的假绿）、动态（ARM 模拟器上同结果且非平凡值）、
  字节账（构造用例必须**真的变小**并打印前后数）。
- **实测（0.9.1，宿主 gcc/MinGW）**：`merge.c` 汇编指令行 481 → 448，对象 1146 → 1086 B；
  内联汇编用例整函数放弃、深度 1 后缀不合并、`-O0` 产物逐字节相同；
  `-DARKCC_FEATURE_TAILMERGE=0` 构建以 `C3900U` 拒绝 `--tailmerge` 且默认对象与完整构建逐字节相同。

### P2 尾调用 → 跳转（**已落地 0.9.1**，省 4 B/处）

- **证据**：`07` §3.5 真跑——`f(x){return g(x+1);}` 从 `PUSH{lr}/BL/POP{pc}` 变 `B.W g`，
  `h2/h3` 因为返回后还要用返回值**不能**转；对应 IAR 的 `PreservesLR` 判定。
- **arkc 落点（与初稿不同，已改）**：不新增 `IR_TAILCALL`，而在 **ARM 后端的发射期**判定
  「`IR_CALL` 紧跟 `IR_RETURN`」（或 void 调用的「`IR_CALL` + 假值 `PUSH_INT 0` + `IR_RETURN`」），
  再要求**实参全部装进 r0–r3**（`stack_args == 0`）。发射序列为
  `MOV sp, r6` → `ADD sp, sp, #local` → `POP {r5, r6, r7, lr}` → `B callee`：
  `lr` 必须留着（用 `POP {.., lr}` 而不是 epilogue 的 `pc` 变体），被调方的 `POP {.., pc}`
  直接回到我们的调用者。拒绝：有栈参 / 间接调用 / sret / `_Complex` / `__naked` / `__irq` / 可变参。
- **裁切**：`ARKCC_FEATURE_TAILCALL`（STM32_MIN ⇒ 0，判定块整个折叠）；运行期 `--tailcall`
  默认关。**未加 `-O` 级别闸门**（与 `--reg-top` 一致：显式开关就是意图表达），
  此处以 `docs/TAILCALL.md` 为准。
- **判据**：`tests/run_tailcall_tests.py`（29 项检查，`make test-tailcall`）——开关真变汇编、
  三个正向形状逐行断言 `B <callee>` 与 `POP {r5, r6, r7, lr}` 且**没有** `BL`、自递归转成分支、
  六种拒绝形状逐字节不变、同 TU 选择性（一个改写一个不动）、模拟器同值且非平凡、
  默认关闭产物逐字节相同、裁剪构建以 `C3900U` 拒绝选项且默认对象与完整构建哈希相同。
- **实测（0.9.1，宿主 gcc/MinGW，Cortex-M7）**：`tc.c` 汇编 424 → 413 行、对象 1171 → 1157 B；
  `tf`/`tf64`/`vt`/`tsum` 分别 23→21、23→19、18→15、55→53 条；模拟器 `off=81 on=81`。
- **未做**：栈参尾调用的搬移、其它后端（x86-64 / RISC-V 上 `--tailcall` 是无害空操作）。
  细节见 `docs/TAILCALL.md`。

### P3 除常数 → 乘倒数（更快，`-O2`）

- **证据**：两侧都有（IAR `GoDivideByConstant`/`TaDivByConstant`；AC5 `constant_multiply.c` +
  `no_constdiv`）。ARM 无硬件除法时 `/const` 走 `__aeabi_idiv`，20+ 周期变 3–5 周期。
- **arkc 落点**：`ir.divconst`，`IR_DIV`/`IR_MOD` 的除数是指令流里的常量时，
  用魔数乘法 + 移位（有符号用 round-up 修正）替换。
- **裁切**：`ARKCC_FEATURE_DIVCONST`；运行期 `--divconst`。
- **判据**：穷举 `n ∈ [-2^31, 2^31)` 抽样 + 边界（`INT_MIN / -1` 必须仍按 C 的 UB 处理而不是先崩），
  与"原样调用 `__aeabi_idiv`"逐值比较。

### P4 块级重复块消除（cross-jump 的整块形态）

- 与 P1 同一个匹配器，只是不限尾段：整块相同 ⇒ 只留一份 + 其余改为跳转。
- 逆向里 AC5 用 `zip` 统一处理这两种形态，所以**共用一份匹配与重写代码**，
  只是候选生成器不同。等 P1 稳定后再开。

### P5 cross-call（跨过程共享）——**明确不做，理由写死**

- 收益依赖"工程里存在大量相似函数前缀"，而代价是调用约定、返回标签、unwind 链三件事
  （`07` §2.3 的四条 `isn't set`）。arkc 目前没有 unwinder，也没有跨 TU 的 IR 池，
  做出来只能在单 TU 内生效——收益与复杂度不成比例。**记录在案，不排期。**

### P6 size/speed 连续权重（`-Oz` / `-Os` / `-Ot` 档）

- **证据**：IAR 把 `-z0..9` / `-s0..9` 做成连续权重（0–2 Debug / 3 Low / 4–6 Medium / 7–9 High），
  AC5 是 `-Ospace`/`-Otime` 二元。
- **arkc 落点**：不给每个 pass 加参数，先加**一个全局权重**（`g_config.size_weight` 0..9），
  由内联阈值、展开倍数、合并门槛三处读取。这样"偏小但不牺牲太多速度"的中间地带可调。
- **注意**：这是**接口级**改动，会改所有读它的 pass 的行为，必须在 P1/P3 都稳定后单独一轮，
  并且要给出"权重不写时逐字节等于 0.9.x"的判据。

## 3 与阶段表的关系（裁切的两个层次）

| 层次 | 手段 | 关掉时的保证 |
| --- | --- | --- |
| 编译期 | `ARKCC_FEATURE_*` | 代码与字符串整块消失；阶段表保留编号但 `built_in=0`；选项以 `C3900U` 拒绝 |
| 运行期 | `--<pass>` / `-fno-<pass>`、INI 键 | 产物与不含该 pass 的构建逐字节相同 |
| 剖面 | `--pipeline=lite` | 贵阶段被跳过并留下原因；`full` 与不写逐字节相同 |

三条都要有门禁覆盖：**能被关掉** 与 **关掉后真的没留下痕迹** 是两件事。

## 4 已知欠账（与优化无关，登记在案）

见 `docs/BOARD_VALIDATION.md` §8：每语句约 1.3 KB arena、长 `double` 字面量差 1 ulp、
板端未上传 `aeabi_float.c`、串口 RX 偶发丢字节、`pyocd -m` 需固定 cwd。
优化线不碰这些，但**它们会限制优化的验证方式**（例如板端跑不动大函数的全展开）。
