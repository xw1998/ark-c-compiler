# `-fopt-voldmb`：省掉没人能观察到的 volatile 屏障

[English](VOLDBM.en.md) | 中文

> 一句话：对**帧局部** volatile 对象的访问，`arkcc` 会发一对 `DMB SY`（前置 + 后置）。如果
> **本函数从不取该对象的地址**，帧外没有任何人能命名它，屏障没有任何可观察效果，纯开销。
> 本 pass 按对象名做地址逃逸分析，把这些成对的屏障删掉。HAL 全语料少 **170 条指令（−1.38%）、
> 616 字节（−1.88%）**，`bigger TU 0`。
>
> **判决：落地，默认关闭。** 这是本轮唯一「用了确定更大的开销换确定收益」的确定项。
> 旗标默认关闭、STM32_MIN 构建里裁掉（按名拒绝 `C3900U`）。

---

## 1 成本从哪来

HAL 里到处都是这个惯用法：

```c
__IO uint32_t tmpreg;          /* __IO = volatile */
tmpreg = RCC->CR;              /* 读外设 */
RCC->CR = tmpreg;              /* 写回 */
```

`tmpreg` 是帧局部 `volatile`。按 C 抽象机，对它的每次访问都是可观察副作用；`arkcc` 保守地
为每次访问发一对 `DMB SY`（读前 + 读后，写前 + 写后）。统计 12,304 条语料：

| 量 | 读数 |
|---|---|
| `DMB` 总数 | **139** |
| 紧邻 `[r6` 帧访问的 | **138（99.3%）** |
| 全局 volatile（外设寄存器，经指针访问）发出的 | **0**（本来就不发） |

即：95% 以上的 `DMB` 都花在「`__IO` 局部量」这一个惯用法上，每对 8 字节。

## 2 为什么可以删

`DMB` 只约束**内存事务对其他观察者的可见顺序**。帧局部的地址只有本函数知道，本函数又不取它的
地址 ⇒ 没有其他 observer（另一个核、DMA、外设）能命名它 ⇒ 顺序约束是空约束。

交叉验证：`armcc -O2`、`armclang -O2`、`IAR iccarm -Ohs` 在这个惯用法上**都不发任何屏障**。

## 3 实现：按对象名做逃逸分析

帧偏移无法表达「这个对象占多宽」（`&s` 的 extent 未知），所以**不用偏移区间**，改用名字：
`irgen.c` 在发 `IR_PUSH_ADDR` 时已经带上了被取地址的对象名（`node->u.name`）。

- 同函数内存在 `&name` ⇒ `name` 的屏障**全部保留**；
- `IR_PUSH_ADDR` 的 name 为空（无法归属）⇒ 置 `vdm_blind`，**整个函数保留全部屏障**；
- 否则该对象的 volatile 访问可以省掉 DMB 对。

四个发射点（均在 `codegen_arm()` 内）统一加守卫 `if (is_volatile && !vdm_elide(I->name))`。
**只删不插**，且判决是「能证明才删」，证明不了就整函数退回。

## 4 实测

四臂 95 TU：

| 臂 | insns | bytes |
|---|---|---|
| base | 12,304 | 32,690 |
| `-fopt-frame` | 12,275（−29） | 32,606（−84） |
| `-fopt-voldmb` | **12,134（−170，−1.38%）** | **32,074（−616，−1.88%）** |
| both | **12,105（−199）** | **31,990（−700）** |

所有臂 `bigger TU 0`；both 臂 `smaller TU 16 / identical 79`。
170 条 ≈ 139 条 `DMB` 的两个方向合计（部分函数因 `&` 逃逸保留），与统计口径自洽。

## 5 与 `-fopt-copyprop` 的交互（安全）

`copyprop` 用 `DMB` 作为「volatile 访问的屏障判据」。省掉 `DMB` 后它可能把 volatile 局部量的
值前送。**这仍然正确**：本 pass 的判据正是「地址未逃逸」⇒ 无人可观察 ⇒ 前送无副作用。
两条安全条件在这里合一。

## 7 已知缺口（现存，不是本 pass 引入）

`volatile` **结构体成员**访问（`s.v`）本来就不发 `DMB`（探测夹具实测 0 个屏障）。也就是说
「volatile 成员访问缺少屏障」是 `arkcc` 更早的一个保守性缺口，方向是**少发**而不是多发——
与「宁可报错不给错答案」的纪律存在张力，已登记，未在本轮处理。

## 8 未做 / 已知限制

- 未做「跨函数」逃逸分析（`static` 帧量被取地址传出去的情形仍保守保留）；
- `IR_PUSH_ADDR` 名字为空的整函数退回（保守，宁可少做）；
- Linux 宿主未实跑；STM32H743 仅 `--layout both` 构建通过，未上板。
