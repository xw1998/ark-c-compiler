# 操作数分配（S3 预注册）：从「每个中间值都过一次内存」到「留在寄存器里」

> 状态：**预注册，未实现**。本文先把语料现状量清楚（§1）、把「文本层已经没得吃」这件事
> 定量写死（§2）、把第一个切片 S3a 定义到可验证的粒度（§3）、并把它与既有
> `-fopt-regalloc` 的**寄存器与帧冲突**摆上台面（§4），最后冻结判据与否证线（§5–§7）。

1. 剩下的 18,665 条指令到底由什么构成（§1）；
2. 为什么继续写文本规则不会有用（§2）；
3. 下一步的**第一个可验证切片**是什么，它值多少条（§3）；
4. 它与既有 `-fopt-regalloc` 抢同一批寄存器和同一段帧，怎么排（§4）；
5. 什么算成功、什么算失败（§5–§7）。

## 2 为什么文本层已经没得吃

三件事已经做完，且都用冻结判据量过：

| 线 | 拿到 | 判决 |
| --- | ---: | --- |
| 十二个文本开关（P7–P14） | 47,885 → 19,066 | 落地 |
| `-fopt-cmat`（P16） | 19,066 → 18,729（−1.77%） | 落地 |
| `-fopt-slotreg`（P17） | 18,729 → 18,665（−0.34%） | **收档**（< 0.5% 否证线） |

`-fopt-slotreg` 的教训是决定性的：不带安全闸时它能删到 −1.82%，但那 1.8% 的每一条都由
**文本层看不见的间接读写**撑着（`c = k ? a : b` 的两次 `STR` 由 `memcpy` 在内部读），
实测直接造成 5 个执行级 failure。文本层能安全拿到的是 0.34%，其余全部堵在
「谁还在读这块内存」这个问题上，而这个问题在文本层**没有答案**——只有 IR 层有。

所以下一步不是再删，而是**不要再产生这些指令**：让 IR 的值直接活在机器寄存器里。

## 3 切片 S3a：函数级 32 位常量缓存（callee-saved）

### 3.1 为什么从常量开始

`MOVW` + `MOVT` 合计 2,096 条（11.2%），是单一家族里最大的一块，而且它的语义最干净：
**一个 32 位常量一旦材料化进某个寄存器，只要那个寄存器不被改写，它就一直在那里。**
这不需要活跃性分析，只需要「寄存器 == 常量」这条块内/跨块事实。

实测（同一语料，按函数切分，键 = `MOVW` 的操作数字符串，**含目的寄存器**，因此这是保守口径）：

| 项 | 数值 |
| --- | ---: |
| `MOVW` 总条数 | 1,115 |
| 其中「同一函数内同一 `MOVW` 形态再次出现」 | **657**（59%） |
| 有重复的函数 | 约 70 个（占比小、但重复集中在少数大函数上） |

### 3.2 规则

> 若一个 32 位常量 `K` 在函数内被材料化 `c` 次（`c ≥ 3`），把它材料化一次到一个
> **callee-saved** 寄存器 `rC`（`r8`–`r11` 之一），其余 `c − 1` 次改为 `MOV rD, rC`。

账：原来 `2c` 条；改后 `2 + (c − 1)` 条 ⇒ 净省 `c − 2` 条；另付 `PUSH`/`POP` 各一次
（`rC` 是 callee-saved，必须保存，2 条）。所以**净收益 = (c − 2) − 2 = c − 4**，
门槛 `c ≥ 5` 才划算——`c = 3` / `c = 4` 打平或亏，不选。

### 3.3 实测上界（乐观口径）

用「每个重复常量都按 `c − 4` 计收益、且最多 4 个缓存寄存器」的模型在同一批 `.s` 上算：

| 模型 | 净省条数 | 占 18,665 |
| --- | ---: | ---: |
| 缓存寄存器不限个 | **399** | 2.1% |
| 缓存寄存器限 4 个（`r8`–`r11`） | **193** | 1.0% |

两个数都是**上界**：模型假设没有额外的 `MOV`、且每次复用都真的命中。真实值一定更低。
按 P17 的经验（文本层上界 0.7% → 实测 0.34%），S3a 的实测很可能落在 **1–2%**。

### 3.4 为什么仍然值得做（而不只是那 1–2%）

因为它是 S3b 的**地基**：S3a 必须解决的三件事，正是「让值活在 callee-saved 寄存器里」的全部难点：

1. 在 `r8`–`r11` 里放一个不是帧槽的东西（既有 `ra_` 只会把**帧槽**提升到 `r8`–`r11`）；
2. 加宽 `PUSH`/`POP` 并把**所有偏移平移**（既有 `ra_` 有这段代码，`tests/run_regalloc_tests.py` 覆盖）；
3. 保证 8 字节对齐（`ra_` 已经会用「一个备用寄存器」补奇数个保存字）。

S3a 一旦跑通，S3b（跨调用点的活跃值进 callee-saved 寄存器）只是**换一个消费者**，不用再动帧。

## 4 与 `-fopt-regalloc` 的冲突（必须先解决，否则不要开工）

这是写本文件时读 `ark_regalloc_function()` 读出来的真问题，不是假想：

| 冲突 | 事实 | 后果 |
| --- | --- | --- |
| 抢寄存器 | `ra_` 默认档在 HAL 上一个槽都不选，`-fopt-regalloc-near` 才会选，且用的是 `r8`–`r11` | 两个 pass 同时要同一组寄存器 |
| 抢帧 | 两者都要加宽 `PUSH`/`POP`，都要**平移所有偏移** | 谁先跑谁定 `extra`；后跑的那个必须知道前面多存了几个字 |
| 抢顺序 | `ra_` 的平移代码只认「自己加的那一段」 | 两个 pass 各加一次 = 偏移被平移两次或漏平移 |

**解法（写死，实现时按这个来）**：S3a 不自己加宽 `PUSH`/`POP`，而是**先问 `ra_` 要结果**——
把 `ra_` 已经选出的 `made[]`/`extra` 暴露出来，S3a 只从**剩下的**寄存器里挑，
并且在 `ra_` 的加宽里**顺带**多存自己需要的寄存器（`extra` 一次性算完，偏移只平移一次）。
也就是说：**`PUSH` 加宽与偏移平移只允许有一个所有者**，S3a 是它的第二个客户。

若实现中发现必须让 S3a 自己加宽，那么本切片**降级为不做**——两个 pass 各自平移偏移是
误编译的高发区，不值得为 1–2% 冒这个险（对应「宁可报错，不给错答案」）。

## 5 判据（冻结，实现前不改）

`tests/run_operand_alloc_tests.py`，`make test-opalloc`：

1. **OFF IS OFF**：不带旗标时 95 TU 语料逐字节相同；
2. **只减不增**：每个 TU 的指令数 `on <= off`，总数严格下降；**任何 TU 变大即判红**；
3. **常量复用真的发生**：至少一个夹具里同一 32 位常量的 `MOVW`+`MOVT` 出现次数下降，
   且被替换的是 `MOV rD, rC`（而不是被删掉）；
4. **跨调用正确**：夹具里在两次材料化之间插入一个 `BL`，缓存仍然命中（callee-saved 的理由），
   且被调用者返回后值仍正确；
5. **不抢 `ra_` 的寄存器**：同时开 `-fopt-regalloc-near` 时，两者不重叠使用同一寄存器，
   且偏移只平移一次（用「帧偏移集合」前后对比断言）；
6. **语义**：`tests/arm_exec` 全语料 off/on 同值，另加至少 3 个新夹具
   （常量跨 `BL`、常量在循环体内、常量与 `ra_` 同时开）；
7. **裁剪**：`ARKCC_FEATURE_OPT_CONSTCACHE`（`STM32_MIN` 0），裁剪构建以 `C3900U` 拒绝旗标，
   不带旗标仍可编译。

## 6 否证条件（写死）

任何一条成立就收档，不再投入：

- 语料总指令数下降 < 0.5%（< 95 条）；
- 出现任何一个 TU 变大；
- 需要超过 4 个缓存寄存器才能过 0.5%（说明收益来自「寄存器多」而不是「常量复用」这个机制）；
- 必须让 S3a 自己加宽 `PUSH`/`POP`（即 §4 的共享方案行不通）。

## 7 S3b 的方向（本文件只登记，不预注册）

若 S3a 过线，S3b 的对象是**跨调用点的活跃值**：值栈（`[r5, ...]`，1,414 条）与帧
（`[r6, #n]`，1,879 条）里的临时值，若在一个函数里跨越 `BL` 后仍要读回，就应当留在
callee-saved 寄存器里。它的账比 S3a 难得多（需要活跃区间、需要溢出策略），
因此**必须在 S3a 的门禁与帧机器跑通、并且实测过 S3a 的净收益之后**再单独预注册。
本文件不为 S3b 冻结任何数字。

## 8 实施与实测（2026-11-23，S3a 已落地）

### 8.1 在哪实现

`-fopt-constcache` 不是独立 pass，而是 `ark_regalloc_function()` 里的**第二个客户**——§4 写死的
「`PUSH` 加宽与偏移平移只允许有一个所有者」由此成立：`extra` 一次算完、偏移只平移一次、
`PUSH`/`POP` 只改一次。

- **常量普查**在选槽之前对同一段文本扫一遍：`MOVW`+`MOVT` 相邻、目的寄存器相同才算一对，
  键是 `(lo, hi)`；`.arkdata` / `.arkdatasym` 之后的对子是链接期重定位的地址而**不是数字**，
  整键 poison（不缓存），同函数里的其它键照常。
- **选配顺序**：`ra_` 先选槽（`made[0..nregs)`），常量只从剩下的 `r8`–`r11` 里取，且要求该
  寄存器**在函数原文本里完全不出现**（保守；误判只损失一个寄存器）。寄存器总数仍受
  `RA_MAX_REGS`（4）限制。
- **收益账** `Σ(count−1)`：材料化 `c` 次是 `2c` 条，入口建一次加每个使用点一条拷贝是 `2+c`。
  把保存块从「没有保存寄存器」变成「有」要多付一次加宽的 `PUSH`+`POP`（2 条），只在原
  `nregs == 0` 时计入；不够本就整组退回，函数绝不因此变大。
- **材料化放在入口**（`PUSH` 之后、`SUB sp` 之前），不放首次文本出现处——后者可能落在分支里，
  不满足 dominance。
- 奇数个寄存器补一个备用寄存器，保证保存块是 8 字节的整数倍（AAPCS 在每个 `BL` 处要求）。

### 8.2 实现中暴露的既有缺陷（已修）

`ra_` 认 prologue 用的是**前缀**匹配 `"PUSH {r5"`。值栈的 `PUSH {r5}`（压一个值）正好命中，
于是函数**中段**的压栈被当成帧保存加宽、入口材料化被插到函数中间；同时 vstack 的 r4 形态
`PUSH {r4, r5, r6, r7, lr}` 反而匹配不到（这也是它以前从没被 `ra_` 改坏的原因）。

修法是**整串比较**：去掉空格后必须恰好等于 `PUSH{r5,r6,r7,lr}`；epilogue 同理
（`POP{r5,r6,r7,pc}` 或 `POP{r5,r6,r7,lr}`）。`PUSH` 只改第一处（真正的帧保存），
`POP` 的每个返回路径都改（它们都得恢复同一个加宽后的块），并且尾部元素（`pc}` / `lr}`）
原样接回而不是在这里重新选。

**代价与边界**：`vstack` 的 r4 形态 prologue 本 pass **主动不接管**——它多带一个填充字，
加宽会破坏 8 字节对齐。因此被 vstack 改写成 r4 形态的函数整函数弃权：收益少一点，
但绝不会碰错。这是有意接受的保守，不是遗漏。

### 8.4 判决：落地（不过否证线）

§6 四条否证一条都没成立：−0.85% 高于 0.5% 线、无 TU 变大、只用 ≤4 个寄存器、
**没有让 S3a 自己加宽**（§4 的共享方案成立）。§5 七条判据的落点全部在
`tests/run_operand_alloc_tests.py`（`make test-opalloc`）里，检查项全绿；
其中「跨调用」「不抢寄存器」「偏移只平移一次」三条是拿真实生成文本断言的，不是拿 IR 推的。

S3b 仍未预注册：本切片打通的是「把非帧槽的东西放进 `r8`–`r11`」「加宽保存块并只平移一次
偏移」，而 S3b 还需要活跃区间与溢出策略，按 §7 单独预注册。
