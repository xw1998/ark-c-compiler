# 块尾合并（`--tailmerge`，阶段 `ir.tailmerge`）

> 0.9.1 的第一条优化。它做的事只有一句：**当多个基本块以完全相同的指令序列收尾时，
> 只留一份，其余块改成跳到它前面的一条跳转**。
>
> 源码：`src/opt_tailmerge.c`　门禁：`tests/run_tailmerge_tests.py`（`make test-tailmerge`）
> 阶段位置：**13 → 14**，在 `ir.const-global` 之后、`ir.vectorize` 之前
> （见 `docs/PASS_PIPELINE.md`）

---

## 1. 为什么要在这个位置

内联把被调方的函数体搬到调用点，常量传播把读 `const` 全局的指令折成立即数。两者都会造出
「若干块以同一串指令收尾」的形状：

```c
int f(int a, int b) {
    if (a) { ...; b *= 3; b ^= 5; b += 11; return b + 7; }
    else   { ...; b *= 3; b ^= 5; b += 11; return b + 7; }
}
```

两分支只有上半天差地别，下半天一模一样。块尾合并紧跟在这两步之后，正好清掉它们造出来的
重复；再往后只剩 `ir.vectorize` 与后端，没有别的 pass 会再造这种重复。

逆向依据（`c_compiler/iar/docs/07-crossjump-and-tbaa.md`）：AC5 的 `CrossJumps`、
IAR 的 `intracrossjump` 都是这个作用，且实测「共享 1/2/3/5 条语句分别省 8/16/24/40 B」
——**小 N 就有正收益**，这正是它值得作为第一条优化落地的原因。

## 2. 五条规则（每条都有反例或代价在背后）

| # | 规则 | 为什么 |
| --- | --- | --- |
| 1 | 匹配是**逐指令相同**（op / val / aux / aux2 / name 全等），不是语义等价 | AC5 的 `cj6.c` 实验：两个尾部只差寄存器（`r1` vs `r0`）就**不**合并。要放宽就必须先有一份等价性证明，本 pass 没有 |
| 2 | 只合并**求值栈深度为 0**的尾段 | IR 是栈机。跳进一个栈非空的点，等于把求值栈当作状态跨控制流边携带——后端没有作过这个承诺。深度 0 就是语句边界，要求它不花任何代价 |
| 3 | 尾段长度 ≥ `ARK_TAILMERGE_MIN_LEN`（默认 3） | 每多一个入口就多付一条 `JMP`。两三条指令的尾巴合并后省不回跳转本身；但阈值不靠注释自证，门禁打印真实字节账 |
| 4 | 一轮只做一次最优合并，然后**重建 CFG** | 与 `opt_licm_func` 同型。合并把某块的尾段换成一条跳转，它周围的块边界都变了；重推图比修补图便宜得多也更难错。轮数以代码长度为上界，天然带终止护栏（对应 IAR 的 `Jump size optimization will not terminate!`、AC5 的 `need another pass`） |
| 5 | 深度模型不成立就**整函数放弃**，不是跳过那一块 | 半对的控制流比不优化更糟。触发条件：标签入口出现两种深度、出现本 pass 没有栈效应的 opcode、内联汇编、负深度 |

## 3. 算法

```
loop:
  mir_build(f)                      # 重建基本块图
  栈深度定点分析（块入口深度 + 逐指令前深度）
  if !ok: return                     # 规则 5
  每块取候选尾段：块内**最后一个**深度为 0 的位置，排除标签，长度 ≥ MIN_LEN
  按 (长度, 逐指令相同) 分组；取总和节省最大的一组：
      节省 = (成员数 - 1) × (尾段长度 - 1)
      （成员数 - 1 条尾段变跳转，每条被删掉 len - 1 条指令）
  if 无组: return
  重写：在被保留的尾段前插一条新 IR_LABEL，其余成员的尾段整段换成一条 IR_JMP
```

几个容易写错的点：

- **尾段起点必须取块内最后一个深度 0 的位置**。取第一个会把「两分支本来不同的上半段」
  一起拖进候选，于是两个本可合并的分支看起来不可合并（第一版就是这么错的，门禁里的
  `merge.c` 立刻暴露）。
- **标签永远不属于尾段**。复制标签等于给同一个跳转目标做第二份定义，所有跳转仍会瞄准
  原来那份；而 `IR_LABEL` 的 id 在 `val` 里，逐指令比较又恰好会要求 id 相同——
  两者叠加会让「带标签的尾巴」永远匹配不上，所以干脆在候选阶段排除。
- **`IR_CMP_JMP_EQ` 直接判为不安全**：这是 0.2.x 的 opcode，irgen 已不再发射，而
  **两个后端对「未命中边是否 pop」的读法不一致**（ARM 无条件 pop，C 后端只在命中时 pop）。
  在这个分歧被统一之前，本 pass 不替任何一方下注。

## 4. 裁剪（三层，默认关时零变化）

| 层次 | 手段 | 关掉时的保证 |
| --- | --- | --- |
| 编译期 | `ARKCC_FEATURE_TAILMERGE`（`include/arkcc_config.h`） | STM32_MIN 剖面或无 MIR 的构建 ⇒ 0，`src/opt_tailmerge.c` 整个函数体消失；阶段表保留编号但 `built_in = 0`，**不引用符号**（否则裁剪构建链接失败） |
| 运行期 | `g_config.enable_tailmerge`，`--tailmerge` / `--no-tailmerge`，INI `tailmerge=` | 默认 0。不打开时该文件被链接但从不进入，产物与「不含这个 pass 的构建」**逐字节相同**（门禁实测对象哈希相等） |
| 剖面 | `--pipeline=lite` | `ir.tailmerge` 的 `min_profile` 是 `full`，lite 剖面跳过并留理由 |

裁剪构建**拒绝**选项而不是装作优化：`-DARKCC_FEATURE_TAILMERGE=0` 时
`--tailmerge` 以 `C3900U` 报错并指名该宏（命令行与 INI 两条路径都有守卫）。

## 5. 门禁

`tests/run_tailmerge_tests.py`，23 项检查，五个问题各自可单独失败：

1. **静态**：开则汇编真变（出现新标签 `.L_<func>_N` 与被丢弃分支的 `B` 到它），关则相同。
2. **负例**（开关开了也必须一模一样）：末条语句不同 / 相同后缀起始于栈深 1 /
   后缀短于下限 / 函数含内联汇编。
3. **选择性**：同一个 `.c` 里既有可合并函数、也有深度 1 形状的函数，
   只允许前者多出标签——这条是为了排除「整个文件其实没跑过 pass」的假绿。
4. **动态**：ARM 模拟器上开关前后返回同一值，且该值非平凡。
5. **字节账 + 防假绿**：对象严格变小并打印前后字节数；默认关闭；`--no-tailmerge`
   能退回默认产物；`-O0` 产物逐字节不变；`--print-pipeline` 如实显示 run / skip 与
   `needs a higher -O level`；INI 键生效；裁剪构建拒绝选项且默认对象仍与完整构建相同。

## 6. 实测（0.9.1，宿主 gcc / MinGW）

| 用例 | 读数 |
| --- | --- |
| `merge.c`（两分支共享 `return b + 7;`，另有三路同尾的 `tail3`） | 汇编指令行 481 → 448；对象 1146 → 1086 B |
| `neg_depth.c`（相同后缀起始于栈深 1） | 开关前后汇编逐字节相同 |
| `neg_asm.c`（函数含 `__asm`） | 触发规则 5，整函数放弃，逐字节相同 |
| `-O0 --tailmerge` | 产物与关闭时逐字节相同 |
| `-DARKCC_FEATURE_TAILMERGE=0` | 拒绝 `--tailmerge`（`C3900U` 指名宏）；默认对象与完整构建哈希相同 |

## 7. 刻意没做的事（以及做之前必须补什么）

- **不做跳距重算**：IR 没有变长编码，`JMP` 只有一种宽度，所以 AC5 的
  「跳距变化 ⇒ 再跑一趟」在这里没有对应物。真到机器层再谈。
- **不把共享块搬到「最便宜的位置」**：AC5 有 `BLKLIFTABLE` / `on_savepath` 两条块级自检，
  会挑一个入口最少、布局最省的位置放置共享尾巴。本 pass 直接把标签放在**被保留的那一份**
  前面，少一层推理，代价是偶尔多几条长跳转——等真正量到再说。
- **不做跨过程（cross-call）**：见 `docs/OPTIMIZER_PLAN.md` P5，理由写死在那里。
- **不做整块重复（P4）**：同一个匹配器，只换候选生成器，等本条稳定后再开。
