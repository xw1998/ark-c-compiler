# 除常数 → 乘魔数 + 移位（`--divconst`）

> 0.9.1 的第三条优化。一句话：**除数在编译期已知时，把 `SDIV`/`UDIV`（或对
> `__aeabi_idiv` 的调用）换成「乘一个魔数 + 右移」**。ARM 没有硬件除法，一次
> `/ const` 从 20+ 周期掉到 3–6 周期。
>
> 实现位置：`src/backend/arm/backend_arm.c`（**发射期**，不是新的 pass）
> 门禁：`tests/run_divconst_tests.py`（`make test-divconst`）
> 开关：`--divconst` / `--no-divconst`，INI `divconst=` / `div-const=`

---

## 1. 为什么放在发射期，而不是新增一个 pass

判定依据只有一件事：**除数是不是常量**。在 IR 里它表现为
`IR_PUSH_INT c` 立刻后跟 `IR_DIV` / `IR_MOD`——因为 irgen 把 `x / 3` 编成「压 c、压 x、相除」。
于是发射期看一眼下一条指令就知道，不需要改 IR、不需要改 4 个后端、不需要在 `irser` 里
加字段。

代价是**不能用 MIR 的寄存器分配结论**：序列自己在 r0–r3 上做算术。这正是本后端既有的做法
（栈机模型 + `emit_push_r0/pop_r0` 搬运），风险可控。

负常数还有一层：`x / -5` 的 IR **不是** `PUSH_INT -5`，而是

```
IR_PUSH_INT 5      ; val = 5
IR_UNARY           ; aux = TOK_MINUS, val = 0  （32 位取负）
IR_DIV
```

所以前瞻要看得更远：`at = 1`（下一条就是 DIV/MOD）或 `at = 2`（下一条是 32 位取负的
`IR_UNARY`，再下一条是 DIV/MOD）。命中第二种时把除数翻成 `0u - dv`（回绕正好给出负的位模式），
并用计数器 `divconst_skip` 跳掉那条取负指令——否则它会把栈顶的除数当成被除数取负。

## 2. 数学：无符号魔数

给定无符号除数 `d ≥ 2`，取

```
L = ceil(log2 d)          ; 最小的 L 使 2^L >= d
m = ceil(2^(32+L) / d)
e = m*d - 2^(32+L)        ; 恒有 0 <= e <= 2^L
```

那么对任意 `0 <= n < 2^32`，`floor(n/d) = floor((n*m) / 2^(32+L))`。两种形状：

| 形态 | 条件 | 序列 |
| --- | --- | --- |
| 移位 | `d` 是 2 的幂 | `LSR r0, r0, #log2(d)` |
| 乘 | `m < 2^32` | `UMULL r2,r3, r0, m` → `LSR r0, r3, #L`（`r3` 是乘积高 32 位） |
| 加（add 形） | `m >= 2^32` | `t = mulhi(n, m-2^32)`；`q = (t + ((n-t) >> 1)) >> (L-1)` |

add 形的推导是标准的：`m >= 2^32` 时 `mulhi(n, m)` 会溢出，所以改乘 `m - 2^32` 再补回
那一位的贡献（`t + ((n-t)>>1)`）。

**`L == 32` 的特例**：`2^(32+L) = 2^64` 不可表示，`m = ceil(2^64/d)` 也放不进 64 位中间量。
此时令 `m = (2^64 - 1)/d + 1`、`e = m*d`（`m*d` 在 64 位无符号里回绕，回绕值正好是误差项），
仍走 add 形。`d > 2^31` 的除数是这条路的常见触发者（门禁用 `3000000000u` 覆盖）。

无符号余数：`r = n - q*d`；若 `d` 是 2 的幂则直接 `AND r0, r0, #(d-1)`。

## 3. 数学：有符号用幅值法

有符号不走签名魔数（那要另一套误差证明），而是**归约到已穷举验证的无符号结论**：

```
sign = n >> 31 (算术)   ; 0 或 -1
|n|  = (n ^ sign) - sign
q'   = |n| / |c|        ; 走上面的无符号序列
q    = (q' ^ s) - s     ; s = sign，若 c < 0 则 s = ~sign（MVN 一条指令）
r    = n - q*c          ; 余数用**原始除数**算，符号随 n，天然符合 C99 的截断语义
```

- `c < 0` 只翻符号寄存器（`n / -d == -(n/d)`、`n % -d == n % d`），不用单独再取负。
- `n = INT_MIN` 自动正确：`|n| = 0x80000000` 作为无符号是合法的 2^31，无符号序列照算；
  取负回 `INT_MIN` 时回绕回原位，正是 C 的期望值。
- 余数走 `q*c` 而不是掩码：负数的 `% 8` **不是** `n & 7`（门禁里 `m8` 一条专门盯这个，
  第一版实现写错成掩码，被这一条抓出来）。

数学部分在写代码之前先用 Python 全量验过：无符号 9,150,609 组 `(d, n)`、有符号
4,030,257 组（含 `INT_MIN`、负除数、负的 2 的幂）**0 失败**。

## 4. 拒绝清单（拒绝即逐字节不变）

| 拒绝 | 原因 |
| --- | --- |
| `c == 0` | 除以零是 UB；保持既有行为（真的发除法，交给运行时/硬件） |
| 无符号 `c == 1` | 无事可做，但也别把 `UDIV` 换成空序列（会与拒绝混在一起说不清） |
| 有符号 `c == 1` | 同上 |
| 有符号 `c == -1` | `INT_MIN / -1` 溢出（UB），幅值法在 `|n| = 2^31` 那一步会给出错值 |
| 有符号 `|c| == 2^31` | `|c|` 无法表示为正的 int32 |

拒绝形状的门禁判据是**整文件逐字节相同**（不是「没看到魔数」）：把开关打开重编，
与关掉时那份 `.s` 做 SHA 比较。

## 5. 发射序列（实测，`-O2`）

有符号 `x / 3`：

```asm
    POP  {r0}              ; 被除数
    ASR  r1, r0, #31
    EOR  r0, r0, r1
    SUB  r0, r0, r1        ; |n|
    PUSH {r1}              ; 存 sign
    MOVW r1, #21846
    MOVT r1, #21845        ; m = 0x55555556
    UMULL r2, r3, r0, r1
    SUB  r2, r0, r3
    LSR  r2, r2, #1
    ADD  r2, r3, r2
    LSR  r0, r2, #1
    POP  {r1}
    EOR  r0, r0, r1
    SUB  r0, r0, r1        ; q
    PUSH {r0}
```

有符号 `/ 8`（2 的幂）中间只剩一条 `LSR r0, r0, #3`；有符号 `% 3` 在 q 之后多
`MOV r2, #3` / `MUL r0, r0, r2` / `SUB r0, r1, r0`。

无符号 `/ 7u`：`MOVW/MOVT` 装 `m`、`UMULL r2,r3`、`SUB`/`LSR #1`/`ADD`/`LSR #2`。
无符号 `/ 8u` 只有 `LSR r0, r0, #3`；无符号 `% 8u` 只有 `AND r0, r0, #7`
（掩码 > 255 时改 `MOV r1, #mask` + `AND r0, r0, r1`）。

两点实现细节：

- **内部汇编器只接受 `MUL Rd, Rn, Rm` 中 `Rd == Rn` 的 16 位形态**，所以余数序列写成
  `MUL r0, r0, r2` 再 `SUB r0, r1, r0`，不能写 `MUL r3, r0, r2`。
- `MVN r1, r1` 是负除数唯一的一条额外指令；它必须在 `PUSH {r1}` **之前**做，否则存进去的
  仍是旧符号。

## 6. 裁剪（三层，默认关时零变化）

| 层次 | 手段 | 关掉时的保证 |
| --- | --- | --- |
| 编译期 | `ARKCC_FEATURE_DIVCONST`（`include/arkcc_config.h`，`STM32_MIN` ⇒ 0） | 前瞻块与发射函数整块消失，`divconst_live` 恒 0，DIV/MOD 的 `if` 折叠掉 |
| 运行期 | `g_config.enable_divconst`，`--divconst` / `--no-divconst`，INI `divconst=` | 默认 0；默认产物与「不含该特性」的构建逐字节相同（门禁实测） |
| 剖面 | （无需） | 发射期优化，不在 `--pipeline` 阶段表里 |

裁剪构建**拒绝**选项而不是装作优化：`-DARKCC_FEATURE_DIVCONST=0` 时 `--divconst` 与 INI
`divconst=1` 都报 `C3900U` 并指名该宏。

裁剪的实测代价（宿主 gcc 4.8.0 `-O2`，只编 `backend_arm.c`）：`.text` 93376 → 95056 B，
即**这个特性占 1680 B 代码、0 B 数据**；符号表 186 → 189（新增的是四个 static 函数里
未被内联的 3 个，无新增外部符号）。板端工程 `mdk/STM32H743_ArkCC` 用
`ARKCC_PROFILE_STM32_MIN`，发射期代码整块不编进去（UV4 重建 0 Error）：`Code=182820 -> 182824`、`ZI-data=37136 -> 37140`，
多出的 4+4 字节来自 config 层——INI 键 `divconst=` 与 `--print-config` 多打一项，这两处不受特性宏保护（与 `tailcall` 同型）。

## 7. 门禁（`tests/run_divconst_tests.py`，45 项）

六组，每组可单独失败：

1. **静态形状**：常量除法的 TU 里 `SDIV`/`UDIV` 计数为 0，且 16 个用例各自命中自己那条
   形状标记（`add form` / `shift` / `mask` / `q*d` / `flips the sign register` / `L == 32`）。
2. **单 TU 选择性**：同一个文件里常量除法被改写、变量除数（`SDIV`/`UDIV`）原样保留——
   排除「整个文件其实没跑过」的假绿。
3. **拒绝形状逐字节相同**：五个被拒的常数 + 无符号 `1u`，开关前后 `.s` 完全一致。
4. **执行三方一致**：16 个常数除法 × 66 个被除数（±`INT_MIN`/`INT_MAX`/255/256/65535/
   123456789 等 + 30 个 LCG 值），在模拟器上跑出 checksum，与「开关关掉」和「Python 精确
   模拟 C 截断除法」三方相等；并断言 checksum 非平凡。另跑 `--reg-top`、`--divconst
   --reg-top`、`--divconst --tailcall` 三种组合，checksum 必须仍是同一个。
5. **防假绿**：默认关闭（产物逐字节相同）、`--no-divconst` 能退回、裁剪构建拒绝选项且
   默认产物与完整构建相同、INI 键生效。
6. **字节账如实报告**：打印对象与指令行的前后数字，两个方向都报；只对「无符号 2^k」的
   除法与余数断言**变短**，其余不做「优化一定变小」的假承诺。

## 8. 实测（0.9.1，宿主 gcc + 模拟器，`Cortex-M7`）

| 读数 | 值 |
| --- | --- |
| 门禁项 | 45 项全 PASS |
| 执行 checksum | `0x40F32C43`（off / on / Python 三方一致） |
| 组合 `--reg-top` / `--tailcall` | 同一 checksum |
| 对象体积（16 个常数除法的 TU） | 4293 → 4533 B（**+240 B**） |
| 指令行 | 1743 → 1836（**+93 行**） |

体积变大的原因说清楚：`SDIV`/`__aeabi_idiv` 调用是 2–4 字节，魔数序列是 8–12 字节。
本优化换的是**周期**不是**字节**——只有 2 的幂那两个形状同时变小。要同时收体积，
得配合 P4（块级重复块消除）或后续的 `--size` 权重（P6），不在本条里假装。

## 9. 与路线图的差异（如实记录）

- 路线图原写「`ir.divconst`（一个新的 IR pass）」。实现落在**发射期**：IR 里没有 mulhi
  这个概念，做 pass 要改 4 个后端 + `irser` + `MIR`；发射期可以直接发 `UMULL`。
- 路线图原写「有符号用 round-up 修正」。实现改用**幅值法**：正确性直接继承无符号的
  穷举结论，`INT_MIN` 与负除数都不用单独证明。
- 与本仓库既有优化一致，**没有加 `-O` 级别闸门**：显式 `--divconst` 就是意图表达。
  因此 `docs/OPTIMIZER_PLAN.md` 标题里的 `-O2` 只在「默认流水线」意义上成立，以本文为准。

## 10. 刻意没做的事

- **64 位除法不做**：`long long / const` 走 `__aeabi_ldivmod`，要 64×64 乘法与 128 位中间量，
  收益与论证成本都另算一轮。
- **浮点不做**：`double / const` 的正确舍入要求更多证明（且板端无 FPU）。
- **其它后端不做**：x86-64 与 RISC-V 有硬件除法，`--divconst` 在那里是无害空操作。
- **不做 `d == 0` 的编译期报错**：那是诊断（`-Wdiv-by-zero`）的事，不是优化的边界；
  本 pass 只保证「不改 UB 的行为」。
- **不做体积收缩的夸大**：见第 7 节第 6 组。
