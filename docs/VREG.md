# S6 预注册：IR 级虚拟寄存器分配（`-fopt-vreg`，未实现）

[English](VREG.en.md) | 中文

> 一句话：文本层能吃的已经吃完——`-fopt-cmat` −1.77%、`-fopt-slotreg` −0.34%、
> `-fopt-coalesce` −1.93%，三条都按「只删/只改名、不改模型」的纪律做完并实测收口。
> 剩下的 17.7% 帧访问、6.2% 寄存器暂存、9.7% 常量二次材料化，**不是多余的访问，是
> 「每个中间值都必须经过 r0 与帧」这个模型本身的产物**。本文件把换模型这件事先预注册：
> 判据、否证线、切片、裁切、回滚写死，实现按切片推进，每一片各自可收档。

**已冻结的判据与否证线一字不改**——这是 `docs/SLOT_REGISTERS.md` §5 与

## 1 现状度量（2026-11-23，95 个 TU，Cortex-M4，`-O2` 十五开关 + `-fopt-coalesce`）

| 项 | 值 |
| --- | --- |
| 指令数 | **18,151** |
| 函数个数（含全局标签） | 548（中位 8 条、p90 51 条、最大 `HAL_RCC_OscConfig` 3,156 条） |
| 对照 | armcc `-O2` 5,629、armclang `-O2` 5,068（96 TU 口径，见 `docs/COMPARISON.md`） |
| 差距 | **约 3.2–3.4 倍** |

指令族分类（同一语料，占 18,151 条的比例）：

| 族 | 条数 | 占比 | 谁能让它消失 |
| --- | ---: | ---: | --- |
| ALU（`ADD`/`CMP`/`AND`/`ORR`/`LSL`/`SUB`…） | 4,234 | 23.3% | 部分：操作数已直接可算的那部分由 S6a 吃掉暂存 |
| **帧访问（`[r6]` / `[r5]` 基址的 `LDR`/`STR`）** | **3,213** | **17.7%** | **只有寄存器分配** |
| 分支 / `bx` | 2,014 | 11.1% | 否（`-fopt-branch` / `-fopt-cbz` 已到底） |
| 常量材料化（`MOVW`+`MOVT` 对） | 1,754 | 9.7% | 部分：810 个完整对，只有「同函数复用」还有空间（`-fopt-constcache` 已吃 159） |
| `MOV rD, #imm` | 1,740 | 9.6% | 部分：小块常量进池寄存器后由 S6a 消化 |
| `MOV rD, rS` 暂存 | 1,120 | 6.2% | 多数：`-fopt-coalesce` 已吃 358，剩下的形状被 `BL` 与源存活挡住 |
| `PUSH` | 1,060 | 5.8% | 多数：其中 `PUSH {r0}` 741 条就是值栈往返 |
| `POP` | 731 | 4.0% | 同上（`POP {r0}` 269 条） |
| 帧指针成对出现（`MOV r6, sp` / `MOV sp, r6`） | 517 | 2.8% | 否，除非取消帧指针（已量化：可去帧的叶子函数只有 26 个） |
| 其它 `LDR`/`STR`（字面符号、`[sp]`…） | 316 | 1.7% | 否 |

**读法**：`18,151` 里能被「删一行、改个名」拿掉的已经全拿掉了
（`docs/COALESCE.md` §5 的差距解释、`docs/OPTIMIZER_PLAN.md` P17 的收档结论）。
3,213 + 1,120 + 741 = **5,074 条（28%）** 是「值必须经过内存或 r0」这一个假设的直接开销。

## 2 为什么不能再用文本层

三条已经做过的尝试，都是同一堵墙：

1. `-fopt-slotreg`（P17）：不带安全闸能删 −1.82%，但 5 个 `arm_exec` failure
   （`memcpy` 在内部间接读，文本层看不见）。带闸只剩 −0.34%，**收档**。
2. `-fopt-constcache`（P18/S3a）与 **S3b**：S3b 想省「跨调用活着的值」，
   实测 95 个 TU 里真实机会只有 **5 对 / 0.11%**，**收档**。
3. `-fopt-coalesce`（L5）：81/95 个 TU 逐字节不变，−1.93%；剩下的拷贝一律卡在
   「段内有 `BL`」或「源在段内被写」。

结论：**文本上看不见「这个值此刻在哪个寄存器里」**，所以每一条规则都必须先把
「看不见的读写」当成危险来防——防到安全时收益就没了。要有下一层收益，必须让
「值住在哪个寄存器」成为编译器里的**一等对象**，而不是事后猜。

## 3 目标模型

现在的模型（`docs/RA_VSTACK.md` §1）：IR 是栈机，发射期每个中间值 `PUSH`/`POP`，
`-fopt-vstack` 事后把相邻往返折成 r0/r5/r7 的搬运，其余落回帧。

目标模型：

```
irgen（不变） → IR（不变） → 新的 IR→文本发射器（S6） → 汇编（不变）
                                  ↑
                      虚拟寄存器 + 线性扫描 + spill
```

- **虚拟寄存器**：`IR_PUSH` 与产生值的指令在 S6 里得到一个 `vreg`，不再隐含 r0；
  栈语义由 `vreg` 编号的活跃区间表达，不再有 `PUSH`/`POP` 的机器栈含义。
- **寄存器池**：
  - caller-saved `r0`–`r3`：块内、且活跃区间不跨 `BL` 的值；
  - callee-saved `r8`–`r11`：活跃区间跨 `BL` 的值，代价是每函数一次 `PUSH` 加宽
    （与 `ark_regalloc_function()` 共用同一段保存块，**只允许一个所有者**，
    这条约束在 `docs/OPERAND_ALLOC.md` §4 已经写死）。
  - `r6` 仍是帧基址（不把它交出去：取消帧指针实测只值 0.2%）。
- **活跃区间**：按 IR 线性序 + 基本块（`src/mir.c` 已有 CFG）计算，块边界按
  succ 合并；`RETURN` / `BL` / 间接调用是切分点。
- **spill**：只在 S6c 引入；溢出到帧槽，槽位由 `alloc_local()` 同一套分配器给。
- **与 `-fopt-vstack` 的关系：二选一**（`docs/OPTIMIZER_PLAN.md` P12 S5 的原判）。
  S6 一旦并线，`-fopt-vstack` 的文本重建在同一函数上不再运行；默认保留谁由语料实测决定，
  另一条留作回退开关。

## 4 切片（每片独立门禁、独立收档）

| 片 | 范围 | 目标 | 判据重点 |
| --- | --- | --- | --- |
| **S6a** | 单个基本块内、不跨 `BL`：ALU 双操作数直读池寄存器、结果留在寄存器 | −8% 或更多（≥1,450 条） | OFF IS OFF 逐字节；任一 TU 变大即红；`arm_exec` 全量 0 failure |
| **S6b** | 跨块：线性扫描 + 区间合并（含分支菱形） | 再 −8% | 同上 + 菱形汇合处区间必须相交才算存活 |
| **S6c** | 跨 `BL`（callee-saved）与 spill | 收支为正才启用（省下的访存字节 > 加宽 `PUSH` 字节） | 收支判据必须打印；负账即不启用 |
| **S6d** | 与 `-fopt-vstack` 合并/二选一，定默认 | 无新增收益，去重 | 两条路径在全部 95 个 TU 上逐字节一致或明确更小 |

**S6a 是第一个可判的切片**，也是唯一一片允许在「只做块内」的前提下宣称独立的。

## 5 冻结门禁（实现前不改）

1. **OFF IS OFF**：`-O2` 与 `-O2 -fno-opt-vreg` 逐字节相同（95/95 TU）；
2. **只减不增**：任一 TU 指令数变大即红，不做「平均更好」的解释；
3. **默认关**：`enable_opt_vreg = 0`，INI/CLI 双向可开关；
4. **执行级同值**：`tests/arm_exec/run_arm_exec.py --extra=-fopt-vreg` 全量 0 failure，
   且每条断言仍是「程序外算出的常量」，不允许改成自证；
5. **裁剪拒绝**：`-DARKCC_FEATURE_VREG=0` 的构建以
   `Fatal error: C3900U: -fopt-vreg is not compiled into this build` 拒绝并返回 1，
   不带旗标仍能编译；
6. **板端体积**：`tools/stm32_build_check.py --layout both` 仍全 PASS（代码 + rodata ≤ 2 MB，
   `.ark_buf` 落在两个布局各自的区间内）；
7. **全量门禁**：`make test` EXIT=0（含本切片新增的 `make test-vreg`）。

## 6 否证条件（写死，触发即收档）

- **F1**：S6a 落地后总下降 **< 5%** ⇒ 收档（这一条比 0.5% 严，因为换模型本身有风险成本）；
- **F2**：任一 TU 变大 ⇒ 收档；
- **F3**：`arm_exec` 出现一个无法归因到「未实现的形状」的 failure ⇒ 收档（**宁可报错，不给错答案**）；
- **F4**：S6a 必须用超过 `r0`–`r3` 四个寄存器、或必须 spill 才能过 5% ⇒ 收档，
  退回文本层继续找（那说明块内本来就没有这么多可用寄存器）。

## 7 裁切

- `ARKCC_FEATURE_VREG`：`ARKCC_PROFILE_STM32_MIN` ⇒ 0，宿主与交叉构建 ⇒ 1，默认**关**；
- 关闭时：不运行的代码，且不改变任何既有产物（OFF IS OFF 是逐字节保证）；
- 主体是新的发射器而不是新表，因此板上裁掉它只省代码体积，不影响其它 pass。

## 8 风险与回滚

| 风险 | 处理 |
| --- | --- |
| S6a 的正确性（最难的是「栈语义 ↔ 寄存器语义」的等价） | 每个函数在 S6a 前后做一次 `memcmp` 级等价自检不成立（文本本来就该变），所以判据只能靠**执行级**：95 TU 语料 + `arm_exec` 全量 + 逐函数差分探针 |
| 与 `ark_regalloc_function()` 抢保存寄存器块 | 写死「`PUSH` 加宽与偏移平移只有一个所有者」（`docs/OPERAND_ALLOC.md` §4）；做不到则 S6c 降级为不做 |
| 长函数（`HAL_RCC_OscConfig` 3,156 条）区间爆炸 | 线性扫描按区间端点排序，O(n log n)；区间上限触发整函数弃权（回到 vstack 路径） |
| 调试可读性 | `-g` 下需要保留变量位置信息；S6 未做之前不接受「调试信息丢失」 |

回滚方式：单个旗标默认关；`--pipeline=lite` 可跳过；不删任何既有代码路径。

## 9 不承诺的事（写死，避免被读成承诺）

1. **不承诺打到 armcc `-O2` 的 5,629 条**。三条结构性差距里还有「每份 TU 自带运行时助手
   920 条（4.8%）」与「没有指令调度」两条不在本切片范围内；
2. **S6a+S6b 的中间目标**是 **12,700 条（−30%）**，不到目标就不是「near parity」，
   只是「把模型换对」；
3. 本文件不改变 `-fopt-vstack` / `-fopt-slotreg` / `-fopt-coalesce` 的任何既有判词；
4. 「换模型」是项目级决定：本预注册落地前需一次明确的启动裁定，与
   `docs/OPTIMIZER_PLAN.md` P12 的 S4/S5 条目一致。
