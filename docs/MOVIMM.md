# 一条指令装下一个常量

[English](MOVIMM.en.md) | 中文

> 一句话：旧路径对**每一个超过 255 的常量**都发 `MOVW` + `MOVT` 两条指令，其中
> `MOVT rd, #0` 是纯浪费——ARM ARM 的 `MOVW (immediate)` T3 会把 bits[31:16] 零填充，
> 那条 `MOVT` 改不动任何一位。改成按值域挑最少指令之后，同一份 95 个翻译单元的
> HAL 语料在 `-O2` 下从 **51,416 条 / 116,380 字节** 降到
> **50,965 条 / 114,576 字节**（**−451 条 / −0.88%**、**−1,804 字节 / −1.55%**）。
>
> 实现位置：`src/backend/arm/backend_arm.c` → `emit_mov_imm()`，发射期直接写汇编文本，
> 不经过任何 pass
> 门禁：`tests/run_movimm_tests.py`（`make test-movimm`，20 条检查）
> 开关：**没有**。这不是一次优化尝试，是把错的地方改对，所以 `-O0`、`-O2`、任何
> profile 都走同一条路，板端与主机一样受益。

---

## 1. 旧形态错在哪

```asm
    MOVW r0, #20000          ; 低十六位
    MOVT r0, #0              ; 这一条永远写 0，也永远不需要
```

旧代码的注释是这么写的：「MOVW 只设 bits[15:0]，不发 MOVT 的话 bits[31:16]
会残留上一次的旧值，导致错常量（0x40022000 而不是 0x00002000）」。
这句话把因果说反了：按 ARM ARM《MOV (immediate)》T3，`MOVW` 写低十六位、
**bits[31:16] 零填充**，不会残留任何东西。那个 0x40022000 的例子真实来源是
后面又发了一条 `MOVT` 把高半覆盖掉了，不是 `MOVW` 自己留下的垃圾。

于是旧代码在三类常量上都多发了指令：

| 常量 | 旧形态 | 浪费 |
|---|---|---|
| `20000`（16 位内） | `MOVW` + `MOVT #0` | 1 条 |
| `1u << 29` = `0x20000000`（修改立即数） | `MOVW #0` + `MOVT #0x2000` | 1 条 |
| `0x00FFFFFF`（补码可表示） | `MOVW #0xFFFF` + `MOVT #0` | 1 条（且 `MOVW #0xFFFF` 是对的不对的，见 §4） |

以上三类在 HAL 语料里分别出现 192、258、1 次，合计 **451 条**，与§5 的
实测差完全对上。

## 2. 五档选择

`emit_mov_imm(b, rd, imm)` 按值域从上到下试，第一个能完整载入值的就是答案：

| 值域 | 形态 | 宽度 | 标志位 |
|---|---|---|---|
| `0..255` | `MOV rd, #imm`（r0–r7 落成 16 位 `MOVS`，r8–r15 落成 `MOVW`） | 2 / 4 | r0–r7 **置 NZ**；`MOVW` 不置 |
| `≤ 0xFFFF` | `MOVW rd, #imm` | 4 | 不置 |
| ThumbExpandImm 可表示 | `MOV.W rd, #imm` | 4 | 不置（`S=0`） |
| `~v` 是 ThumbExpandImm | `MVN rd, #~v` | 4 | 不置 |
| 其余 | `MOVW` + `MOVT` | 8 | 不置 |

两条口径写死：

1. **`0..255` 仍走 16 位 `MOVS`，因此仍置标志位**。这与旧行为逐位一致，
   所有既有调用方看到的标志状态都没变；想不置标志得另起一条路。
2. **其余四档一律不置标志位**，与它们替换掉的 `MOVW`+`MOVT` 对完全一致。

一键一义：这个函数只负责「把一个 32 位值完整写进 `rd`」，不负责
选寄存器、不负责省下一条（那是 `-fopt-live` 的 L4）、不负责并入算术的立即数域
（那是 `-fopt-imm`）。

## 3. 两遍必须同口径

汇编器是两遍的：pass 1 只累加每条指令的字节数以定下 label 与分支偏移，pass 2
才真正编码。两遍对同一句汇编的宽度必须一致，否则每个 label 之后的地址全错。

选形规则在两边按同一条件写：

```c
pc += (rd1 >= 0 && rd1 <= 7 && u1 <= 255u) ? 2 : 4;   /* pass 1 */
```

```c
if (rd >= 0 && rd <= 7 && u <= 255u)  { /* 16 位 MOVS */ }
else if (u <= 0xFFFFu)                { /* MOVW       */ }
else if (thumb_imm12_a(u, ...))       { /* MOV.W      */ }
else if (thumb_imm12_a(~u, ...))      { /* MVN        */ }
else                                  { /* MOVW+MOVT  */ }
```

`MOV.W` 与 `MVN` 都是 4 字节，宽度由 `logic_dp_a()` 统一给出，而 pass 1 调的是
同一个函数，因此这两档不可能分歧。

顺带修掉一处未定义行为：新路径会把宽值打印成 32 位十六进制（`MOV r0, #0xFF000000`、
`MVN r0, #0x000000FF`），而旧的 `parse_imm_a()` 用有符号 `int` 累加——`#0x80000000`
以上是整型溢出，只靠补码回绕「碰巧」算出正确的位型。换成无符号的
`parse_imm_u32_a()` 之后，取值不再依赖回绕（这条是隐患清理，不是一次实测到的
错误输出；实测见 §5）。

## 4. 汇编器侧的编码

- **`MOV.W rd, #imm`**（修改立即数）：`11110 i 0 0010 0 S 1111 | 0 imm3 Rd imm8`，
  `S = 0`。`S = 0` 是故意的：`MOVS` 的 16 位形式在 IT 块里是
  UNPREDICTABLE，`MOV.W` 带 `S = 0` 在 IT 块里安全。
- **`MVN rd, #imm`**：没有独立的 `MVN (immediate)` 编码，它是
  `ORN (immediate)` 取 `Rn = 1111`（GAS 实测：`mvn r0, #1` 得 `f06f 0001`）。
  汇编文本里打印的是**被取反的那个数**：要装 `0xFFFFFF00` 就写 `MVN r0, #0x000000FF`，
  这样人看汇编与 armasm 看到的是一回事。
- **越界不截断**：`MOV` 的立即数既不是 16 位值也不是修改立即数时报
  hard error（“MOV immediate is out of range (a 16-bit value or a modified
  immediate)”）并退回 `MOVW #0`，而不是静默截断。这是「宁可报错，不给错答案」那条纪律。

## 5. 实测

为了把账算干净，基线不用历史读数，而是**只把 HEAD 的 `backend_arm.c` 单独取出来**
与当前源码其余部分一起编出一个 `arkcc_head.exe`，两个二进制跑同一批 95 个翻译单元、
同一组参数（`-target arm -mcpu Cortex-M4 -O2 --reloc-data`）：

| 臂 | 指令数 | 代码字节 |
|---|---|---|
| HEAD 的 backend | 51,416 | 116,380 |
| 当前 | **50,965** | **114,576** |
| 差 | **−451 / −0.88%** | **−1,804 B / −1.55%** |

形态普查（同一语料、`-O2`）把 451 拆开：

| 形态 | HEAD | 当前 | 省下 |
|---|---|---|---|
| `MOVW` | 1,432 | 1,173 | — |
| `MOVT` | 1,432 | 981 | — |
| 其中成对（`MOVW`+`MOVT`） | 1,432 对 | 981 对 | — |
| 单条 `MOVW`（16 位值） | 0 | 192 | −192 |
| `MOV.W`（修改立即数） | 0 | 258 | −258 |
| `MVN`（补码） | 0 | 1 | −1 |
| 残余 `MOVT rd, #0` | 1,432 | 29 | — |

- 192 + 258 + 1 = **451**，与上表的差逐位对上，命中结束。
- 残余的 29 条 `MOVT rd, #0` **不是**浪费：它们全部紧跟在 `.arkdatasym` 之后，
  是 `--reloc-data` 的重定位对（链接器把地址填进这两条指令），必须保留。
- 不开任何开关的 `-O2` 都受益，因此全开十开关的那一行也一起下移；逐级累加的权威口径在
  `docs/COMPARISON.md` §5（当前终点 21,300 条 / 50,648 字节）。

## 6. 门禁：`tests/run_movimm_tests.py`（20 条）

寒件是七个一行函数（`c_255` / `c_ffff` / `c_imm` / `c_mvn` / `c_pair` / `c_all` / `c_mvn2`），
每个返回一个常量，加一个 `main` 把它们相加：

1. **五个常量类各 3 条**（共 15 条）：函数真的发出来了、目标助记符与立即数
   逐字匹配、**没有**更宽的形态。比如 `c_255` 要求 `MOV r0, #255` 且不得出现
   `MOVW`/`MOVT`/`MVN`；`c_ffff` 要求单条 `MOVW r0, #65535` 且不得出现 `MOVT`。
2. **`c_pair` 的高半是 `MOVT`**：宽值仍然是一对，说明新路径没把它弄坏。
3. **`-O0` 走同一条路**：`-O0` 下 `c_ffff` 也是单条 `MOVW` 且无 `MOVT`。
4. **两条自检**：寒件真的发出了 `MOVW` / `MOVT`。计数**只统计七个寒件函数的函数体**，
   不吃 prologue（函数序幕自己也会发 `MOVW`，全文计数会把它算进来）。
   这一条是故意的：自检要证明的是「寒件确实覆盖了两个助记符」，
   不是「寒件里恰好有几条」——后者会随序幕变化而断。
5. **逐位答案**：把寒件编成镜像交给 unicorn 跑，七个常量相加必须等于 `1`。
   这一条是真正的结论门禁：形态看对不代表值看对。

## 7. 与 `-fopt-imm` 的分界

两件事听起来都像「常量不要多花指令」，但它们修的是不同层：

| | `-fopt-imm`（`docs/IMM_FOLD.md`） | 本文（`emit_mov_imm`） |
|---|---|---|
| 修什么 | `PUSH k` 紧跟算术/比较时，把 `k` 写进指令的立即数域 | 一个常量**怎么进寄存器** |
| 层面 | IR 之后的发射期 pass，需要开关 | 发射器的基本正确性，不过 pass、没有开关 |
| 关掉时 | 行为与开关不存在时逐字节相同 | 不存在「关掉」这个状态 |
| 板端 | 默认开 | 永远生效 |

也正因为它不开关，它对不开任何优化开关的 `-O0`/`-O2` 也生效：板上那一档
只能开得起小小的定制集时，这一部分收益不会丢。
